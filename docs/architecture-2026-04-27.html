Things that surprised me reading this code

The doctrine is real and the boundaries are enforced. These are the load-bearing details that don't show up in any single function.

Doctrine

A. LLM = heart, Open Brain + Karpathy LLM Wiki = brain, tools = hands

RagPlanner (legacy name) does ONE thing — pick the right agent. Its LLM call gets no tools, no tool executor, no memory manager and no grounding nudge, so the planner has only one job: emit plan JSON. Subagents do the actual work in their own subprocess.

bootstrap/orchestrator.rs::RuntimeChatServiceFactory::run_turn_inner (via run_turn_with_system)
Fix B

B. Shared session_id

The caller resolves the id once (resolve_session_id: TENGU_SESSION_ID env override or a fresh UUID; tengu webhooks mints webhook-<name>-<uuid> per request) and build_orchestrator passes it to both RagPlanner and SubprocessRunner, so planner messages and subagent summaries share the same session key.

bootstrap/orchestrator.rs::resolve_session_id · build_orchestrator
Phase 7.2 fix

C. Sandbox config crosses the IPC boundary

Without this, the child loaded ~/.tengu/config.toml not the parent's sandbox config. Symptom: http_request scope-denies in researcher even when the parent's sandbox allowed "*". Fix: AgentIpcInput.sandbox_config field, threaded from Config.sandbox_name → SubprocessRunner → IPC.

Config.sandbox_name (#[serde(skip)]) · load_sandbox_or sets it
Implicit contract

D. compress_and_store is implicit, not declared

Never list compress_and_store in [agents.*].tools — the runner appends it to every subagent automatically. Used to mark "I'm done." Middle-ground protocol: only Failed when no text emitted AND no compress_and_store called. Otherwise OK with a tracing warn. A Claude Code step's bridge writes the summary to TENGU_BRIDGE_SUMMARY_FILE, then the engine ends the CLI run.

adapters/inbound/cli/run_agent.rs::run_agent_subprocess (Phase 5c)
Recall layers

E. Recall layers in the planner prompt

In-memory ring buffer (Phase 6.4 lite) — recent user msgs THIS process, lost on restart. Cross-session block (Phase 6.4 full) — Open Brain agentic_memory recall, opt-in via memory.cross_session_msg_top_k. Both inject before the current turn. A third opt-in lane, within_session_output_top_k, recalls this session's step outputs.

RagPlanner::update_and_format_history + cross_session_recall_block + session_output_recall_block
Multi-turn UX

F. C → B fallback — composed agents, two turns

Turn 1 (C): planner emits Direct asking the user to confirm closest match. Turn 2 (B): on confirmation, planner emits Plan with Step.compose set. Child loads the base agent's [agents.*] block, OVERRIDES skill_packages+tools for this run only. No persistence — config on disk unchanged. In a hardened sandbox ([risk] / Solana signer) compose may only narrow the base.

domain/plan.rs::AgentCompose · bootstrap::tools::compose_agent
Phase 7.3 · local 2026-09-23

G. [agents.*].engine — three backends

Each [agents.<name>] block declares engine = "openrouter", "local" (any OpenAI-compatible server on the host, direct, never via the proxy) or "claude_code" (same field as in-process agents). Model slug format depends on engine: OpenRouter wants anthropic/claude-sonnet-4-6; Claude Code wants bare claude-sonnet-4-6; local sends the server's own id. Mixed-mode (planner = OpenRouter, subagents = Claude Code) is the verified pattern — Claude Code as planner bypasses orchestration because its MCP tool access is set at engine-construction time.

[agents.<name>].engine — engines::build_engine · build_step_engine
Phase 7.4 · parity 2026-09-30

H. Claude Code agents see tengu's tools via MCP

run_agent_subprocess sets EngineContext.bridge_tools = Some(tools) when the agent's engine == "claude_code". Claude Code spawns tengu mcp-bridge, which advertises tengu's tools as mcp__tengu-tools__<name> and runs them as the calling agent (TENGU_CONFIG + TENGU_BRIDGE_AGENT: its scopes, sandbox sections, redaction). The CLI merges the MCP config's env over its own env, so secrets such as OPENROUTER_API_KEY arrive by inheritance — never written into the --mcp-config file; only non-secret values are (TENGU_BRIDGE_*, TENGU_EGRESS, TENGU_SESSION_ID, TENGU_SECRETS_LOADED key names).

engines/claude_code.rs::build_mcp_config_json — inbound/mcp_bridge.rs::build_bridge_executor — outbound/bridge_env.rs
Phase 7.4

I. parse_verdict prose-fallback

Claude Code is conversational by default; even with the SKILL.md instructing JSON-only, the planner LLM sometimes emits prose. parse_verdict tries raw JSON, fenced JSON, JSON inside prose, then wraps any remaining text as Direct { response } with a warn log. No JSON-schema validator runs in Rust; only an empty output ends the turn with System error: orchestrator initial call failed.

J. Adding a tool is a one-row edit — and three parity checks

Phase 7.7

K. WORKSPACE_TOOLS — single constant

Opt-in tools — agentic_memory, shared_cache, persistent_store, skill_distill, apply_improver_proposal, manage_skill, the Solana, Hyperliquid, xmarket, xlab (incl. strategy_ranking) and sources families — are one pub(crate) const WORKSPACE_TOOLS in domain/tools.rs (beside XM_TOOLS, XM_EXEC_TOOLS, SOLANA_WRITE_TOOLS). 2026-09-16

L. Every LLM network path goes through egress.rs

[egress] network = "tor" is the default: proxy socks5h://127.0.0.1:9050 (TENGU_TOR_PROXY overrides — the deploy/tor/ Arti + lyrebird-rs container), route_llm_api on; network = "open" is plain internet (xmarket / xlab add an allow_hosts ceiling). The resolved config is handed to run-agent / mcp-bridge children as TENGU_EGRESS. http_request, crypto, Hyperliquid, GeckoTerminal, SEC EDGAR, EU TED and Solana RPC use the proxied tool client; OpenRouter, embeddings and Jev the LLM client; the Claude Code CLI gets HTTPS_PROXY (HTTP CONNECT on the SOCKS port); Telegram a proxied reqwest 0.11 client. Feed and loop calls carry their own agent / session / call id on the JSONL audit (AttributedExecutor).

egress::install · resolved · tool_client · llm_api_client · check_url · shell_command · guard_shell · claude_cli_env · AttributedExecutor · docs/egress-2026-09-16.md
2026-09-30

M. Money paths fail closed inside the tool

The [risk] gate is not a planner or loop step: it runs inside every exec tool, so a feed, a Jev loop, a bridged Claude Code call and tengu tool call hit the same check. Gate + fill + ledger write = one BEGIN IMMEDIATE; idempotent per client_order_id (the arg, else the call id — never random); a replay asking for another order is refused (client_order_id_conflict); only a private agent may hold an exec tool; an entry re-probes the kill-switch file inside the transaction.

tools/xm/exec_common.rs::run_exec · PaperLedger::place · domain/xm/risk.rs::evaluate
2026-10-01

N. Time is a port; history is read as-of

Clock: SystemClock live (feed schedules, paper fill latency), SimClock in replay — the backtest gate runs the real DecisionLoop with its clock set to each candidate's decided_at, and the decision cache makes reruns identical. The engine reads series only as-of t: a bar is observable at its close; every trade records data_asof_ms ≤ decided_at_ms; checks.rs perturbs everything after t and asserts nothing at or before t changes.

2026-10-01

O. One owner per state dir

tengu run and tengu webhooks take the same leases (runtime:<sandbox>, state:<dir>) in <state dir>/runtime.db; a second process exits 1. Behind them, each ledger account records the sandbox that first wrote it — another sandbox's tools are refused account_owner_mismatch.

bootstrap/runtime.rs::LeasePlan · OwnerLeases · outbound/paper_store.rs
2026-10-06 · 2026-10-08

P. Sealed before seen, frozen once judged

A preregistered variant, experiment or ranking contract is sealed (tengu lineage seal: its digest appended to lineage/locks.toml) before any outcome; seal_mismatch fires if it changes after, and the ranking publisher refuses an unsealed or changed contract. A FROZEN generation (W1) is checked at every Config::load of a bound sandbox: a tool or kind outside it, or an edited pinned section (pin_drift), fails the load — W2 work goes in new, unbound sandboxes (xlab-w2). Evidence is copied once into a read-only vault pinned by sha256; readers open SQLite immutable=1.

2026-10-08

Q. Agents never fetch sources

source_evidence only reads sources.db; fetching is the operator's (tengu sources fetch), gated per row — enabled, reviewed terms_sha256, the runtime kill switch — before any request. Source text reaches a model fenced as untrusted data.

2026-10-09

R. Models write data; the domain decides (SOE)

The SOE stage agents never return a draft as text: soe_propose / soe_challenge write records through application::soe::submit (phase, limits, every check), and domain::soe::allocate::decide_week computes every figure, gate, rank and action. Frozen run dirs make a week reproducible from its inputs.

S. The browser draws; Rust decides (Studio)

Studio's page owns no workflow, risk, scope or colour rule: the graph (layout included), each status's tone, a run's board at a seq and every control verdict come from Rust over the trace each run writes once. Play / Stop never reach a [generation]-bound or hardened sandbox.
