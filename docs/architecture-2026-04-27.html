Six things that surprised me reading this code

The doctrine is real and the boundaries are enforced. These are the load-bearing details that don't show up in any single function.

Doctrine

A. LLM = heart, Open Brain + Karpathy LLM Wiki = brain, tools = hands

RagPlanner (legacy name) does ONE thing — pick the right agent. Its LLM call strips tools, tool_executor, memory_manager, and grounding so the planner has only one job: emit plan JSON. Subagents do the actual work in their own subprocess.

bootstrap::orchestrator::run_turn_with_system
Fix B

B. Shared session_id

bootstrap::orchestrator::build_orchestrator resolves the id once (TENGU_SESSION_ID env override or fresh UUID) and passes it to both RagPlanner and SubprocessRunner, so planner messages and subagent summaries share the same session key.

bootstrap/orchestrator.rs::build_orchestrator
Phase 7.2 fix

C. Sandbox config crosses the IPC boundary

Without this, the child loaded ~/.tengu/config.toml not the parent's sandbox config. Symptom: http_request scope-denies in researcher even when the parent's sandbox allowed "*". Fix: AgentIpcInput.sandbox_config field, threaded from Config.sandbox_name → SubprocessRunner → IPC.

Config.sandbox_name (#[serde(skip)]) · load_sandbox_or sets it
Implicit contract

D. compress_and_store is implicit, not declared

Never list compress_and_store in [agents.*].tools — the runner appends it to every subagent automatically. Used to mark "I'm done." Middle-ground protocol: only Failed when no text emitted AND no compress_and_store called. Otherwise OK with a tracing warn.

adapters/inbound/cli/run_agent.rs::run_agent_subprocess (Phase 5c)
Two layers

E. Two layers of recall in the planner prompt

In-memory ring buffer (Phase 6.4 lite) — recent user msgs THIS process, lost on restart. Cross-session block (Phase 6.4 full) — Open Brain agentic_memory recall, opt-in via memory.cross_session_msg_top_k. Both inject before the current turn.

RagPlanner::update_and_format_history + cross_session_recall_block
Multi-turn UX

F. C → B fallback — composed agents, two turns

Turn 1 (C): planner emits Direct asking the user to confirm closest match. Turn 2 (B): on confirmation, planner emits Plan with Step.compose set. Child loads the base agent's [agents.*] block, OVERRIDES skill_packages+tools for this run only. No persistence — config on disk unchanged.

orchestrator/plan.rs::AgentCompose (Phase 6.7)
Phase 7.3

G. [agents.*].engine — subagents pick their backend

Each [agents.<name>] block declares engine = "openrouter" or engine = "claude_code" (same field as in-process agents). Subprocess honours it via build_engine. Model slug format depends on engine: OpenRouter wants anthropic/claude-sonnet-4-6; Claude Code wants bare claude-sonnet-4-6. Mixed-mode (planner = OpenRouter, subagents = Claude Code) is the verified pattern — Claude Code as planner bypasses orchestration because its MCP tool access is set at engine-construction time.

[agents.<name>].engine — bootstrap::tools::subagent_config — build_engine
Phase 7.4

H. Claude Code subagents see tengu's tools via MCP

adapters/inbound/cli/run_agent.rs::run_agent_subprocess sets EngineContext.bridge_tools = Some(tools) when the agent's engine == "claude_code". Claude Code spawns tengu mcp-bridge as an MCP server, which advertises tengu's tools as mcp__tengu-tools__<name>. Claude Code calls those, the bridge dispatches to its own ToolRegistry, response flows back. Two key env vars forwarded to the bridge: TENGU_SESSION_ID and OPENROUTER_API_KEY (without them the bridge silently fails to register memory tools).

EngineContext.bridge_tools — adapters/outbound/engines/claude_code.rs::build_mcp_config_json — mcp_bridge.rs::build_bridge_executor
Phase 7.4

I. parse_verdict prose-fallback

Claude Code is conversational by default; even with the SKILL.md instructing JSON-only, the planner LLM sometimes emits prose. Pre-7.4 this produced System error: orchestrator initial call failed. Now parse_verdict wraps any unparseable text as Direct { response } with a warn log. User sees the model's reply; logs show when it's firing so you can tune.

orchestrator/planner.rs::parse_verdict — Path 4 fallback
2026-09-23

J. Adding a tool is a one-row edit

catalog() in adapters/outbound/tools/mod.rs lists every built-in tool group as a ToolEntry; register_catalog (in-process executor AND MCP bridge) and advertised_defs (the tool list the model sees) both read it. Opt-in names also go in domain/tools.rs::WORKSPACE_TOOLS; catalog_tests enforce the sync. Recipe: docs/tools.md, docs/code-map.md.

adapters/outbound/tools/mod.rs — catalog · register_catalog · advertised_defs
Phase 7.7

K. WORKSPACE_TOOLS — single constant

Opt-in workspace tools such as agentic_memory, shared_cache, persistent_store, skill_distill, apply_improver_proposal, and manage_skill use one pub(crate) const WORKSPACE_TOOLS in bootstrap/. Adding another opt-in is a one-line allowlist edit plus plugin registration. bootstrap::tools::subagent_config merges the names in tools that match it into workspace_tools; the bridge filters allowed_names against it.

domain::tools::WORKSPACE_TOOLS
2026-09-16

L. Every LLM network path goes through egress.rs

[egress] network = "tor" is the default: proxy socks5h://127.0.0.1:9050 (TENGU_TOR_PROXY overrides — the deploy/tor/ Arti + lyrebird-rs container), route_llm_api on; network = "open" is plain internet. EgressConfig::resolved() fills those defaults, the policy is installed process-wide, and the resolved config is handed to run-agent / mcp-bridge children as TENGU_EGRESS. http_request, crypto and MCP-http use the proxied tool client; the Claude Code CLI gets HTTPS_PROXY (HTTP CONNECT on the SOCKS port, claude_cli_env); Telegram gets a proxied reqwest 0.11 client (TelegramPipe::build_bot); http_request follows redirects itself and re-checks allow_hosts/deny_hosts/https_only + net_hosts on every hop. run_command runs under sandbox-exec when shell_network = "isolated". Every hop / network-looking shell command lands in the JSONL audit log. build_tool_executor no longer accepts an HTTP client, so nothing can inject an unproxied one.
