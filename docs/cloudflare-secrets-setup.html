1What you end with

Your Mac · tenguNo provider keys. Only a session token, in memory, signed by your Secretive key (Touch ID).
request + session
Worker · tengu-sealKeys are Cloudflare secrets. Adds the route's key, calls the provider, masks the key out of the reply.
request + key
ProviderOpenRouter · Telegram · Alchemy · Helius · Privy
  • No agent ever gets a key: there is none on the Mac.
  • Each route says exactly where its key goes: one header, the start of the path, or one query parameter. A request that puts TENGU_SECRET anywhere else is refused (403), so a session can use a key but never copy it out (into a webhook URL, a message text).
  • Only SSH keys listed in CLIENTS get a session, and only for routes named in that key's routes (empty = none). tengu asks for the routes its [keys.env] uses; the session gets those that CLIENTS also allows.
  • Replies come back with the key replaced by [REDACTED]: in every header, and in text / JSON / XML bodies up to 2 MiB (masked as bytes). A bigger text body streams on unmasked past 2 MiB; event streams and binary bodies pass through. Their headers are still masked.
  • Still open: a session holder can use a route's key (for example call any Telegram Bot API method as the bot), never read it. Sessions are not refreshed while tengu runs: restart a long run before session_hours ends.
  • The Privy wallet works the same way: its app secret is a Cloudflare secret behind route privy. Give that route only to tengu-attended (Touch ID), so an unattended run can't sign. Not moved: the Solana signer key file ([solana] signer_key_file).

3Deploy the Worker

cd <repo>/cloudflare/seal-worker
npx wrangler login
npx wrangler deploy
  • <repo> = the tengu checkout that has cloudflare/seal-worker (branch feature/sealed-keys until it merges).
  • login opens the browser. Allow access.
  • The first deploy installs worker-build and compiles Rust to wasm. It is slow once.
  • If wrangler asks for a workers.dev subdomain, pick one. That is your <your-subdomain>.
  • It prints your Worker URL: https://tengu-seal.<your-subdomain>.workers.dev.

Check it is up (no key needed):

curl -s https://tengu-seal.<your-subdomain>.workers.dev/healthz
{"ok":true,"routes":["evm-rpc","openrouter","privy","solana-rpc","telegram"]}

4Session key

openssl rand -hex 32 | npx wrangler secret put SESSION_KEY
  • 64 random characters go straight into Cloudflare. Never shown, never stored on the Mac. (The Worker needs at least 32.)
  • It signs every session. Changing it ends all sessions (§ 10).

1. In cloudflare/seal-worker/wrangler.toml, CLIENTS (then `npx wrangler deploy`):

  "SHA256:<fingerprint-1>": { "label": "<key name>", "session_hours": 24, "routes": ["openrouter"] },
  "SHA256:<fingerprint-2>": { "label": "<key name>", "session_hours": 24, "routes": ["openrouter"] }

2. In your config (base or sandbox):

[keys]
...

Paste those lines into CLIENTS in cloudflare/seal-worker/wrangler.toml. It is a JSON object: a comma between entries, none after the last. Copy each fingerprint in full, exactly as printed. Give each key only the routes it needs:

CLIENTS = '''
{
  "SHA256:<fingerprint-of-tengu-attended>": { "label": "tengu-attended", "session_hours": 24, "routes": ["openrouter", "telegram", "evm-rpc", "privy"] },
  "SHA256:<fingerprint-of-tengu-unattended>": { "label": "tengu-unattended", "session_hours": 168, "routes": ["openrouter"] }
}
'''
FieldRule
labelAny name. Shows in tengu keys status and in the Worker logs.
session_hours1–168, default 24. tengu does not refresh a session while it runs: restart before it ends (a tengu run too).
routesRoute names this key may use, or ["*"] = all. Empty or missing = none: the key gets no session. Each name must be in ROUTES, else /session and every call answer 500.

Fingerprints are public, so this file can go in git. Then:

npx wrangler deploy

6Add the keys

Make fresh keys. The old ones sat in a world-readable .env, and some were in public git history. At each provider, create a new key and paste it straight into Cloudflare. Revoke the old key once § 8 passes.

How to add one secret

a. Dashboard (recommended)

  1. dash.cloudflare.com → Workers & Pages → tengu-seal
  2. Settings → Variables and Secrets → Add
  3. Type: Secret (not Text)
  4. Name: e.g. OPENROUTER_API_KEY
  5. Paste the value from the provider's page → Deploy

The value goes from the provider straight to Cloudflare. It never touches a file on the Mac.

b. Terminal

In cloudflare/seal-worker. It asks for the value with a hidden prompt; paste, Enter. Live at once, no deploy.

npx wrangler secret put OPENROUTER_API_KEY
npx wrangler secret put TELEGRAM_BOT_TOKEN
npx wrangler secret put ALCHEMY_API_KEY

Secrets survive npx wrangler deploy. Plain variables do not: keep ROUTES and CLIENTS in wrangler.toml only, never in the dashboard.

Privy: one secret from two values

Privy expects Authorization: Basic base64(<app id>:<app secret>), so the Worker stores that one string. In cloudflare/seal-worker:

read -rs S    # paste the Privy app secret, Enter (nothing shows)
printf '%s:%s' '<your PRIVY_APP_ID>' "$S" | base64 | npx wrangler secret put PRIVY_BASIC_AUTH
unset S

The secret stays in shell memory only; nothing goes to a file or your shell history. A trailing newline is fine: the Worker trims every secret. To limit what the wallet may sign, use Privy's own wallet policies in the Privy dashboard.

Cloudflare secrets after this step: SESSION_KEY, OPENROUTER_API_KEY, TELEGRAM_BOT_TOKEN, ALCHEMY_API_KEY, PRIVY_BASIC_AUTH. Optional: ANTHROPIC_API_KEY, HF_TOKEN. The solana-rpc route needs HELIUS_API_KEY; your .env has none, so skip it until you use Helius (until then that route answers 500).

Optional routes (Anthropic, Hugging Face)

Add inside the ROUTES JSON in wrangler.toml (comma after the entry before), add the secret and the route name to the CLIENTS key that needs it, then npx wrangler deploy. Recipe: § 10.

"anthropic": { "upstream": "https://api.anthropic.com", "secret": "ANTHROPIC_API_KEY", "header": "x-api-key: {secret}" },
"huggingface": { "upstream": "https://huggingface.co", "secret": "HF_TOKEN", "header": "Authorization: Bearer {secret}" }

7Point tengu at the Worker

Put this block in the config tengu loads:

  • ~/.tengu/config.toml (the base config) for commands without --sandbox.
  • sandboxes/<name>/config.toml for --sandbox <name>. A sandbox file replaces the base config entirely, so every sandbox you run needs its own [keys] block.
[keys]
proxy = "https://tengu-seal.<your-subdomain>.workers.dev"
client = "tengu-attended"
agent_socket = "~/Library/Containers/com.maxgoedjen.Secretive.SecretAgent/Data/socket.ssh"
strip = ["TELEGRAM_BOT_TOKEN", "ALCHEMY_API_KEY", "HELIUS_API_KEY", "PRIVY_APP_SECRET"]

[keys.env]
OPENROUTER_BASE_URL = "openrouter"
OPENROUTER_API_KEY = "@session"
TELEGRAM_API_URL = "telegram"
EVM_RPC_URL = "evm-rpc/TENGU_SECRET"
PRIVY_API_URL = "privy"
# Only once a HELIUS_API_KEY secret exists:
# SOLANA_RPC_URL = "solana-rpc/?api-key=TENGU_SECRET"
FieldMeaning
proxyThe Worker origin: https, no path, no user or password. tengu uses it in canonical form (lowercase host, no default port, no trailing slash); the session signature covers it. (http://127.0.0.1:<port> / localhost works only for wrangler dev.)
clientWhich agent key signs: its name as tengu keys setup prints it, or its full SHA256: fingerprint. In a tengu run sandbox, use tengu-unattended. Not set = the agent's only key.
agent_socketOptional. Not set = $SSH_AUTH_SOCK.
stripEnv vars removed at load: local copies of keys that now live in the Worker. Removed whether the session works or not, and again in every run-agent / mcp-bridge child (they re-read .env). A name [keys.env] sets is refused (it is overwritten anyway).
[keys.env]VAR = "<route>[/path][?query]" exports <proxy>/<value>. "@session" exports the session token: only for OPENROUTER_API_KEY, and only with OPENROUTER_BASE_URL = "<route>" next to it (else the token would go to the provider). Both override any value from the shell or .env. The session asks for exactly the routes these values name.
  • If tengu cannot get a session at startup, it unsets every [keys.env] var and logs a warning. A leftover local key can never get around the Worker. Commands that need no key still run.
  • tengu telegram with TELEGRAM_API_URL in [keys.env] and no session refuses to start. It never falls back to a local bot token.
  • The Privy tools with PRIVY_API_URL in [keys.env] and no session fail with Missing environment variable PRIVY_APP_SECRET: strip must list it, so they never fall back to a local secret. An agent with its own scope for a Privy tool also needs PRIVY_API_URL in env_reads and the Worker host in net_hosts.
  • If the Worker grants fewer routes than [keys.env] uses, tengu warns with the missing ones. Add them to that key's CLIENTS routes.
  • A sandbox with [egress] allow_hosts must list the Worker host, e.g. "*.workers.dev". Otherwise the config does not load: keys.proxy host '…' is not in [egress] allow_hosts.
  • Sandboxes on Tor (the default) reach the Worker through Tor, like LLM calls. Not tested live yet; see § 11.
Older tengu builds refuse [keys]. A build without this branch (for example the frozen weekend #2 binary) stops on an unknown [keys] section in ~/.tengu/config.toml for every command run without --sandbox. Add [keys] to the base config only after the weekend #2 stop (Mon 2026-10-12), with every tengu built from this code. Until then, use a sandbox file.

9Clean the Mac

tengu reads .env from the folder you start it in (or a parent). See the names only, never the values:

cut -d= -f1 .env
DoLines in .env
Delete (17)OPENROUTER_API_KEY, TELEGRAM_BOT_TOKEN, EVM_RPC_URL, ALCHEMY_API_KEY, PRIVY_APP_SECRET, ANTHROPIC_API_KEY, HF_TOKEN, POI_API_KEY, QDRANT_API_KEY, QDRANT_CLUSTER_ENDPOINT, MOLECULE_API_KEY, MOLECULE_CLIENT_URL, MOLECULE_LABS_URL, X402_GATEWAY_URL, IPNFT_CONTRACT_ADDRESS, BEACH_API_KEY, BEACH_SCIENCE_API_KEY
Keep (7)PRIVY_APP_ID, PRIVY_WALLET_ID, SEC_USER_AGENT, EVM_WALLET_ADDRESS, PRIVY_WALLET_ADDRESS, RUST_LOG, TENGU_HOME

Until a moved key is gone everywhere, [keys] strip (§ 7) keeps it out of every tengu process. The redaction registry is extended after the session starts, never rebuilt, so old .env / vault values stay masked too. Make what is left readable by you only:

chmod 600 .env

The tengu vault may hold copies. List names, then remove each moved one:

tengu secret list
tengu secret remove OPENROUTER_API_KEY

Shell profile and the current shell, names only:

rg -o -N 'export [A-Z0-9_]*(KEY|TOKEN|SECRET|RPC_URL)' ~/.zshrc ~/.zprofile ~/.bash_profile
env | cut -d= -f1 | rg 'KEY|TOKEN|SECRET|RPC_URL'

Delete those lines in an editor, then open a new terminal. Last: revoke the old keys at OpenRouter, Alchemy, Privy (old app secret), Anthropic, Hugging Face and Beach.science. (Telegram: BotFather /revoke already killed the old token.)

route name1–32 chars of a-z 0-9 - _; not healthz, session, whoami.
