What tengu does NOT have

For comparison with Claude Code / Cursor / similar harnesses.

Missing context-management features

  • No LLM-driven auto-compact pass. The model never sees a summary of its own history. Old turns just drop off via the sliding window.
  • No /compact slash-command equivalent in the TUI. The user cannot manually trigger a compaction pass.
  • No semantic dedupe of repeated tool calls. If the model calls http_request with the same URL twice in one turn, both full responses sit in context.
  • No retrieval over prior turns of the current session for the chat loop. Postgres agentic_memory user messages exist but RagPlanner::cross_session_recall_block is the only consumer (planner-side, opt-in cross_session_msg_top_k).
  • Subagent step traces are NEVER fed back into the planner's history. Only the compress_and_store summary survives, and only RagPlanner::replan (cross-plan) / plan (within-session, opt-in within_session_output_top_k) read it — not the per-turn chat history.
  • Claude Code engine has no in-loop compaction at all. That's why max_mcp_result_chars exists as a hard cap on bridge-routed tool results — it's the only context governor on that path.

Compare: durable per-step summarisation

compress_and_store looks similar but is on a different axis. It writes a one-shot LLM-produced summary of a finished subagent step to Postgres agentic_memory (postgres_memory) for cross-plan recall — it never trims any LLM's input. See compression-flow-2026-04-27.svg.
