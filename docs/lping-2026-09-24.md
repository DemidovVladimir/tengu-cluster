## Target flow

```
Helius webhook / gRPC stream ──► ingest (Rust, no LLM): filter by program + pool
        ──► gate (Jev decision, ~$0.00003, <600 ms): "act on this event?"
        ──► tengu webhook → planner → crypto_researcher / lp agents
```

An LLM turn per on-chain event is unaffordable; filter + gate first.

## `~typesafe/jev-latest`

| Field | Value |
|---|---|
| Resolves to | `typesafe/jev-1.13` (alias, created 2026-09-18) |
| Type | `text->decisions` — returns typed answers (`noul` 0..1, `choice`, `score`), **no text, no tool calls** |
| `supported_parameters` | `[]` — no `tools` / `tool_choice` / `response_format` |
| Price | $0.042/M prompt, completion $0 |
| Context | 32k |
| Use as | **Action selector** for the continuous loop (`choice` over a fixed action set: `hold` / `rebalance` / `widen` / `close` / `hedge_up` / `hedge_down`, like its Mario/Doom game agents) + gate (`noul`). Rust code computes the arguments from state. Not a chat/planner model: it does not write arguments or text |
| Verified 2026-09-24 | `POST https://openrouter.ai/api/alpha/decisions`, ~0.3 s, ~$0.00002/call |

Schema (probed live):

| Type | Request | Response |
|---|---|---|
| `choice` | `{"type":"choice","instructions":"...","criteria":{"<label>":"<description>",...}}` — labels are per-call (tool names work) | `choice`, `probabilities{label:p}`, `confidence` |
| `score` | `{"type":"score","instructions":"...","criteria":[{"score":0,"description":"..."},{"score":1,"description":"..."}]}` | `score`, `legend`, `probabilities`, `confidence` |
| `noul` | `{"type":"noul","instructions":"..."}` | `noul` (0..1) |

Probe results: LP state (price below range) → `rebalance` p=0.83; tool pick for a Meteora-pools question → `http_request` p=1.0. Score with 2 anchors looked miscalibrated (urgency 0.93 on a non-urgent ask) — use more anchors, check before trusting.

## Jev state + argument slots (design, probed 2026-09-24)

| Part | Shape |
|---|---|
| `state.goal` | Current objective + hard caps (max size, allowed pools) |
| `state.world` | `world` aliases → observation-store rows (`decision_value`: status, age, slot, source, features); stale / missing / failed rows carry no numbers |
| `state.history` | Ring buffer, last N≈8 actions: `{t, action, args, ok, result}`; `result` normalised by a per-tool reducer (never raw JSON) |
| Questions | `next_tool` (choice over allow-listed tools) + one `choice` per **argument slot**, all in ONE request |
| Slot candidates | Built by code from state: ids from history results (`pool_1..n` → full address in code), preset sizes, preset ranges |
| Execution | Code maps labels → real args, re-checks caps, acts, appends to history; below confidence threshold → escalate to `crypto_researcher` |
| Storage | In-process ring buffer per loop; audit in `<TENGU_HOME>/logs/decisions.jsonl` |
| Budget | 32k context; probe used 837 input tokens for 2 history entries, $0.000035 |

Probe: history = [pool list, wallet balance], goal cap 2 SOL → `open_position` (p=0.76), `pool_2` (highest fees/TVL, p=0.93), size `2` (p=0.97). Did not repeat completed steps.
