# `tengu run` — runtime operator doc (2026-09-30)

The long-running process of a sandbox (xmarket M0 `rt-daemon`, `rt-health`, `rt-scheduler`). Code: `src/adapters/inbound/run.rs` → `src/bootstrap/runtime.rs` → `src/application/runtime/`; pure data + the live verdict in `src/domain/runtime.rs`, fire times in `src/domain/schedule.rs`. Tracker: `docs/xmarket-tracker-2026-09-29.md` (`rt-*` items); `rt-docs` (W2) extends this page with the bus and latency.

## Run

| Command | Effect |
|---|---|
| `tengu run --sandbox <s>` | one process: every `[decision_loops.*]` built once + every `[feeds.*]` (§ Feeds) + the webhook routes; logs to `<TENGU_HOME>/logs/tengu.log` + stderr |
| `--sandbox` omitted | config from `--config` / `$TENGU_CONFIG`; runner name `default` |
| SIGINT / SIGTERM | graceful shutdown (below), exit 0 |
| second signal while draining | exit at once, code 130 (the lease frees itself after ≤ 30 s) |
| a second `tengu run` of the same sandbox | exits 1: ``sandbox `<s>` is already running: lease `runtime:<s>` in <state dir>/runtime.db is held by `<host>:<pid>:<uuid>` for <n> s more. Stop that `tengu run` first (SIGTERM drains it); if it crashed, retry once the lease expires.`` |

## `[runtime]` (`src/config/runtime.rs`, `deny_unknown_fields`, all optional)

| Key | Default | Effect |
|---|---|---|
| `shutdown_grace_secs` | 20 | after the stop signal, running loop events and tasks get this long (≤ 3600), then are aborted |
| `max_decisions_in_flight` | 4 | loop events running at once across all loops; a loop always runs one event at a time, in arrival order (also applies to `tengu webhooks`) |
| `heartbeat_secs` | 5 | period of the heartbeat file and the health rows (1–3600) |
| `heartbeat_stale_secs` | 30 | `tengu doctor --live` fails when the heartbeat is older (must exceed `heartbeat_secs`) |

## Single-runner lease

| Piece | Value |
|---|---|
| Store | `<state dir>/runtime.db`, table `leases` (WAL, one statement per change — same pattern as `solana-writes.db`) |
| State dir | `<TENGU_HOME>/state/<[xmarket] state>` when the sandbox has `[xmarket]`, else `<TENGU_HOME>/state` |
| Resource / holder | `runtime:<sandbox>` / `<host>:<pid>:<uuid>` |
| TTL / renewal | 30 s / every 10 s; a runner that crashed is replaced once its lease expires |
| Lost lease (another holder took it, or renewals failed until expiry) | the runner stops as failed (exit non-zero) |

## Shutdown

| Step | What happens |
|---|---|
| 1 | stop signal (`tokio::sync::watch`) reaches every task |
| 2 | webhook server stops accepting (`with_graceful_shutdown`); loop endpoints answer 503 from now on |
| 3 | heartbeat `stopping`; queued loop events are dropped (logged with their session id); running ones get `shutdown_grace_secs`, then are aborted |
| 4 | heartbeat `stopped` (+ reason); lease released; log lines `loop totals` per loop and `tengu run stopped` with finished / dropped / aborted counts |

A task that ends before the stop signal (webhook server crash, a panic) stops the runtime as failed — Docker's restart policy brings it back.

## Webhooks under `tengu run`

| Build / config | Result |
|---|---|
| `--features webhooks` + `[webhooks] enabled = true` | `/webhooks/:name` served in this process (`docs/webhooks-2026-05-11.md`); loop endpoints queue on the runtime's loops |
| feature on, `enabled = false` | log `webhooks off` |
| built without the feature | log `webhooks off`; a warning when `[webhooks] enabled = true` |

Do not run `tengu webhooks` for a sandbox that `tengu run` serves: two processes would each own a copy of every loop.

## Health (`src/application/runtime/health.rs`)

| Output | Where | Content |
|---|---|---|
| `run-<sandbox>.json` | state dir; every `heartbeat_secs` (first at start), `stopping` / `stopped` on shutdown; temp file + rename | `sandbox`, `pid`, `holder`, `state` running \| stopping \| stopped, `stop_reason`, `started_at_ms`, `ts_ms`, `heartbeat_secs`, `loops` (= `loop/1` data), `feeds` (= `feed/1` data) |
| `loop/1:<name>` | the loop agent's `observations.db`, every beat | `queue_depth`, `in_flight`, `accepted`, `completed`, `failed`, `dropped`, `last_decision_age_s` (last finished event), `last_error` |
| `feed/1:<name>` | the store the feed registered with (`HealthBoard::feed` → `FeedWriter`: `item` / `error` / `reconnecting` / `dropped`; written by the scheduler, § Feeds) | `state` connecting \| live \| backoff \| stalled \| down, `required`, `stale_after_s`, `last_item_age_s`, `items`, `reconnects`, `dropped`, `last_error_class`, `last_error`. Row `observed_at_ms` = last item ⇒ `requires = { feed = 10 }` = "delivered within 10 s"; no row before the first item |

Errors in rows and heartbeats never carry URLs (`<url>`).

## `tengu doctor --sandbox <s> --live` (Docker healthcheck)

Runs the normal doctor, then reads the heartbeat + the `loop/1` / `feed/1` rows (every agent workspace whose `observations.db` exists; per name the newest wins) → `domain::runtime::live_verdict`. Exit non-zero when:

| Check | Fails when |
|---|---|
| heartbeat | `run-<s>.json` missing or unreadable, older than `heartbeat_stale_secs`, or `stopping` / `stopped` |
| required feed | `down`; no item for `stale_after_s` (since start while none); entry not updated for `max(stale_after_s, heartbeat_stale_secs)` |
| health row | a `loop/1` / `feed/1` row does not decode |
| loops, optional feeds | never — reported only |

```
  Runtime (live): sandbox xmarket · /opt/tengu/data/state/xmarket
    ok   heartbeat                running · up 3 h 0 min · last beat 2 s ago (limit 30 s) · pid 4242 · holder vps-1:4242:0f8c6a52-5d0e-4c8e-9a71-3b2f1c9d7e44
    ok   loop xm_main             in_flight 0 · queue 0 · done 11 · failed 1 · dropped 0 · last decision 14 s ago · last error: jev 503
    FAIL feed hl_ctx (required)   down: down · items 1 · last item 1 s ago (stale after 60 s) · reconnects 0 · dropped 0 · last error auth_required: blocked (geo/WAF/Tor exit?)
    => NOT live
```

## Feeds (`[feeds.<n>]`)

One supervised task `feed:<name>` per block, started after the loops (`bootstrap/runtime.rs::start_feeds` → `application/runtime/feeds.rs`, fire times `src/domain/schedule.rs`); keys and validation in `src/config/feeds.rs`, examples in `config.example.toml` (`hl_ctx`, `hl_book` with windows, daily `risk_status`, the `xm_exits` exit check every 15 s, an at-tick loop event). A feed that fails to build — a tool its agent cannot run, a tick target not running — stops `tengu run` at start; the `tengu run started` log line lists the feeds.

| Key / rule | Value |
|---|---|
| `kind = "tool"` | `agent` runs `tool` (listed in its `tools`, or opted in via `workspace_tools`) through the executor its decision loop would get (scopes, workspace, secret redaction); `args` + fan-out `each = { coin = ["xyz:TSLA", "xyz:NVDA"] }` (every combination, key order, ≤ 500 calls; `concurrency` 1–32, default 1). No LLM, no Jev: deterministic clock work (exit checks, the weekend fade, the daily risk roll) is a tool feed |
| `kind = "tick"` | `event` + `ts_ms` (the slot) to `[decision_loops.<target>]` (a Jev loop), session id `<name>:<slot ms>` |
| other kinds | `"poll"` = `info-fetch` (W2), `"stream"` / `"ws"` / `"rows"` later — refused at load until built |
| `every_secs` | base interval, 1 s – 7 d, on the UTC epoch grid (60 ⇒ :00 of every minute) |
| `windows` | `{ days = ["Sun"], from = "17:00", to = "19:00", every_secs = 60 }` in `tz`; replaces `every_secs` inside; `to <= from` ends the next day, `"24:00"` = midnight; no `days` = every day |
| `at` | clock ticks in `tz`: `"<Mon…Sun> HH:MM"` or `"daily HH:MM"` (e.g. `"Sun 18:00"`, `"daily 00:01"`); exact (no jitter); calendar-agnostic — a holiday-aware tool checks its calendar itself. Put clock ticks in a feed of their own: a tick that passes while the feed's previous run is still going is skipped |
| `tz` | `America/New_York` · `Europe/Paris` · `UTC` (default). DST: a gap time reads with the standard offset, an overlap time is the first instant — an at-tick fires once per named day; windows keep wall-clock bounds |
| `jitter_pct` | 0–50: a grid fire starts up to this % of its interval late (spreads the request budget) |
| `run_on_start` | one run at start (slot = the start time) |
| call ids | `feed:<name>:<slot ms>:<i>` → `ToolCtx.call_id`; a retry reuses it (exec tools deduplicate) |
| one in flight | a run finishes before the next fire is computed; a tick is skipped (`dropped`) while the feed's previous event is still queued or running |
| missed slots | never replayed: the next fire is computed when a run ends; a slot reached later than max(60 s, its interval) after its time (at-ticks: 60 s — a system sleep) is skipped (`dropped`) |
| failures | observation `status = error` (class of its most retry-worthy error), `HTTP <non-2xx>` text, executor error (`fatal`) ⇒ `domain::backoff` FEED: transient / timeout / rate limit ⇒ the failed calls again after 1–60 s (≥ `Retry-After`), a slot due first runs every call; quota / long rate limit ⇒ park (no slot until then); auth / fatal / decode / not_applicable ⇒ the next slot. Messages in logs and rows: no URLs, ≤ 200 chars cut at whole words |
| health | `feed/1:<name>` in the feed agent's store (tick: the loop agent's): `connecting` → `live` (per ok call / sent tick) · `backoff` · `down`; `required` (default false) + `stale_after_secs` (default 3 × the longest interval, ≥ 60 s; without `every_secs` — idle between windows / at-ticks — 8 d) drive `tengu doctor --live` |
| stop | checked before every nap (≤ 60 s) and every call; a call in progress finishes within `shutdown_grace_secs` |
