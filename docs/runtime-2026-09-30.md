# `tengu run` — runtime operator doc (2026-09-30)

The long-running process of a sandbox (xmarket M0 `rt-daemon`, `rt-health`, `rt-scheduler`). Code: `src/adapters/inbound/run.rs` → `src/bootstrap/runtime.rs` → `src/application/runtime/`; pure data + the live verdict in `src/domain/runtime.rs`, fire times in `src/domain/schedule.rs`. Tracker: `docs/xmarket-tracker-2026-09-29.md` (`rt-*` items); `rt-docs` (W2) extends this page with the bus and latency.

## Run

| Command | Effect |
|---|---|
| `tengu run --sandbox <s>` | one process: every `[decision_loops.*]` built once + every `[feeds.*]` (§ Feeds) + the webhook routes; logs to `<TENGU_HOME>/logs/tengu.log` + stderr |
| `--sandbox` omitted | config from `--config` / `$TENGU_CONFIG`; runner name `default` |
| SIGINT / SIGTERM | graceful shutdown (below), exit 0 |
| second signal while draining | exit at once, code 130 (the lease frees itself after ≤ 30 s) |
| Play in `tengu studio --sandbox <s>` (default build, control on) | the same start (`inbound::run::start_session`) inside the Studio process: same leases, loops, feeds, heartbeat, recording, webhook routes (a build with `webhooks` too); Studio's Stop = the SIGINT drain. A `tengu run` while Studio runs one is refused like any second runner, and the reverse (Studio shows `attached`). Operator doc: `docs/studio-2026-10-08.md` |
| a second `tengu run` (or a `tengu webhooks`, or a `tengu soe cycle` — it takes the same leases) of the same sandbox | exits 1: ``sandbox `<s>` is already running: lease `runtime:<s>` in <state dir>/runtime.db is held by `<host>:<pid>:<uuid>` for <n> s more. Stop that `tengu run` / `tengu webhooks` first (SIGTERM drains it); if it crashed, retry once the lease expires.`` |
| a `tengu run` / `tengu webhooks` of another sandbox naming the same `[xmarket] state` | exits 1: ``state dir <dir> already has an owner: lease `state:<dir name>` in <dir>/runtime.db is held by `<host>:<pid>:<uuid>` for <n> s more — …`` (review #13: a ledger has one owner) |
| a `tengu run` / `tengu webhooks` of another `[soe]` sandbox naming the same `[sources] state` | exits 1: ``SOE state root <dir> already has an owner: lease `state:<dir name>` in <dir>/runtime.db is held by `<host>:<pid>:<uuid>` for <n> s more — …`` (one owner of the cycles and state logs) |

## `[runtime]` (`src/config/runtime.rs`, `deny_unknown_fields`, all optional)

| Key | Default | Effect |
|---|---|---|
| `shutdown_grace_secs` | 20 | after the stop signal, running loop events and tasks get this long (≤ 3600), then are aborted |
| `max_decisions_in_flight` | 4 | loop events running at once across all loops; a loop always runs one event at a time, in arrival order (also applies to `tengu webhooks`) |
| `max_queued_per_loop` | 64 | events one loop holds waiting (≥ 1); one more is refused: warn with loop + session id, counted `dropped`, `last_error` in `loop/1`, a webhook gets 429, a feed tick is dropped (the next one retries) |
| `heartbeat_secs` | 5 | period of the heartbeat file and the health rows (1–3600) |
| `heartbeat_stale_secs` | 30 | `tengu doctor --live` fails when the heartbeat is older (must exceed `heartbeat_secs`) |

## Single-runner lease

| Piece | Value |
|---|---|
| Store | `<state dir>/runtime.db`, table `leases` (WAL, one statement per change — same pattern as `solana-writes.db`) |
| State dir | `<TENGU_HOME>/state/<[xmarket] state>` when the sandbox has `[xmarket]`, else `<TENGU_HOME>/state/<[sources] state>` when it has `[sources]` (the SOE state root, `docs/soe-2026-10-08.md`), else `<TENGU_HOME>/state` (`config/runtime.rs::state_dir`) |
| Resources (`bootstrap/runtime.rs::LeasePlan`, taken in order, all or none) | `runtime:<sandbox>` — one runner per sandbox; with `[xmarket]` also `state:<dir name>` — one owner per state dir and its `ledger.db`, whichever sandbox names that `[xmarket] state` (`<TENGU_HOME>/state` without `[xmarket]` is install-wide: no state lease); with `[soe]` also `state:<[sources] state>` — one owner per SOE state root (`cycles/`, `stage-cache/`, the state logs); a dir is leased once |
| Holder | `<host>:<pid>:<uuid>`, one per process |
| Who takes them | `tengu run`, `tengu webhooks` and `tengu soe cycle` (the same set: never one beside another). Operator commands (`tengu risk status` / `halt` / `resume`, `tengu tool call`, `tengu doctor`) take none and work while a run holds them |
| TTL / renewal | 30 s / every 10 s (`application/runtime/mod.rs` `keep_lease` over the shared `HeldLeases`); a runner that crashed is replaced once its lease expires |
| Lost lease (another holder took it; it lapsed and another had it since — a renewal granted with another `acquired_at_ms`; or renewals failed until expiry — for a writer, within 1 s of it: `EXPIRY_GUARD_MS`) | the runner stops as failed (exit non-zero); lost for good (a later renewal never owns it again) |
| Writers under the leases (`ports::runtime::Ownership` = `HeldLeases`, `OwnerLeases::ownership` / `Runtime::ownership`) | renew them before each irreversible write and race long waits against the loss: the SOE cycle (`tengu soe cycle`, the `soe_cycle` job) before each stage, the freeze and each state-log line — lost ⇒ `lease_lost`, nothing more written (`docs/soe-2026-10-08.md` § 10) |
| A binary from before 2026-10-01 (the frozen weekend `tengu-6fcb455`) | takes `runtime:<sandbox>` only — a newer runner of the same sandbox is still refused; of another sandbox on its state dir, not |
| Ledger owners (`outbound/paper_store.rs`, `docs/xmarket-risk-paper-2026-09-30.md` § Ledger) | the second line of defence: each account records the sandbox whose tools first wrote it; another sandbox's tools are refused `account_owner_mismatch` |

## State layout (tracker convention 3)

One state dir per sandbox, `<TENGU_HOME>/state/<[xmarket] state>` (an SOE sandbox: `<[sources] state>`, § SOE sandbox), shared by every process of the install. Paths: `src/config/xmarket.rs` (`ledger_db`, `runtime_db`, `history_dir`, `market_db`, `backtests_dir`, `rankings_dir`). `tengu prune` never deletes it — only `state/flows`, in every mode (`--hard` spares a workspace child that holds `TENGU_HOME`).

|---|---|
| `[risk]` needs `[xmarket]` | the ledger lives in the state dir |

## Shutdown

| Step | What happens |
|---|---|
| 1 | stop signal (`tokio::sync::watch`) reaches every task |
| 2 | webhook server stops accepting (`with_graceful_shutdown`); loop endpoints answer 503 from now on |
| 3 | heartbeat `stopping`; queued loop events are dropped (logged with their session id); running ones get `shutdown_grace_secs`, then are aborted |
| 4 | heartbeat `stopped` (+ reason); leases released; log lines `loop totals` per loop and `tengu run stopped` with finished / dropped / aborted counts |

A task that ends before the stop signal (webhook server crash, a panic) stops the runtime as failed — Docker's restart policy brings it back.

Studio's Stop (`tengu studio`, control on) is step 1 with reason `studio stop` (a Studio SIGINT: `studio SIGINT`) — the same drain, the same report (Trace § Control).

## Webhooks under `tengu run`

| Build / config | Result |
|---|---|
| `--features webhooks` + `[webhooks] enabled = true` | `/webhooks/:name` served in this process (`docs/webhooks-2026-05-11.md`); loop endpoints queue on the runtime's loops |
| feature on, `enabled = false` | log `webhooks off` |
| built without the feature | log `webhooks off`; a warning when `[webhooks] enabled = true` |

`tengu webhooks` beside a `tengu run` of the same sandbox (or of another sandbox on its `[xmarket]` state dir) exits 1 — both take the same leases (§ Single-runner lease): two processes would each own a copy of every loop.

Trace: each request to a configured endpoint is a `trigger.webhook` root in the runtime's run (Studio Play too), its loop events or planner turn under it, then `webhook.responded`; `tengu webhooks` writes the same into its own run (`kind = "webhooks"`). § Trace.

## Health (`src/application/runtime/health.rs`)

| Output | Where | Content |
|---|---|---|
| `run-<sandbox>.json` | state dir; every `heartbeat_secs` (first at start), `stopping` / `stopped` on shutdown; temp file + rename | `sandbox`, `pid`, `holder`, `state` running \| stopping \| stopped, `stop_reason`, `started_at_ms`, `ts_ms`, `heartbeat_secs`, `loops` (= `loop/1` data), `feeds` (= `feed/1` data) |
| `loop/1:<name>` | the loop agent's `observations.db`, every beat | `queue_depth`, `in_flight`, `accepted`, `completed`, `failed`, `dropped`, `last_decision_age_s` (last finished event), `last_error` |

## `tengu doctor --sandbox <s> --live` (healthcheck for a `tengu run` container)

Runs the normal doctor, then reads the heartbeat + the `loop/1` / `feed/1` rows (every agent workspace whose `observations.db` exists; per name the newest wins) → `domain::runtime::live_verdict`. Exit non-zero when:

| Check | Fails when |
|---|---|
| heartbeat | `run-<s>.json` missing or unreadable, older than `heartbeat_stale_secs`, or `stopping` / `stopped` |
| required feed | `down`; no item for `stale_after_s` (since start while none); entry not updated for `max(stale_after_s, heartbeat_stale_secs)` |
| health row | a `loop/1` / `feed/1` row does not decode |
| loops, optional feeds | never — reported only |

```
  Runtime (live): sandbox xmarket · /opt/tengu/data/state/xmarket
    ok   heartbeat                running · up 3 h 0 min · last beat 2 s ago (limit 30 s) · pid 4242 · holder vps-1:4242:0f8c6a52-5d0e-4c8e-9a71-3b2f1c9d7e44
    ok   loop xm_main             in_flight 0 · queue 0 · done 11 · failed 1 · dropped 0 · last decision 14 s ago · last error: jev 503
    FAIL feed hl_ctx (required)   down: down · items 1 · last item 1 s ago (stale after 60 s) · reconnects 0 · dropped 0 · last error auth_required: blocked (geo/WAF/Tor exit?)
    => NOT live
```

## Feeds (`[feeds.<n>]`)

One supervised task `feed:<name>` per block, started after the loops (`bootstrap/runtime.rs::start_feeds` → `application/runtime/feeds.rs`, fire times `src/domain/schedule.rs`); keys and validation in `src/config/feeds.rs`, examples in `config.example.toml` (`hl_ctx`, `hl_book` with windows, daily `risk_status`, the `xm_exits` exit check every 15 s, the `xm_weekend_fade` step every 60 s, an at-tick loop event). A feed that fails to build — a tool its agent cannot run, a tick target not running — stops `tengu run` at start; the `tengu run started` log line lists the feeds.

| Key / rule | Value |
|---|---|
| `kind = "tool"` | `agent` runs `tool` (listed in its `tools`, or opted in via `workspace_tools`) through the executor its decision loop would get (scopes, workspace, secret redaction); `args` + fan-out `each = { coin = ["xyz:TSLA", "xyz:NVDA"] }` (every combination, key order, ≤ 500 calls; `concurrency` 1–32, default 1). No LLM, no Jev: deterministic clock work (exit checks, the weekend fade, the daily risk roll) is a tool feed |
| `kind = "tick"` | `event` + `ts_ms` (the slot) to `[decision_loops.<target>]` (a Jev loop), session id `<name>:<slot ms>` |
| `kind = "job"` | `job` names an application job from a closed list (`config/feeds.rs` `JOBS`; never a command from config); no `agent` / `tool` / `args` / `each` / `concurrency` / `target` / `event`. `RuntimeJob::run(slot ms, "feed:<name>:<slot ms>")` (`ports/runtime.rs`; a retry: the same slot and id); `Done` = one item, `Failed { class }` = a failed call of that class — the same backoff, at-tick retry window and health. Strategy ranking stays a `kind = "tool"` feed |
| job `soe_cycle` | needs `[soe]` (`config/soe.rs`; an `[soe]` sandbox runs job feeds only). Built by `bootstrap/soe.rs`: `FsCycleStore` on the `[sources]` state dir, `sources.db` opened each run (none yet ⇒ an empty packet), the Architect and Critic as `run-agent` children behind the stage cache (`adapters/outbound/soe/`), the generation pin, `operator.toml` of the state root. | other kinds | `"poll"` = `info-fetch` (W2), `"stream"` / `"ws"` / `"rows"` later — refused at load until built |
| `every_secs` | base interval, 1 s – 7 d, on the UTC epoch grid (60 ⇒ :00 of every minute) |
| `windows` | `{ days = ["Sun"], from = "17:00", to = "19:00", every_secs = 60 }` in `tz`; replaces `every_secs` inside; `to <= from` ends the next day, `"24:00"` = midnight; no `days` = every day |

| `tz` | `America/New_York` · `Europe/Paris` · `UTC` (default). DST: a gap time reads with the standard offset, an overlap time is the first instant — an at-tick fires once per named day; windows keep wall-clock bounds |
| `jitter_pct` | 0–50: a grid fire starts up to this % of its interval late (spreads the request budget) |
| `run_on_start` | one run at start (slot = the start time) |
| call ids | `feed:<name>:<slot ms>:<i>` → `ToolCtx.call_id`; a retry reuses it (exec tools deduplicate) |
| egress audit | each request a feed call makes: `agent` = the feed's, `session` = `feed:<name>`, `call_id`; a loop's: its agent, the event's session id, `<loop>:<session>:<t>` (`egress::AttributedExecutor`, `docs/egress-2026-09-16.md` § Audit log) |
| one in flight | a run finishes before the next fire is computed; a tick is skipped (`dropped`) while the feed's previous event is still queued or running |
| missed slots | never replayed: the next fire is computed when a run ends; a slot reached later than max(60 s, its interval) after its time (at-ticks: 60 s — a system sleep) is skipped (`dropped`) |
| clock stepped back | a last slot more than 1 s after the clock counts as now: the next fire comes on the new clock's grid, not after the step; a slot before the step may fire again under its call ids (exec tools deduplicate) |
| failures | observation `status = error` (class of its most retry-worthy error), `HTTP <non-2xx>` text, executor error (`fatal`) ⇒ `domain::backoff` FEED: transient / timeout / rate limit ⇒ the failed calls again after 1–60 s (≥ `Retry-After`), a slot due first runs every call; quota / long rate limit ⇒ park (no slot until then); auth / fatal / decode / not_applicable ⇒ the next slot — except an at-tick slot (and the start run of an at-only feed: its next slot is a day or a week away), whose failed calls of any class retry as transient (1 s … 60 s, same ids) until 15 min after the slot (`AT_RETRY_WINDOW_MS`; a busy or failing ledger is an executor error = `fatal`), then wait for the next tick (review #14). Messages in logs and rows: no URLs, ≤ 200 chars cut at whole words |
| health | `feed/1:<name>` in the feed agent's store (tick: the loop agent's): `connecting` → `live` (per ok call / sent tick) · `backoff` · `down`; `required` (default false) + `stale_after_secs` (default 3 × the longest interval, ≥ 60 s; without `every_secs` — idle between windows / at-ticks — 8 d) drive `tengu doctor --live` |
| stop | checked before every nap (≤ 60 s) and every call; a call in progress finishes within `shutdown_grace_secs` |
