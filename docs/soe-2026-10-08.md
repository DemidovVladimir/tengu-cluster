# Software Opportunity Engine (SOE) — contract, sources, threat model (2026-10-08)

A sibling capital-intelligence domain: a weekly, evidence-backed ranking of software opportunities (acquire, automate, integrate, migrate, productize, license, deliver, partner), where `HOLD` is a valid week. **State:** O0 package + eval set (16 dated synthetic cases, § 7) + O1 value types, records, the private profile / record loader, deterministic economics, the PRD § 7.2 hard gates, capability fit and the ranking primitives (`src/domain/soe/`, `src/config/soe.rs`). Offline: no SOE tool, sandbox, CLI, source fetch or cycle exists yet. Tutorial: [`tutorial/soe.html`](tutorial/soe.html).

The planning set (PRD v0.1, gated roadmap, compatibility review — `software-opportunity-{prd,roadmap,compatibility}-2026-10-04.md`) stays local to the operator: it holds private figures. This is the public SOE doc; it names profile fields, never their values.

| Rule | Applied as |
|---|---|
| Field names, never values | operator parameters live only in the signed private profile (§ 2); no committed file, test, fixture or code default carries them |
| Offline until G-O0 | no network read, contact, spend or publish |
| `HOLD` is first class | a week may end with no new test |
| Human gates | every external action needs the operator's explicit approval (PRD § 9); no such action exists before O5 |

## 2. Operator contract — profile fields (PRD § 4, § 7.2, § 14)

Profile (built: `config/soe.rs::load_profile`): `<TENGU_HOME>/state/soe/operator.toml`, `schema = "soe.operator_profile/1"`, `signed_by` + `signed_at`. Code has no built-in value for any field and no field has a serde default; there is no salary field. Refusals, in order: `operator_profile_missing` · `invalid_profile` (every problem listed) · `synthetic_profile_refused` (a fixture, unless allowed) · `profile_in_repo` (a real profile inside a git work tree) · `profile_mode` (any group / other permission bit) · `operator_profile_unsigned` (`signed_by = "UNSIGNED"`). `tengu soe init` (planned) writes an UNSIGNED template. ## 4. Threat model

| Threat | Existing control (code) | SOE rule |
|---|---|---|
| Secrets | `SanitizedToolExecutor` redacts vault values and `*_API_KEY` `*_SECRET` `*_TOKEN` `*_PASSWORD` `*_PRIVATE_KEY` env values from text, observations and errors on every surface (`domain::secrets::is_env_secret`); `$SEC_USER_AGENT` is never logged | credentials by env-var name only — never in a record, fixture or profile |
| PII | none yet: no SOE store or tool exists | records keep entity ids and public notice fields, not people; fixtures scrubbed; a public brief takes facts from an allow-list (planned) |
| Malicious content | `egress.rs` policy + `[egress] allow_hosts` + scope `net_hosts` on every request (`http_request` re-checks each redirect hop); `write_file` refuses agent / CLI state (`domain::scope::protected_write`) | fetch only registry hosts; typed parsers — a bad row is a visible failure, never a guess |
| Prompt injection | the planner call has no tools, memory or grounding (`run_turn_with_system`); every tool call is scope-checked | source text is data — facts and inferences never become instructions; no SOE tool in O1; O2's `source_evidence` is read-only |
| Seller fraud | `DealReview` blocks carry a status (`VERIFIED` needs an evidence locator); `ACQUIRE_TRANSFORM` without a `[deal]` is refused (`deal_review_missing`) | a seller claim is never a fact (status `SELLER_CLAIM`); unverified ownership, legal or transition ⇒ `HOLD` (`LEGAL_UNRESOLVED`), another unverified block ⇒ `HOLD` (`DILIGENCE_OPEN`), a red flag ⇒ `REJECT` (`DEAL_RED_FLAG`) |
| Public leakage | public repo; this doc names fields, never values | profile, `sources.db`, cycles and episodes stay under `<TENGU_HOME>/state/soe/` (the loader refuses a real profile inside a git work tree or with any group / other permission bit); public lineage records hold ids + sha256 only; `PublicBrief` serializes allow-listed keys only and cites `url:` facts only (`private_locator`); its sanitizer is O7 |
| Approval bypass | Telegram fails closed without an allow-list; no tool call waits for an approval (`[telegram] tool_approvals` is not implemented) | no contact / spend / publish / sign / deploy tool exists; sandbox `soe` is a closed world (planned) |
| Unbounded downside | the trading `[risk]` gate does not apply | hard gates before ranking (PRD § 7.2, § 5 below): cash above the cap, no staged stop rule or an unstated downside ⇒ `REJECT` / `HOLD` |

## 5. Records and values

| Record | Schema | Holds | State |
|---|---|---|---|
| values | — | `Minor`, `Money`, `Currency`, `Bps`, `FxRate`, `Converted`, `Est`, `Assumption`, `Scenario`, `SchemaTag` (`src/domain/soe/value.rs`) | built |
| source record | `domain::source::SourceRecord` | PRD § 5.2 provenance; amounts as written (`NativeAmount`) | planned O2 |
| record header | every record below | `schema`, `id` (lineage id), `version` ≥ 1; unknown keys refused at every level; every problem listed `<code>: <field>: <why>` (`src/domain/soe/record.rs`) | built |
| `OperatorProfile` | `soe.operator_profile/1` | § 2 fields + `[[capabilities]]` (level, proof, capacity, cost, validity) + `rank_order` (8 `RankKey`s); private | built |
| `Opportunity` | `soe.opportunity/1` | customer, pain, mechanism (12, closed: PRD § 3 + `HOLD` / `REJECT`), source record ids, jurisdictions, economic inputs (`RECURRING` · `ONE_OFF` · `ACQUISITION` · `REVENUE_SHARE`, every input an `Assumption`), `RiskAssessment`, `ExperimentSpec` (stages, `ApprovalKind`), `DealReview` | built |
| economics · gate verdict | — (computed, never stored as truth) | downside / base / upside figures from the input ranges (`economics.rs`) · `PASS` / `HOLD` / `REJECT` with every failed gate (`gates.rs`); tables below | built |
| `WeeklyPortfolio` | `soe.weekly_portfolio/1` | ISO week, profile + inputs sha256, ranked / held / rejected rows with an action (`CHEAP_TEST` `CONTINUE_ACTIVE` `HOLD` `DILIGENCE` `REPRICE` `REJECT`; no launch), allocation, `HOLD` rationale | type, rows and the `HOLD` week built (`rank.rs`); the allocated week O3 `allocate` |
| `PublicBrief` | `soe.public_brief/1` | facts (`url:` only), thesis, disclosed assumptions, experiment update | type built; sanitizer O7 |
| `OpportunityEpisode` | `soe.opportunity_episode/1` | verdict, actions, spend, hours, forecast vs actual, lineage `Quality` / `Lesson`; quadrant = lineage `quadrant_of`; private | built |
| eval case | `soe.eval_case/1` | one dated decision: `as_of`, `class`, `synthetic`, the `profile` id it holds for, `[[cited]]` record views, `[[candidates]]`, `[expected]` verdicts · gates · ranked · next information · versions (§ 7) | built (`eval.rs`) |

| Value rule (built) | Refusal code |
|---|---|
| Money = integer minor units from decimal text (`"41250.75"`, or whole units); ≤ 2 fraction digits; a float is refused | `invalid_amount` |
| Closed currency set EUR USD GBP CHF KZT RUB CNY, 2 minor digits each; a source amount in another currency is `UNKNOWN` with the reason | `invalid_currency` |
| FX: native amount, rate (+ its source and time) and result stored apart; result = floor or ceil of the exact product | `invalid_conversion` · `invalid_rate` |
| Rounding never flatters: inflows (revenue, contribution) floor, outflows (cost, exposure, capital) ceil | — |
| Estimate = `"UNKNOWN"` · `"UNKNOWN: <reason>"` · `{ low, base, high }` with low ≤ base ≤ high; an unknown never reads as 0 | `invalid_estimate` · `invalid_range` |
| Scenarios: downside takes each input's adverse end, upside its favorable end, base the base | — |
| Every record carries `schema = "soe.<record>/1"`; another version is refused | `schema_unsupported` |
| Record rules: `HIGH_TICKET_DELIVERY` with `RECURRING` revenue · `PARTNER_REVSHARE` without `REVENUE_SHARE` / `ACQUIRE_TRANSFORM` without `ACQUISITION` · `ACQUIRE_TRANSFORM` without `[deal]` · an assumption or the `fx` rate dated after the record's `as_of` | `fake_recurring` · `revenue_model_mismatch` · `deal_review_missing` · `future_leakage` |

| Economics rule (built, `ECONOMICS_VERSION` 1) | Applied as |
|---|---|
| Unit | integer only (`i128` inside, minor units out), in the profile `currency`; another native currency converts through `economics.fx`, else every money figure is `UNKNOWN: needs economics.fx` |
| Unknown | a figure lists the input fields it lacks — never 0; figures that do not need the input stay known |
| Run-rate month | `max_payback_months`, counted from the decision; nothing is earned during `ramp_months` |
| Revenue | `RECURRING` customer base (thousandths, churned monthly) × price · `ACQUISITION` asset revenue churned monthly · `REVENUE_SHARE` partner revenue × share · each × (1 − collection loss) · `ONE_OFF` expected contract value per occupied month (⌈weeks × 12 / 52⌉) |
| Contribution | cash = revenue − variable − fixed; time-adjusted = cash − owner hours × `shadow_hourly_rate` |
| Payback | first month the running sum (fixed costs and owner hours from month 1) covers the initial capital; none in 600 months ⇒ `NOT_REACHED`; cash payback needs no rate |
| Expected loss | Σ probability × impact: a low..high range, never a point |
| Scenarios | downside = every input's adverse end, upside its favorable end; `ONE_OFF` figures take the worse / better delivery length per figure |
| Basis | `PRE_TAX` (no tax model in v1) |
| Identity | `inputs_sha256` = canonical sha256 of version + economics + risk + the profile knobs read |

| Gate (built, PRD § 7.2) | `REJECT` when | `HOLD` when |
|---|---|---|
| exposure · tranche | largest of downside initial capital, Σ stage cash, max-loss cash > `max_cash_exposure` · a stage > `max_validation_tranche` (at the value passes) | an amount unknown |
| contribution · payback | base contribution (`contribution_basis`) < `min_monthly_contribution` with no bounded path · base payback > `max_payback_months` or `NOT_REACHED` | `BELOW_TARGET_WITH_PATH`: the upside reaches the target and a staged experiment tests it; unknown; a passing figure under `POST_TAX` |
| delivery · bounds | — · owner time, support, payment access or scope `UNBOUNDED` | a `ONE_OFF` longer than `max_one_off_delivery_weeks` · a bound or the owner hours `UNKNOWN` |
| evidence | — | no cited record supports it at `as_of` (not knowable yet, trigger only, expired or contradicted) · one demand event only (`SINGLE_DEMAND_SIGNAL`) · a contradiction · no revenue input names evidence |
| legal · deal | a deal red flag | a legal / sanctions / licensing / data / transferability risk not `RESOLVED`; a deal block not `VERIFIED` |
| jurisdictions · stop rule · downside · mechanism | — · the first stage with cash has no stop rule · — · `REJECT` | a jurisdiction `UNKNOWN` or outside `jurisdictions_allow` · no experiment · a max-loss term unknown · `HOLD` |
| verdict | any `REJECT` row | else any `HOLD` row; else `PASS` (still no permission to act); refused outright: an unsigned profile, a decision time before the opportunity |

| Ranking rule (built, `rank.rs` · `matching.rs`) | Applied as |
|---|---|
| Who ranks | `PASS` candidates only, by the profile's `rank_order` (no built-in order), ties by id |
| Keys | `EVIDENCE_CONFIDENCE` (`HIGH`: a supporting fact, nothing contested · `MEDIUM`: ≥ 2 supporting events · `LOW`) · `TIME_ADJUSTED_BASE` · `PAYBACK_BASE` (cash) · `DAYS_TO_DECISIVE_EVIDENCE` (to the end of the experiment deadline, rounded up) · `REVERSIBILITY` · `CAPABILITY_FIT` · `CONCENTRATION_MAX` (largest share) · `DEFENSIBILITY` |
| Unknown | ranks after every known value of its key (no experiment, no concentration listed, a `UNKNOWN` tier, no required skill) |
| Copies | supporting records count once per `event_key` (the O2 as-of view gives copies one key) |
| Capability fit | per required skill: `PROVEN` (an active proven capability) > `CLAIMED` (active, not proven) > `STALE` (none active: expired or not yet valid) > `MISSING`; the opportunity takes its weakest skill |
| Explanation | the first key in the profile's order on which two candidates differ, with both values |
| Rank moves | per id whose rank changed: `ENTERED` / `LEFT` (verdict + gates), `CROSSED` (the nearest swapped candidate, the deciding key, both values before → after), `SHIFTED` (one entered or left above it) |
| Sensitivity | scale one input (`OWNER_HOURS` `CONVERSION` `CHURN` `PRICE`) by ± bps, rounded against the candidate, and report the base time-adjusted figure, the verdict and the gates it adds or removes |
| Weekly rerun | one row per id: its highest version not dated after the decision; a later version is ignored |
| `HOLD` week | nothing passes: held / rejected rows with every gate, the next information ordered by how many candidates each field blocks, a rationale; validated as a `WeeklyPortfolio` |

| From | Deviation | Why |
|---|---|---|
| Roadmap § 2, compatibility § 5: extend the capability registry | operator capabilities live in the private profile, not `lineage/capabilities/` | public repo; operator decision |
| PRD § 6 `Signal` | no SOE `Signal` type: `Opportunity.signals` lists source record ids | one provenance type for every domain (`domain/source/`) |
| Roadmap O0: accepted PRD + compatibility review | both stay untracked; this doc is the public SOE doc | they hold private figures |
| PRD § 6 `EconomicModel` · `Capability` | economics are computed from `Opportunity.economics` (no stored model record); capabilities sit inside the profile | one source of truth per figure |
| O1 design: `OpportunityEpisode.forecast_base: ScenarioMetrics` | `forecast_base` holds `Est` fields (`monthly_cash`, `time_adjusted`, `owner_hours`) | the economics type lands after the records |
| O1 design W3: customers after `ramp` months; payback = initial / base contribution | run-rate month = `max_payback_months` with the ramp as a delay; payback = running monthly sum | the design's rule makes a longer (adverse) ramp raise revenue; the plain ratio flatters a growing base and ignores the ramp |
| O1 design W3: `POST_TAX` basis | figures are `PRE_TAX`; a `POST_TAX` profile holds a passing figure (`UNKNOWN_INPUT:economics.tax_review`), a failing one still fails | no tax input exists to compute it |
| O1 design W4: `gates(opp, signals: &[Signal], …)` | `gates(opp, &[CitedRecord], …)`: kind `FACT` / `DEMAND` / `TRIGGER`, `knowable_at`, `valid_until`, `contradicted_at` — the O2 as-of view builds them | one provenance type (`domain/source/`, not yet merged here); soe never reads a store |
| O1 design W4 codes | added `SINGLE_DEMAND_SIGNAL` (PRD § 5.1), `DILIGENCE_OPEN`, `DEAL_RED_FLAG` (a red flag is not "unresolved legal") | named reasons |
| Profile knobs | `weekly_owner_hours`, `channels_allow`, `languages`, `exclusions` are not gates | capability fit is a rank key (`CAPABILITY_FIT`); weekly hours and the tranche are the O3 allocation's; channels, languages and exclusions are not read yet |
| O1 design W5: `rank.rs::build_portfolio` (allocation greedy over weekly hours + tranche) | `rank.rs` holds the primitives and the `HOLD` week only; the allocated week (and its test `allocation_respects_weekly_hours_and_tranche`) is O3 `allocate` | critic C4: one portfolio builder |
| O1 design W5: `evidence_confidence(&[Signal], …)` counting distinct `origin_source_id` | reads the `CitedRecord` views; copies share the `event_key` the O2 as-of view assigns | C1 (no `Signal`) · C6 (syndication is detected only in `domain/source/asof.rs`) |
| O1 design W5: `capability_fit` = `PROVEN` `PARTIAL` `STALE` `MISSING` | `matching.rs::fit`: `PARTIAL` is named `CLAIMED` (what the capability level says); no required skill = `UNSTATED`, ranked as unknown | C7: one fit rule, reused by O3 |
| O1 design W5: `sensitivity(opp, signals, profile, …)` | `sensitivity(opp, cited, profile, as_of, …)`; `PRICE` = `price_per_month` · `contract_value` · `share` (revenue share); an input outside the model scales nothing (reported) | one input name per revenue model |
| O1 design W8: `[[signals]]` in a case; the acquisition `HOLD` case named after a price above the synthetic cap | `[[cited]]` (`CitedRecord` views) + a `profile` id + optional `versions`; case `hold_unverifiable_transfer_acquisition` (a 15000.00 asset, under the synthetic cap, so only the diligence holds it) | C1; boundaries are relative to the profile the case names |

## 7. Eval set (O0, built)

`tests/fixtures/soe/cases/<id>.toml` (`soe.eval_case/1`), run under `tests/fixtures/soe/profile.synthetic.toml` (`synthetic-operator`). Every case is `synthetic = true`: invented example values and `synthetic:` record ids — no real firm, person, URL or figure. Each run also checks that dropping every record not knowable at `as_of` changes nothing, and that a week where nothing ranks is a valid `HOLD` week.

| Case | Class | Tests |
|---|---|---|
| `good_recurring_automation` | GOOD | a recurring automation on one primary fact passes and ranks |
| `good_high_ticket_integration` | GOOD | one-off delivery priced with owner time, win probability and collection loss; two independent demand events |
| `good_revenue_share` | GOOD | two revenue shares: the fact-backed one ranks above the larger demand-backed one (evidence first in the synthetic order) |
| `bad_hidden_labor_12k_160h` | BAD | 12000.00 a month collected, 160 owner hours: passes in cash, rejected time-adjusted |
| `bad_cash_above_cap` | BAD | the adverse end of the build puts more than `max_cash_exposure` at risk |
| `platform_change_automation_vs_migration_hidden_support` | BAD | PRD § 12 #1: one notice, two mechanisms; the automation's unbounded support rejects it, the migration passes |
| `boundary_cash_exactly_cap` | BOUNDARY | exactly at the cap passes, one cent above rejects |
| `boundary_contribution_one_cent_below` | BOUNDARY | exactly at the target passes, one cent below rejects |
| `hold_unverifiable_transfer_acquisition` | HOLD | seller-claimed ownership, unverified transition, unknown costs: the diligence questions are the next information |
| `hold_unknown_price` | HOLD | an unknown price holds, never passes or rejects |
| `syndicated_copies_one_confirmation` | HOLD | two copies of one tender are one demand event (held); two independent tenders pass |
| `no_candidate_passes_empty_hold_portfolio` | HOLD | PRD § 12 #4: nothing passes — a valid `HOLD` week, next information ordered by how many candidates each field blocks |
| `stale_signal_expired` | STALE | an expired listing supports nothing |
| `contradictory_sources` | CONTRADICTORY | a known contradiction holds; one arriving after the decision changes nothing yet |
| `lookahead_signal_ignored` | LOOKAHEAD | a fact observed later the same day is not knowable at the decision |
| `weekly_rerun_no_duplicates` | LOOKAHEAD | PRD § 12 #5: one row per id at its latest version known at the decision; a later version is ignored |
