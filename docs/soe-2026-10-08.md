## 2. Operator contract — profile fields (PRD § 4, § 7.2, § 14)

Profile (built: `config/soe.rs::load_profile`): `<TENGU_HOME>/state/soe/operator.toml`, `schema = "soe.operator_profile/1"`, `signed_by` + `signed_at`. Code has no built-in value for any field and no field has a serde default; there is no salary field. Refusals, in order: `operator_profile_missing` · `invalid_profile` (every problem listed) · `synthetic_profile_refused` (a fixture, unless allowed) · `profile_in_repo` (a real profile inside a git work tree) · `profile_mode` (any group / other permission bit) · `operator_profile_unsigned` (`signed_by = "UNSIGNED"`). `tengu soe init` (§ 8) writes an UNSIGNED template with generic values, the four money values `REQUIRED` (the operator's; the source is public) and no capability — mode 0600, never over an existing file (`profile_exists`), never inside a git work tree (`profile_in_repo`); the operator reviews it, adds `[[capabilities]]` and signs. Public fixtures carry `synthetic = true` round values that are not the operator's.

## 4. Threat model

| Threat | Existing control (code) | SOE rule |
|---|---|---|
| Secrets | `SanitizedToolExecutor` redacts vault values and `*_API_KEY` `*_SECRET` `*_TOKEN` `*_PASSWORD` `*_PRIVATE_KEY` env values from text, observations and errors on every surface (`domain::secrets::is_env_secret`); `$SEC_USER_AGENT` is never logged | credentials by env-var name only — never in a record, fixture or profile |
| PII | TED requests and parses an allow-list of fields, never a contact field (`domain/source/ted.rs` `TED_FIELDS`, test `contact_fields_are_never_kept`); `sources.db` and every cycle stay under the private state root | records keep entity ids and public notice fields, not people; fixtures scrubbed; a public brief takes facts from an allow-list (planned) |
| Malicious content | `egress.rs` policy + `[egress] allow_hosts` + scope `net_hosts` on every request (`http_request` re-checks each redirect hop); `write_file` refuses agent / CLI state (`domain::scope::protected_write`) | fetch only registry hosts; typed parsers — a bad row is a visible failure, never a guess |
| Prompt injection | the planner call has no tools, memory or grounding (`run_turn_with_system`); every tool call is scope-checked | source text is data — facts and inferences never become instructions; a stage goal holds ids and the packet sha256, never source text; `soe_view` fences source text after a note and its observation `data` holds ids and counts only; a draft citing a record outside the packet is refused (§ 13) |
| Seller fraud | `DealReview` blocks carry a status (`VERIFIED` needs an evidence locator); `ACQUIRE_TRANSFORM` without a `[deal]` is refused (`deal_review_missing`) | a seller claim is never a fact (status `SELLER_CLAIM`); unverified ownership, legal or transition ⇒ `HOLD` (`LEGAL_UNRESOLVED`), another unverified block ⇒ `HOLD` (`DILIGENCE_OPEN`), a red flag ⇒ `REJECT` (`DEAL_RED_FLAG`) |
| Public leakage | public repo; this doc names fields, never values | profile, `sources.db`, cycles and episodes stay under `<TENGU_HOME>/state/soe/` (the loader refuses a real profile inside a git work tree or with any group / other permission bit); public lineage records hold ids + sha256 only; `PublicBrief` serializes allow-listed keys only and cites `url:` facts only (`private_locator`); its sanitizer is O7 |
| Approval bypass | Telegram fails closed without an allow-list; no tool call waits for an approval (`[telegram] tool_approvals` is not implemented) | no contact / spend / publish / sign / deploy tool exists; sandbox `soe` is a closed world: `[soe]` load rules (§ 11) + `soe_sandbox_has_no_side_effect_surface` (§ 13) |
| Unbounded downside | the trading `[risk]` gate does not apply | hard gates before ranking (PRD § 7.2, § 5 below): cash above the cap, no staged stop rule or an unstated downside ⇒ `REJECT` / `HOLD` |

| Value rule (built) | Refusal code |
|---|---|
| Money = integer minor units from decimal text (`"41250.75"`, or whole units); ≤ 2 fraction digits; a float is refused | `invalid_amount` |
| Closed currency set EUR USD GBP CHF KZT RUB CNY, 2 minor digits each; a source amount in another currency is `UNKNOWN` with the reason | `invalid_currency` |
| FX: native amount, rate (+ its source and time) and result stored apart; result = floor or ceil of the exact product | `invalid_conversion` · `invalid_rate` |
| Rounding never flatters: inflows (revenue, contribution) floor, outflows (cost, exposure, capital) ceil | — |
| Estimate = `"UNKNOWN"` · `"UNKNOWN: <reason>"` · `{ low, base, high }` with low ≤ base ≤ high; an unknown never reads as 0 | `invalid_estimate` · `invalid_range` |
| Scenarios: downside takes each input's adverse end, upside its favorable end, base the base | — |
| Every record carries `schema = "soe.<record>/1"`; another version is refused | `schema_unsupported` |
| Record rules: `HIGH_TICKET_DELIVERY` with `RECURRING` revenue · `PARTNER_REVSHARE` without `REVENUE_SHARE` / `ACQUIRE_TRANSFORM` without `ACQUISITION` · `ACQUIRE_TRANSFORM` without `[deal]` · an assumption or the `fx` rate dated after the record's `as_of` | `fake_recurring` · `revenue_model_mismatch` · `deal_review_missing` · `future_leakage` |

| Economics rule (built, `ECONOMICS_VERSION` 1) | Applied as |
|---|---|
| Unit | integer only (`i128` inside, minor units out), in the profile `currency`; another native currency converts through `economics.fx`, else every money figure is `UNKNOWN: needs economics.fx` |
| Unknown | a figure lists the input fields it lacks — never 0; figures that do not need the input stay known |
| Run-rate month | `max_payback_months`, counted from the decision; nothing is earned during `ramp_months` |
| Revenue | `RECURRING` customer base (thousandths, churned monthly) × price · `ACQUISITION` asset revenue churned monthly · `REVENUE_SHARE` partner revenue × share · each × (1 − collection loss) · `ONE_OFF` expected contract value per occupied month (⌈weeks × 12 / 52⌉) |
| Contribution | cash = revenue − variable − fixed; time-adjusted = cash − owner hours × `shadow_hourly_rate` |
| Payback | first month the running sum (fixed costs and owner hours from month 1) covers the initial capital; none in 600 months ⇒ `NOT_REACHED`, any ramp (`max_payback_months` ≤ 600); cash payback needs no rate |
| Expected loss | Σ probability × impact: a low..high range, never a point |
| Scenarios | downside = every input's adverse end, upside its favorable end; `ONE_OFF` figures take the worse / better delivery length per figure |
| Basis | `PRE_TAX` (no tax model in v1) |
| Identity | `inputs_sha256` = canonical sha256 of version + economics + risk + the profile knobs read |

| Gate (built, PRD § 7.2) | `REJECT` when | `HOLD` when |
|---|---|---|
| exposure · tranche | largest of downside initial capital, Σ stage cash, max-loss cash > `max_cash_exposure` · a stage > `max_validation_tranche` (at the value passes) | an amount unknown |
| contribution · payback | base contribution (`contribution_basis`) < `min_monthly_contribution` with no bounded path · base payback > `max_payback_months` or `NOT_REACHED` | `BELOW_TARGET_WITH_PATH`: the upside reaches the target and a live staged experiment tests it; unknown; a passing figure under `POST_TAX` |
| delivery · bounds | — · owner time, support, payment access or scope `UNBOUNDED` | a `ONE_OFF` longer than `max_one_off_delivery_weeks` · a bound or the owner hours `UNKNOWN` |
| evidence | — | no cited record supports it at `as_of` (not knowable yet, trigger only, expired or contradicted) · one demand event only (`SINGLE_DEMAND_SIGNAL`) · a contradiction · no revenue input names evidence |
| legal · deal | a deal red flag | a legal / sanctions / licensing / data / transferability risk not `RESOLVED`; a deal block not `VERIFIED` |
| jurisdictions · stop rule · downside · mechanism | — · the first stage with cash has no stop rule · — · `REJECT` | a jurisdiction `UNKNOWN` or outside `jurisdictions_allow` · no experiment, or one that may have expired by the decision (`expires_at`) · a max-loss term unknown · `HOLD` |
| verdict | any `REJECT` row | else any `HOLD` row; else `PASS` (still no permission to act); refused outright: an unsigned profile, a decision time before the opportunity |

| Ranking rule (built, `rank.rs` · `matching.rs`) | Applied as |
|---|---|
| Who ranks | `PASS` candidates only, by the profile's `rank_order` (no built-in order), ties by id |
| Keys | `EVIDENCE_CONFIDENCE` (`HIGH`: a supporting fact, nothing contested · `MEDIUM`: ≥ 2 supporting events · `LOW`) · `TIME_ADJUSTED_BASE` · `PAYBACK_BASE` (cash) · `DAYS_TO_DECISIVE_EVIDENCE` (to the end of the experiment deadline, rounded up; a deadline that may have passed is unknown, never 0) · `REVERSIBILITY` · `CAPABILITY_FIT` · `CONCENTRATION_MAX` (largest share) · `DEFENSIBILITY` |
| Unknown | ranks after every known value of its key (no experiment, no concentration listed, a `UNKNOWN` tier, no required skill) |
| Copies | supporting records count once per `event_key` (the O2 as-of view gives copies one key) |
| Capability fit | per required skill: `PROVEN` (an active proven capability) > `CLAIMED` (active, not proven) > `STALE` (none active: expired or not yet valid) > `MISSING`; the opportunity takes its weakest skill |
| Explanation | the first key in the profile's order on which two candidates differ, with both values |
| Rank moves | per id whose rank changed: `ENTERED` / `LEFT` (verdict + gates), `CROSSED` (the nearest swapped candidate, the deciding key, both values before → after), `SHIFTED` (one entered or left above it) |
| Sensitivity | scale one input (`OWNER_HOURS` `CONVERSION` `CHURN` `PRICE`) by ± bps, rounded against the candidate, and report the base time-adjusted figure, the verdict and the gates it adds or removes |
| Weekly rerun | one row per id: its highest version not dated after the decision; a later version is ignored |
| `HOLD` week | nothing passes: held / rejected rows with every gate, the next information ordered by how many candidates each field blocks, a rationale; validated as a `WeeklyPortfolio` |
