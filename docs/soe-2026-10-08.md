# Software Opportunity Engine (SOE) — contract, sources, threat model (2026-10-08)

A sibling capital-intelligence domain: a weekly, evidence-backed ranking of software opportunities (acquire, automate, integrate, migrate, productize, license, deliver, partner), where `HOLD` is a valid week. **State:** O0 package + eval set (16 dated synthetic cases, § 7) + O1 value types, records, the private profile / record loader, deterministic economics, the PRD § 7.2 hard gates, capability fit, the ranking primitives and the offline `tengu soe` command (§ 8; `src/domain/soe/`, `src/config/soe.rs`, `src/adapters/inbound/cli/soe.rs`) + the O3 / O4 pure domain: observe, Architect proposals, Critic challenges, the allocation, the memo, the forecast log, the Review #2 packet and cycle ops (§ 9). No SOE tool or cycle exists yet. Tutorial: [`tutorial/soe.html`](tutorial/soe.html).

The planning set (PRD v0.1, gated roadmap, compatibility review — `software-opportunity-{prd,roadmap,compatibility}-2026-10-04.md`) stays local to the operator: it holds private figures. This is the public SOE doc; it names profile fields, never their values.

| Rule | Applied as |
|---|---|
| Field names, never values | operator parameters take effect only from the signed private profile (§ 2); no doc, test or fixture carries them and no code default exists — the `tengu soe init` template proposes the PRD § 14 values, unsigned, and every deciding command refuses it until the operator signs |
| Offline until G-O0 | no network read, contact, spend or publish |
| `HOLD` is first class | a week may end with no new test |
| Human gates | every external action needs the operator's explicit approval (PRD § 9); no such action exists before O5 |

## 2. Operator contract — profile fields (PRD § 4, § 7.2, § 14)

Profile (built: `config/soe.rs::load_profile`): `<TENGU_HOME>/state/soe/operator.toml`, `schema = "soe.operator_profile/1"`, `signed_by` + `signed_at`. Code has no built-in value for any field and no field has a serde default; there is no salary field. Refusals, in order: `operator_profile_missing` · `invalid_profile` (every problem listed) · `synthetic_profile_refused` (a fixture, unless allowed) · `profile_in_repo` (a real profile inside a git work tree) · `profile_mode` (any group / other permission bit) · `operator_profile_unsigned` (`signed_by = "UNSIGNED"`). `tengu soe init` (§ 8) writes an UNSIGNED template with the PRD § 14 proposals and no capability — mode 0600, never over an existing file (`profile_exists`), never inside a git work tree (`profile_in_repo`); the operator reviews it, adds `[[capabilities]]` and signs. Public fixtures carry `synthetic = true` round values that are not the operator's.

## 4. Threat model

| Threat | Existing control (code) | SOE rule |
|---|---|---|
| Secrets | `SanitizedToolExecutor` redacts vault values and `*_API_KEY` `*_SECRET` `*_TOKEN` `*_PASSWORD` `*_PRIVATE_KEY` env values from text, observations and errors on every surface (`domain::secrets::is_env_secret`); `$SEC_USER_AGENT` is never logged | credentials by env-var name only — never in a record, fixture or profile |
| PII | none yet: no SOE store or tool exists | records keep entity ids and public notice fields, not people; fixtures scrubbed; a public brief takes facts from an allow-list (planned) |
| Malicious content | `egress.rs` policy + `[egress] allow_hosts` + scope `net_hosts` on every request (`http_request` re-checks each redirect hop); `write_file` refuses agent / CLI state (`domain::scope::protected_write`) | fetch only registry hosts; typed parsers — a bad row is a visible failure, never a guess |
| Prompt injection | the planner call has no tools, memory or grounding (`run_turn_with_system`); every tool call is scope-checked | source text is data — facts and inferences never become instructions; no SOE tool in O1; O2's `source_evidence` is read-only |
| Seller fraud | `DealReview` blocks carry a status (`VERIFIED` needs an evidence locator); `ACQUIRE_TRANSFORM` without a `[deal]` is refused (`deal_review_missing`) | a seller claim is never a fact (status `SELLER_CLAIM`); unverified ownership, legal or transition ⇒ `HOLD` (`LEGAL_UNRESOLVED`), another unverified block ⇒ `HOLD` (`DILIGENCE_OPEN`), a red flag ⇒ `REJECT` (`DEAL_RED_FLAG`) |
| Public leakage | public repo; this doc names fields, never values | profile, `sources.db`, cycles and episodes stay under `<TENGU_HOME>/state/soe/` (the loader refuses a real profile inside a git work tree or with any group / other permission bit); public lineage records hold ids + sha256 only; `PublicBrief` serializes allow-listed keys only and cites `url:` facts only (`private_locator`); its sanitizer is O7 |
| Approval bypass | Telegram fails closed without an allow-list; no tool call waits for an approval (`[telegram] tool_approvals` is not implemented) | no contact / spend / publish / sign / deploy tool exists; sandbox `soe` is a closed world (planned) |
| Unbounded downside | the trading `[risk]` gate does not apply | hard gates before ranking (PRD § 7.2, § 5 below): cash above the cap, no staged stop rule or an unstated downside ⇒ `REJECT` / `HOLD` |

| Value rule (built) | Refusal code |
|---|---|
| Money = integer minor units from decimal text (`"41250.75"`, or whole units); ≤ 2 fraction digits; a float is refused | `invalid_amount` |

| Rounding never flatters: inflows (revenue, contribution) floor, outflows (cost, exposure, capital) ceil | — |
| Estimate = `"UNKNOWN"` · `"UNKNOWN: <reason>"` · `{ low, base, high }` with low ≤ base ≤ high; an unknown never reads as 0 | `invalid_estimate` · `invalid_range` |
| Scenarios: downside takes each input's adverse end, upside its favorable end, base the base | — |
| Every record carries `schema = "soe.<record>/1"`; another version is refused | `schema_unsupported` |
| Record rules: `HIGH_TICKET_DELIVERY` with `RECURRING` revenue · `PARTNER_REVSHARE` without `REVENUE_SHARE` / `ACQUIRE_TRANSFORM` without `ACQUISITION` · `ACQUIRE_TRANSFORM` without `[deal]` · an assumption or the `fx` rate dated after the record's `as_of` | `fake_recurring` · `revenue_model_mismatch` · `deal_review_missing` · `future_leakage` |

| Economics rule (built, `ECONOMICS_VERSION` 1) | Applied as |
|---|---|
| Unit | integer only (`i128` inside, minor units out), in the profile `currency`; another native currency converts through `economics.fx`, else every money figure is `UNKNOWN: needs economics.fx` |
| Unknown | a figure lists the input fields it lacks — never 0; figures that do not need the input stay known |
| Run-rate month | `max_payback_months`, counted from the decision; nothing is earned during `ramp_months` |
| Revenue | `RECURRING` customer base (thousandths, churned monthly) × price · `ACQUISITION` asset revenue churned monthly · `REVENUE_SHARE` partner revenue × share · each × (1 − collection loss) · `ONE_OFF` expected contract value per occupied month (⌈weeks × 12 / 52⌉) |
| Contribution | cash = revenue − variable − fixed; time-adjusted = cash − owner hours × `shadow_hourly_rate` |
| Payback | first month the running sum (fixed costs and owner hours from month 1) covers the initial capital; none in 600 months ⇒ `NOT_REACHED`; cash payback needs no rate |
| Expected loss | Σ probability × impact: a low..high range, never a point |
| Scenarios | downside = every input's adverse end, upside its favorable end; `ONE_OFF` figures take the worse / better delivery length per figure |
| Basis | `PRE_TAX` (no tax model in v1) |
| Identity | `inputs_sha256` = canonical sha256 of version + economics + risk + the profile knobs read |

| Gate (built, PRD § 7.2) | `REJECT` when | `HOLD` when |
|---|---|---|
| exposure · tranche | largest of downside initial capital, Σ stage cash, max-loss cash > `max_cash_exposure` · a stage > `max_validation_tranche` (at the value passes) | an amount unknown |
| contribution · payback | base contribution (`contribution_basis`) < `min_monthly_contribution` with no bounded path · base payback > `max_payback_months` or `NOT_REACHED` | `BELOW_TARGET_WITH_PATH`: the upside reaches the target and a staged experiment tests it; unknown; a passing figure under `POST_TAX` |
| delivery · bounds | — · owner time, support, payment access or scope `UNBOUNDED` | a `ONE_OFF` longer than `max_one_off_delivery_weeks` · a bound or the owner hours `UNKNOWN` |
| evidence | — | no cited record supports it at `as_of` (not knowable yet, trigger only, expired or contradicted) · one demand event only (`SINGLE_DEMAND_SIGNAL`) · a contradiction · no revenue input names evidence |
| legal · deal | a deal red flag | a legal / sanctions / licensing / data / transferability risk not `RESOLVED`; a deal block not `VERIFIED` |
| jurisdictions · stop rule · downside · mechanism | — · the first stage with cash has no stop rule · — · `REJECT` | a jurisdiction `UNKNOWN` or outside `jurisdictions_allow` · no experiment · a max-loss term unknown · `HOLD` |
| verdict | any `REJECT` row | else any `HOLD` row; else `PASS` (still no permission to act); refused outright: an unsigned profile, a decision time before the opportunity |

| Ranking rule (built, `rank.rs` · `matching.rs`) | Applied as |
|---|---|
| Who ranks | `PASS` candidates only, by the profile's `rank_order` (no built-in order), ties by id |
| Keys | `EVIDENCE_CONFIDENCE` (`HIGH`: a supporting fact, nothing contested · `MEDIUM`: ≥ 2 supporting events · `LOW`) · `TIME_ADJUSTED_BASE` · `PAYBACK_BASE` (cash) · `DAYS_TO_DECISIVE_EVIDENCE` (to the end of the experiment deadline, rounded up) · `REVERSIBILITY` · `CAPABILITY_FIT` · `CONCENTRATION_MAX` (largest share) · `DEFENSIBILITY` |
| Unknown | ranks after every known value of its key (no experiment, no concentration listed, a `UNKNOWN` tier, no required skill) |
| Copies | supporting records count once per `event_key` (the O2 as-of view gives copies one key) |
| Capability fit | per required skill: `PROVEN` (an active proven capability) > `CLAIMED` (active, not proven) > `STALE` (none active: expired or not yet valid) > `MISSING`; the opportunity takes its weakest skill |
| Explanation | the first key in the profile's order on which two candidates differ, with both values |
| Rank moves | per id whose rank changed: `ENTERED` / `LEFT` (verdict + gates), `CROSSED` (the nearest swapped candidate, the deciding key, both values before → after), `SHIFTED` (one entered or left above it) |
| Sensitivity | scale one input (`OWNER_HOURS` `CONVERSION` `CHURN` `PRICE`) by ± bps, rounded against the candidate, and report the base time-adjusted figure, the verdict and the gates it adds or removes |
| Weekly rerun | one row per id: its highest version not dated after the decision; a later version is ignored |
| `HOLD` week | nothing passes: held / rejected rows with every gate, the next information ordered by how many candidates each field blocks, a rationale; validated as a `WeeklyPortfolio` |
| Unallocated week | until O3: the `PASS` candidates ranked, each `HOLD` (nothing allocated), held / rejected rows, the next information, rationale `not allocated: …`; nothing passes ⇒ the `HOLD` week |

## 7. Eval set (O0, built)

`tests/fixtures/soe/cases/<id>.toml` (`soe.eval_case/1`), run under `tests/fixtures/soe/profile.synthetic.toml` (`synthetic-operator`): `tengu soe eval tests/fixtures/soe/cases --profile tests/fixtures/soe/profile.synthetic.toml --allow-synthetic` (exit 1 on any `FAIL`). Every case is `synthetic = true`: invented example values and `synthetic:` record ids — no real firm, person, URL or figure. Each run also checks that dropping every record not knowable at `as_of` changes nothing, and that a week where nothing ranks is a valid `HOLD` week. Example week: `tests/fixtures/soe/week/` = the five candidates (`opportunities/<id>.toml`) and `[[cited]]` views (`cited.toml`) of `contradictory_sources`, `boundary_cash_exactly_cap` and `good_high_ticket_integration`, all decided 2026-09-21T18:00:00Z; `tests/soe_cli.rs` keeps them equal.

| `good_high_ticket_integration` | GOOD | one-off delivery priced with owner time, win probability and collection loss; two independent demand events |

## 9. O3 / O4 domain (built, pure)

`src/domain/soe/{observe,proposal,challenge,allocate,memo,forecast,review,ops}.rs` — no IO, no model, no clock. The cycle, the stage runner, the tools (`soe_view` / `soe_propose` / `soe_challenge`) and `tengu soe cycle|replay|grade|resolve|review` come next; none contacts, spends, publishes or deploys.

| Stage | Module | Contract |
|---|---|---|
| Observe | `observe.rs` | one O2 packet at the decision: `EvidenceIndex` (per record: event, class, url, times, confirmations) + `CitedRecord` views (`TRIGGER` / `DEMAND` / `FACT`) |
| Architect | `proposal.rs` | the model writes a `ProposalDraft`; keys in `COMPUTED_KEYS` (figures, verdicts, rank keys, actions, provenance) refused; every `FACT` id in the packet and in `signals`; an evidence locator must be the url of a cited record; a known input without a basis is listed as unsupported |
| Challenge | `challenge.rs` | the Critic writes a `ChallengeDraft`; `WIDEN` moves each end only against the candidate (per-field direction), `unknown_reason` makes it unknown, an unknown stays unknown; `BLOCK_GATE` holds; nothing lifts a gate |
| Economics · gates · rank | O1 (`economics.rs`, `gates.rs`, `rank.rs`) | on the challenged opportunity; blocks added (`GateVerdict::with_holds`) |
| Allocate | `allocate.rs` | the one portfolio builder; `decide_week` runs the stages above, then `allocate` |
| Report | `memo.rs` | verdict · facts · inference (fenced) · computed (portfolio fields only) · unsupported claims · unknowns · challenges · next information |

| Gate verdict | Action (`allocate.rs`) |
|---|---|
| `REJECT` | `REPRICE { min_price }` when only contribution / payback reject and a higher price clears them (binary search on the gates) · else `REJECT` |
| `HOLD`, a deal with `LEGAL_UNRESOLVED` / `DILIGENCE_OPEN` | `DILIGENCE { questions, max_next_tranche }`: the open blocks; the first cash stage, capped at `max_validation_tranche` |
| `HOLD` only on `BELOW_TARGET_WITH_PATH` / `SINGLE_DEMAND_SIGNAL` | `CHEAP_TEST` of the next stage while the week has room, else `HOLD` |
| other `HOLD` | `HOLD` |
| `PASS` | ranked by the profile's `rank_order`; in rank order `CONTINUE_ACTIVE` (active) / `CHEAP_TEST` (new) while the week has room, else `HOLD` |

| Allocation rule | Value |
|---|---|
| Budget | `weekly_owner_hours` + `max_validation_tranche` for the whole week; nothing else |
| Cost | the stage the test runs (new: stage 0; active: its next stage), cash ceiled into the profile currency; no rate ⇒ does not fit |
| Novelty | recorded on the proposal (for the O4 novelty-bias grade), never read |
| Empty week | valid: nothing ranked, every gate on its row, rationale, next information |
