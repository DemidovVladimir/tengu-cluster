Memory Architecture

Tengu Memory StackPartially Built
🔮 Permanent Tier (PLANNED — not implemented) Missing
Design exists in tengu/ideas/memory-idea/. Would use PermanentDiskStore + remember_permanently tool. Never prunable. Auto-promotion after N recalls.
🗄 Persistent Tier (vectors.bin / Qdrant) Implemented
DiskVectorMemoryStore — brute-force cosine similarity, bincode-serialized.
QdrantMemoryStore — ANN search, feature-gated. OpenRouterEmbeddingAdapter.
Tool: remember — stores fact, returns UUID.
Recall: recall_filtered — semantic search at query time.
💭 Session Tier Implemented
In-process RwLock<Vec>. Cleared on prune. Transcript history in ChatRuntimeService. Bootstrap files (AGENTS.md, MEMORY.md) injected at session start.
📦 Persistent Store (SQLite cache) Partial
SharedCacheTool — workspace-scoped SQLite. Not semantic memory, but a KV store. Used by skills for state persistence across turns.
Hermes Memory StackFull Loop
🧬 Honcho User Modeling Unique
plastic-labs/honcho integration. Dialectic user modeling — agent builds a persistent model of who you are from conversation patterns. Cross-session personality profile.
💾 Builtin Memory Provider Implemented
MEMORY.md — curated facts with agent nudges at 75% context usage.
USER.md — user preference profile.
Pre-turn prefetch + post-turn sync lifecycle.
Memory context wrapped in <memory-context> fence (never mistaken for user input).
🔍 FTS5 Session Search Unique
Full-text search across all past sessions. LLM summarizes relevant sessions on recall. Cross-session knowledge continuity without full transcript replay.
🔌 External Provider Slot Extensible
MemoryManager allows ONE external memory plugin (vector DB, graph memory, etc). Clean provider interface: prefetch(), sync_turn(), on_turn_start(), on_session_end(), on_pre_compress().
Cowork/PI MemoryFile-based
📁 MEMORY.md (File-based) Manual
Memory lives in markdown files in the workspace. The consolidate-memory skill merges duplicates and prunes stale facts. Human-readable, git-trackable.
🧩 Skill-encoded Knowledge Implemented
SKILL.md files carry procedural knowledge. Skills are the memory of how to do things. New skills are created via the skill-creator skill — LLM guided but manual trigger.
🗂 Session Context (in-window) Implicit
Claude's context window is the session memory. No persistent cross-session recall built into the platform — must use file tools + skill invocation to carry knowledge forward.
❌ No Vector / Semantic Memory Gap
No built-in embedding or semantic recall. No FTS across sessions. Memory recall relies entirely on the skill system and manual file management.

What Tengu's Memory Needs

🔴
Pre-turn Memory Prefetch
Tengu recalls memory only at query time via recall_filtered. There's no proactive pre-turn semantic prefetch or <memory-context> fence injection like Hermes has.
→ Add a prefetch() phase in ChatRuntimeService before each LLM call
🔴
Permanent Memory Tier
Design exists in ideas folder. PermanentDiskStore, MemoryTier enum, remember_permanently tool — all planned, none implemented.
→ Implement per the ideas/memory-idea design doc (3-4 day Rust task)
🟡
Session Search / FTS
No cross-session conversation search. Hermes has FTS5 SQLite with LLM summarization for cross-session recall.
→ Add rusqlite FTS5 session indexer + recall tool
🟡
Memory Context Fencing
When memory is injected, there's no protection against the model treating recalled facts as current user input. Hermes solves this with the <memory-context> pattern.
→ Wrap recalled memory in a fenced system note in ChatRuntimeService

🚨 Critical Gaps in Tengu-Cluster

Items Hermes Agent has shipped that Tengu has designed but not built (or not yet started).

🔴
Skill Evolution Loop (tengu skill evolve)
The design is excellent (spec in docs/superpowers/specs/). The skill_distill tool is live. But skill-improver agent, approval gate, scratch-worktree, and the tengu skill evolve CLI command are missing. The full loop exists only on paper.
→ Implement evolve.rs + skill-improver agent profile in sandboxes/. Estimated: 1–2 weeks.
🔴
Permanent Memory Tier
Fully designed in tengu/ideas/memory-idea/ with Rust pseudocode. MemoryTier enum, PermanentDiskStore, remember_permanently tool, prune protection — all unimplemented. Agent currently forgets everything on prune.
→ Follow the design doc exactly. Main risk: deciding global vs per-agent permanent scope. Estimated: 3–5 days.
🔴
Cron / Scheduled Tasks
Hermes has a full built-in cron scheduler with delivery to any platform. Tengu has no scheduling subsystem at all — no cron/ module, no scheduled task runner, no concept of time-triggered agent runs.
→ Add a scheduler.rs module. Could piggyback on tokio's time::interval. Deliver results to Telegram channel. Estimated: 1 week.
🟡
Pre-turn Memory Prefetch + Context Fencing
Memory recall happens reactively (agent calls remember/recall tools). There's no proactive semantic prefetch injected before each LLM call, and no <memory-context> fence to prevent recalled facts being confused with user input.
→ Add prefetch_memory(query) call in ChatRuntimeService::handle_turn() before building the LLM prompt. Wrap output in system note.
🟡
Context Compression / Sliding Window
Tengu has prompt_budget.rs for token counting but no automatic context compression when the window fills. Hermes has context_compressor.py with LLM summarization + /compress command.
→ When token budget < threshold: call engine with a compression-system-prompt on the current transcript. Truncate old messages, insert summary. Estimated: 3–4 days.
🟡
Cross-session FTS / Session Search
No ability to search past conversations. Hermes has SQLite FTS5 indexing all sessions + LLM summarization of relevant results. This makes recall of old knowledge genuinely useful.
→ Add rusqlite FTS5 table in the existing SQLite infrastructure. Index each completed session. Add session_search tool. 1 week.
🔵
Messaging Platform Breadth
Tengu supports Telegram only. Hermes supports 6 platforms (Telegram, Discord, Slack, WhatsApp, Signal). Each additional platform multiplies reach significantly.
→ Add Discord adapter via REST API. Slack via Events API. Each is ~300 lines of Rust around the existing event_orchestrator.rs pattern.
🔵
Skill Catalog / Hub Integration
No skill discovery or sharing mechanism. Hermes integrates with agentskills.io. Skills stay local forever in Tengu unless manually copied.
→ Add tengu skill install <url> CLI command. Git clone to ~/.tengu/skills/. 2–3 days.

✅ Where Tengu Is Better Than Hermes

💜
Metric-Gated Skill Evolution (when built)
Hermes improves skills reactively and LLM-only. Tengu's design has a rigorous metric harness (4 metric types, eval fixtures, score delta gate, scratch-worktree isolation). When implemented, this is far more reliable than Hermes's approach.
💜
Blockchain / Crypto Primitives
Built-in Privy wallet tools: sign transactions, sign messages, get wallet address, ABI encode, hex conversions. Hermes has none. This is a major competitive advantage for DeFi/Web3 agent use cases.
💜
Architectural Cleanliness (Ports/Adapters)
Tengu's Rust core enforces clean separation — ports for all external dependencies, structural scope enforcement via lint tests, doctrine that prevents Rust encoding policy. Hermes's Python codebase is more pragmatic and less structured.
💜
Dual Engine (OpenRouter + Claude Code)
Tengu can run agents using Claude Code as the backend, giving access to Claude's native file tools + MCP bridge. This is a unique capability — agents get the full Claude Code experience inside Tengu's orchestration shell.
