One message, end to end

You type one line. A planner LLM reads the team roster and either answers or writes a plan. Each plan step runs as its own tengu run-agent process with its own tools. The last step's answer comes back.

  • 1 planner call per turn
  • ≤ 70 tool rounds per step
  • 600 s wall clock per step
  • 3 attempts, then ≤ 2 replans
  • 心 heart LLM
  • 手 hands tools
  • 脳 brain memory
  • data config and files

Six endings

What the reply can be

  • directthe planner's textA greeting or a question no agent fits. No child runs.
  • donethe leaf step's outputAll steps succeeded; the step nothing depends on answers. Several such steps: their outputs joined, one ### <id> (<agent>) section each.
  • gave upUnable to complete the request after 2 replans. Last error: …Every replan failed too.
  • errSystem error: orchestrator initial call failed: …The planner call itself failed. It is not retried.
  • errSystem error: replan call failed: …A replan call failed.
  • empty(Orchestrator returned no response)The TUI shows this when the reply is blank.
Enforced in code

Guarantees

  • One session id per run. The planner and the runner get the same string, so step summaries are found again on later turns.
  • The planner cannot act. Its call runs with no tools, no tool executor and no memory recall.
  • Only described agents run steps. The runner checks before spawning; the child checks again.
  • A child cannot be started by hand by accident. Without TENGU_AGENT_IPC=1 it exits with an error.
  • Same fences in the child. It reloads the same sandbox file and the parent's resolved egress policy; a bad policy aborts it.
  • Steps cannot hang the turn. The child is killed after the agent's step_timeout_secs (default 600).
