The palette

Ten card kinds, and what each writes

From config/builder/palette.rs. Tools come from the tool catalog, skills from the skill folders, engines from config::ENGINES. Keys never enter the TOML: a secret card holds a name.

always onesandbox[egress] network · allow_hosts[memory] enabled · [studio] controlNetwork defaults to tor; cannot be deleted.
manyagent[agents.<name>]engine, model, default, identity, limits; local / claude_code / codex blocks shown only for their engine.
oneorchestrator[orchestrator] agentmax_attempts_per_step 3, max_replans 2. Wire it to the planner agent.
manytoolagents.<a>.tools[agents.<a>.scopes.<tool>]Restrict on: folders, hosts, env vars, deny by default per field.
manyskillagents.<a>.skill_packagesAny SKILL.md found from the working folder.
manyworkspaceagents.<a>.workspaceConfine (on by default) scopes read_file, write_file, list_directory to the folder.
manysecret(a name, never a value)Stored in the vault, the env, or the Cloudflare Worker ([keys.env] + strip).
oneseal_proxy[keys] proxy · client · agent_socketOnly in a build that knows [keys].
onetelegram[telegram] enabled · allowed_usersIts agent becomes the default agent.
manywebhook[webhooks.endpoints.<name>]Agent, secret_env from a wired secret, goal template.

Never in the palette: run_command, compress_and_store, the wallet-signing tools, the Solana send tools and the exec tools. They need hand-written, hardened TOML (palette::offered).

Keys by name

Three places a secret can live

A secret card names an env var and a store. Validate lists every key the team needs, the card's or the engine's own (an OpenRouter agent needs OPENROUTER_API_KEY), with its state and the command that stores it.

present / missingLocal encrypted vaulttengu secret set NAME <value>Stored in ~/.tengu/secrets.vault, AES-256-GCM. Loaded into the env at start (Secrets).
present / missingEnvironment / .envexport NAME=<value>This shell, or a line in .env. "Present" = set and non-empty in the builder's process.
remoteCloudflare seal proxynpx wrangler secret put NAMEThe key is a Worker secret; tengu gets a route ([keys.env]) and a session, never the key. On only when this build's Config accepts [keys]: probed at start (keys_supported), not compiled in.
What Finalise rewrites

Owned sections, kept sections

The builder rewrites the sections it owns, in a fixed order. Every other top-level key of the file on disk is carried over as it is: scalars first, tables at the end under a comment. Agents not on the canvas are dropped.

Owned (compile::OWNED)

egressmemorystudiokeysorchestratortelegramwebhooksagents

Kept, for example

runtime_profile[hub][decision_loops.*][feeds.*][[mcp_servers]][runtime]

Comments in kept sections are lost; the diff shows it.

Debugging

No browser

tengu sandbox compile --sandbox <n> prints the TOML on stdout and every issue on stderr ([card <id> · <field>], [wire <id>]), then the loader's verdict and sha256; exit 1 on an error. finalise writes it; palette prints the palette JSON.

Debug drawer

On the page: Issues, Blueprint JSON, Last response and a Request log (the last 100: method, path, status, ms). Each request is also a console.debug("[builder]", …) line.

One log line per request

The server logs builder: ok or builder: refused with the route, the sandbox and the ms; Finalise adds config.toml finalised with the sha256. RUST_LOG=tengu=info shows the CLI's steps too.

States

What a card, a wire or a request can be

  • livewire liveThe kind pair is allowed and its rules hold: current flows.
  • warnwarnIt compiles, with a note: an unwired tool, an unsigned webhook, a wrong key name for the engine.
  • errerrorRust refuses it as drawn; Finalise stays off.
  • 200saved · checkedThe blueprint is in builder.json; the status is fresh.
  • 403view-onlyHand-written, frozen or hardened.
  • 409conflictChanged since the preview, or the runtime is running.
  • 422refusedCanvas errors, or the config loader said no.
  • 400bad bodyAn unknown field, another sandbox's blueprint, a non-JSON body (415).
Enforced in code

Guarantees

  • The real loader decides. Validate and Finalise run Config::load on a temp copy, the same parse, validation and hardening as every tengu command.
  • No key in the TOML. A secret card writes a name, or a Cloudflare route; never a value.
  • Nothing is overwritten by surprise. new refuses an existing dir; Finalise writes atomically after the preview you saw and keeps config.toml.prev.
  • The page decides nothing. Kinds, fields, wires, colours and verdicts all come from /api/v1/builder; the wire table is only a drag hint.
  • Bounded input. A blueprint is strict JSON (unknown fields refused), at most 400 cards and 1 600 wires, ids of 1–64 A-Z a-z 0-9 _ -, a body of at most 1 MiB.
  • Studio's fences hold. Loopback only, a per-process token, and Origin + Sec-Fetch-Site + token header on every PUT and POST (Studio).
  • Templates load. A test compiles every template and runs the loader on it; another sets every field of every kind and parses it through the real structs.
