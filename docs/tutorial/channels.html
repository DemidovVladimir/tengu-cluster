Chat surfaces

Three front doors share one runtime. The terminal UI and Telegram keep a conversation. A webhook fires a one-shot planner turn or a decision-loop event, and answers 202 at once.

  • Telegram: no allow-list = refuses to start
  • webhooks on 127.0.0.1:7080 by default
  • loop queue 64 events, then 429
  • Telegram replies split at 4000 chars
  • 守 guard access checks
  • 心 heart planner
  • 手 hands agent with tools
  • 決 Jev decision loop
  • data routing and output

TENGU_TUI_METRICS=1

A one-line token summary after every recorded call. Totals are kept even while the panel is off.

A line per planner registry query with its top three hits. Both flags accept 1, true, yes, on.

Decision feed

When the config has [decision_loops], every new line of decisions.jsonl for those loops appears as a bubble, from any process. It polls every 300 ms.

    Enforced in code
    
    Guarantees
    
  
    
  
      
    
    • Telegram fails closed. No [telegram] allowed_users and no TENGU_TELEGRAM_ALLOWED_USERS: tengu telegram refuses to start.
      • 
    
    • Private agents stay private. No description and not default: never routable, never the default, not in /agents or the team block.
      • 
    
    • Webhooks authenticate first. HMAC-SHA256 or an exact Authorization header, compared in constant time, before any work starts.
      • 
    
    • Bad endpoint config fails at start. Both or neither secret, an empty inline secret, or a loop with no [decision_loops] block stops the listener.
      • 
    
    • One owner. tengu webhooks takes the same leases as tengu run; a second process exits 1.
      • 
    
    • Loops stay ordered. One event at a time per loop, at most 64 waiting by default; the rest get 429.
      • 
    
    • Redaction on every surface. Tool output passes SanitizedToolExecutor; Telegram replies and the TUI's planner answers are redacted again.
      •

    Open each door
    
    
    Webhooks need a build with --features webhooks; the default build has openrouter and telegram. The secret below is an example.
    
  
    
  
    

    $ TENGU_TUI_METRICS=1 tengu chat --sandbox lping
$ TELEGRAM_BOT_TOKEN=<bot token> TENGU_TELEGRAM_ALLOWED_USERS=<your id> tengu telegram --sandbox lping
$ cargo build --release --features webhooks
$ TENGU_LPING_WEBHOOK_SECRET=example-secret target/release/tengu webhooks --sandbox lping
$ BODY='{"pool":"example"}'; SIG=$(printf '%s' "$BODY" | openssl dgst -sha256 -hmac example-secret | sed 's/^.* //')
$ curl -s -X POST localhost:7081/webhooks/solana_events -H "X-Tengu-Signature: sha256=$SIG" -d "$BODY"
{"agent":"lping","endpoint":"solana_events","session_id":"webhook-solana_events-<uuid>","status":"accepted"}
