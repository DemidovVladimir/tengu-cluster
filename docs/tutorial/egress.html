Tor egress

Every request Tengu makes leaves through one egress policy. By default that is Tor, through a local Arti proxy, with no direct fallback. A sandbox opts out with network = "open".

  • default network = "tor"
  • proxy socks5h://127.0.0.1:9050
  • ≤ 10 redirect hops, each re-checked
  • audit <TENGU_HOME>/logs/egress.jsonl
  • 心 heart LLM traffic
  • 手 hands tool traffic
  • 守 guard gates and the proxy

    deploy/tor · docker-compose.tor.yml · Makefile
    
    Where the proxy runs
    
    
    One image: Arti built with HTTP CONNECT, lyrebird-rs as its managed transport. Bridges are mandatory; Arti never dials a relay directly.
    
  
    
  
    
    
    
      
      
      
    
    
    
    
      
    
      
    make tor starts deploy/tor/compose.yml; the port is published on loopback only. Healthy once check.torproject.org reports "IsTor":true.
    
    
    
    
    
      
    
      
    make up picks NETWORK=tor unless the config's [egress] section says network = "open". tengu has no route out but the tor container, so even a program that ignores proxy env cannot leave. The webhook port is not reachable in this mode.
    
    
    
    
    
      
    
      
    Only docker-compose.yml; no proxy, no internal network. The in-process gate (allow_hosts, net_hosts, https_only) still runs.

    When a request fails
    
    
    Venue clients (Solana RPC, Hyperliquid, GeckoTerminal, Jev) sort failures into one class. Only the two green ones are worth a retry.
    
  
    
  
    
    
    "max usage reached" · -32429quota_exhaustedquota text wins over the status
    
    
    HTTP 429rate_limitedRetry-After seconds kept as ms
    
    
    HTTP 401 · 403auth_required
    
    
    HTTP 408 · timeouttimeout
    
    
    HTTP 5xx · connect errortransient
    
    
    body won't decodedecode
    
    
    other 4xx · egress or scope denialfatalnothing was sent for a denial
    
  
    
  
    Error text never carries a secret: an RPC URL renders as its host, and values of key, token, secret, auth, sig, password query params become <redacted>. Bodies are quoted to 160 chars.
    

    


    
  
    
    Six routes
    
    How a request can end
    
  
    
  
      
    
    • torvia ArtiProxied to Arti on :9050, out through a bridge and a Tor exit.
      • 
    
    • proxyvia a set proxyAn explicit proxy, e.g. a corporate one under open.
      • 
    
    • directdirectNo proxy, or an LLM call with route_llm_api = false, or a local engine.
      • 
    
    • norefusedThe gate said no: audited as "verdict":"denied", nothing sent.
      • 
    
    • envadvisoryShell or MCP stdio got proxy env vars; the program may ignore them.
      • 
    
    • loadnever startedA bad [egress]: the config load fails before any request.
      • 
  
    

    


    
  
    
    Enforced in code
    
    Guarantees
    
  
    
  
      
    
    • Tor unless opted out. No [egress] resolves to network = "tor", proxy socks5h://127.0.0.1:9050 (or TENGU_TOR_PROXY), LLM API proxied.
      • 
    
    • A bad policy never runs. An unknown network or field, socks5:// (DNS leak), a proxy without a port, or route_llm_api without a proxy fails the config load.
      • 
    
    • One route, fail closed. A proxied client uses only the configured proxy (env proxy detection off). If Arti is down the request fails; it never goes direct.
      • 
    
    • Every tool hop is gated. http_request checks scheme, deny_hosts, allow_hosts and net_hosts on the first hop and each redirect, up to 10; env-expanded headers are dropped on a cross-origin redirect.
      • 
    
    • Children inherit the parent's policy. run-agent and mcp-bridge apply TENGU_EGRESS over their own config, same audit file.
      • 
    
    • No ungated Bash under a proxy. Claude Code profile editor_shell launches as editor while a proxy is set.
      • 
    
    • Isolated shells are kernel-fenced. With shell_network = "isolated" (macOS sandbox-exec) every outbound connection but the proxy port is refused, DNS included.
      • 
    
    • Audit lines keep secrets out. The URL is logged as the model wrote it ($VAR unexpanded), headers by name only, body and reason redacted.
      • 
  
    
  
    Advisory paths. proxy_env shells and MCP stdio servers only get proxy env vars. LLM, Claude CLI, MCP and Telegram traffic is proxied but not host-checked. A local engine always connects directly. The shell URL check misses built or encoded URLs.
