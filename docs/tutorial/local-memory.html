How persistent_store chunks a file

Chunk size and overlap come from [memory]. Each chunk is embedded on its own and becomes one vector entry; the first carries the description.

5 chunks

    Three files per workspace

    Where it is kept, how it goes

    memory/vectors.bin

    holds
    every entry: id, text, 1536 floats, metadata
    writers
    memory_ingest, persistent_store
    no workspace
    [memory] store_path, default ~/.tengu/memory/
    cleared by
    /purge, tengu prune

    .tengu/storage/<file_id>/

    holds
    the raw file + manifest.json with its chunk ids
    writer
    persistent_store store
    search
    kind persistent_store only, one hit per file
    cleared by
    delete (its vectors too), tengu prune

    .tengu/cache.db

    holds
    table cache_entries: namespace, key, value_json
    writer
    shared_cache put
    sqlite
    WAL, busy timeout 5 s, one connection per tool executor
    cleared by
    delete per key, tengu prune --hard

    Present in code, not wired. The builtin provider can also load AGENTS.md, MEMORY.md, USER.md and daily logs (.tengu/memory/<date>.md), and a <memory-context> fence exists. No live path calls either, and nothing writes daily logs.

    Enforced in code

    Guarantees

    • No secrets in memory. memory_ingest runs every chunk through the secret registry before it is embedded.
    • No torn files, no lost rows. The vector file is written to a temp file and renamed, under a lock file and after a fresh read; a file that cannot be read loads as empty, with a warning.
    • Tools only with a store. Without a vector backend, memory_ingest, memory_search and persistent_store are not registered.
    • Opt-in stays opt-in. persistent_store and shared_cache exist only for agents that name them.
    • Workspace-gated. Both opt-in tools check workspace write permission on every call; persistent_store store also checks read permission on the source file.
    • Budgeted prompt. Each profile file is cut to 2000 tokens; files past the 32000 total are left out.
    • Clean deletes. persistent_store delete removes the file's vector entries by their recorded ids.
    Try it

    Store, list, purge

    storage-test turns memory on with 5000-char chunks; its agent runs on Claude Code (build with --features claude_code). Durable cross-session memory is Open Brain.

    $ export OPENROUTER_API_KEY=<your key>
$ tengu chat --sandbox storage-test
  /purge        # inside the chat: clears the conversation and vectors.bin
$ tengu tool call --sandbox storage-test --agent storage --tool persistent_store --args '{"operation":"list"}'
  # one JSON object: text = {"files": [...], "count": n}, is_error = false
$ tengu prune --sandbox storage-test
  # soft: removes <workspace>/memory and .tengu/storage; --hard empties the workspace
