The status line the TUI prints

Each button sends one example record. The line is built by the same rules as format_status_line: k and M rounding, last call, session total, the agent with the most tokens.

Example values. A planner record is agent planner/lping; a subagent record carries the agent name (crypto_researcher); a decision record the loop name (lp_exec).

Covered and not covered

Which calls leave a record

  • yesplanner plan / replanAfter the engine answers. Layers included.
  • yessubagent engine turnOne per turn of the run-agent loop: logged by the child, sent on by the parent without a second line.
  • yesembedding callTokens from the response's usage, else chars / 4.
  • yeswiki compiler · Jev decisionOne per successful call.
  • noa failed callPlanner, embedding or decision errors return before recording. A failed decision still gets an audit line.
  • noin-process chat turnTUI, Telegram or webhook agent with no plan. Its tokens show in /cost instead.
  • noa child that diesA crash or step timeout returns no IPC payload, so its records never reach the parent.

On disk

Where each trail lives

Paths assume the default TENGU_HOME, ~/.tengu. Every JSONL line is appended whole.

~/.tengu/logs/tengu.log

All tracing, metrics lines included. TUI: file only. Telegram, webhooks, tengu run and the Studio server: file + stderr.

default filter tengu=info

~/.tengu/logs/egress.jsonl

Every http_request hop and network-looking shell command, allowed or denied. Egress.

ts pid session agent call_id via proxy verdict

~/.tengu/logs/decisions.jsonl

One line per Jev decisions call, failures included. Decision loop.

ts ts_ms loop sandbox session_id t call_id decision_id model act_at latency_ms answers usage result args ok output obs trigger runtime_id run_id

~/.tengu/logs/trace/<sandbox>/<run_id>.jsonl

One file per tengu run, tengu webhooks or tengu decide, and with [orchestrator] per tengu chat / tengu telegram process or tengu eval row: ordered, redacted events, first run.opened; this session's planner and subagent records also land there as metrics.recorded. Studio graph and trace.

schema_version event_id seq ts_ms sandbox config_hash runtime_id run_id session_id correlation_id parent_event_id call_id component kind node_id status duration_ms payload artifact

~/.tengu/logs/risk.jsonl

Every [risk] verdict, allow or deny, after its ledger commit. Paper desk.

ts_ms decision_id account call_id session_id tool client_order_id instrument verdict rule class degraded trips checks headroom intent context fill

~/.tengu/logs/maps/<sha256>.json

Each accepted execution map, canonical JSON. Its run's audit lines carry trigger = map:<sha256>.

tengu decide --map

<workspace>/skills/.audit.jsonl

Skill install, remove and export, with the verdict and sha256.

ts op name verdict source sha256

<state dir>/backtests/holdout-reads.jsonl

Each counted holdout read of the xlab backtest tool, its stored rows, or tengu backtest --split.

ts_ms time via run_id spec_sha256 strategy split call_id

~/.tengu/state/soe/<log>.jsonl

The SOE state logs: one line per decided candidate, episode, frozen cycle (hash-chained forecast log), grade, holdout read, resolution, replay and review. SOE.

candidates episodes forecast-log grades holdout-reads resolutions replays reviews
Enforced in code

Guarantees

  • Metrics never gate work. record() returns nothing and cannot fail; a send with no subscriber is ignored.
  • One sink per process. The first install wins; every later build_orchestrator reuses it.
  • Both outcomes report. The parent re-emits a child's records after ok and after failed.
  • Old children still parse. A payload without metrics reads as an empty list.
  • True totals. The TUI aggregator absorbs every record even with the panel off, so turning it on shows real numbers.
  • Slow readers never block. A lagging subscriber skips the records it missed, with a warning.
  • Lines never interleave. Decision, risk, trace and SOE state lines are one write_all each on an append-only file; egress lines too.
