Typed observations

A typed tool returns one envelope: key, status, age, slot, features and the full payload. The same row becomes the model's text, a decision loop's world and a cache entry. A failed read stays an error, never 0.

What a row holds

Every typed tool result is this struct (domain/observation.rs). Example values: a dlmm_pool read of pool 5rCf1DM8LjKTw4YqhnoLcngyZYeNnQqztScTogYHAS6.

keydlmm_pool/1:5rCf1DM8LjKTw4YqhnoLcngyZYeNnQqztScTogYHAS6: schema + subject, full ids joined by :
schema<name>/<version>; typed() refuses a row of another schema
observed_at_ms · ttl_msage = now − observed_at (a future row has age 0)
slotchain slot when known; orders cache writes
sourcelive · cache · stream (a stream row stays stream)
status · errorsok · partial · absent · error; one ReadError per failed field, never a URL
features≤ 32 keys: finite numbers, bools, strings ≤ 64 chars. Missing values are left out
headlineline 1 for the model, full identifiers
datathe whole typed payload as JSON
  • okokEvery promised field is valid.
  • partpartialThe main answer is valid; some fields failed and are listed in errors.
  • noneabsentThe subject really does not exist: a flat perp side, no positions.
  • errerrorNo main answer. Never cached, never fresh, still recorded to history.

    Enforced in code
    
      Guarantees
      
  
      
  
        
    
      • A failed read is never 0. Fields are Field::Error; the feature helpers drop NaN, infinities and missing values.
        • 
    
      • Error rows are never cached. put refuses them, observe() skips them, is_fresh is false for them.
        • 
    
      • A caller can only tighten. max_age_secs is capped by the tool TTL; 0 forces a live read.
        • 
    
      • Slots only move forward. The upsert ignores a row whose slot is older than the stored one, in one SQL statement.
        • 
    
      • Ids are never cut. When line 1 would pass 200 chars, the status suffix moves to its own line.
        • 
    
      • Degraded, not broken. A store that fails to open or read means live reads, never a failed call.
        • 
    
      • Old rows go. Cache rows older than 7 days are deleted when the store opens; day files past retention_days too.
        • 
    
      • Readers touch nothing. tengu history opens day files read-only: it creates and deletes no file.
        • 
    
      • World reads are traced. Under tengu run or tengu decide, a loop step writes one observation.read event per world alias: ok, stale, missing or failed, with its key and age (Studio graph and trace).
        •
