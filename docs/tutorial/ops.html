Diagnose and deploy

tengu doctor is the health check: any failed check exits non-zero, and Docker marks the container unhealthy. make up runs tengu in Docker behind its own Tor proxy unless the config says network = "open".

  • health check every 60 s, 3 retries
  • proxy socks5h://127.0.0.1:9050
  • --live stale after 30 s
  • image CMD tengu telegram
  • 心 heart the tengu container
  • 手 hands make targets
  • 守 guard Tor proxy and checks
  • data config and volumes

    Doctor rows
    
      What a doctor run can report
      
  
      
  
        
    
      • 0all okExit 0; Docker keeps the container healthy.
        • 
    
      • 1backend init errorAn engine did not build: e.g. OPENROUTER_API_KEY is required, or claude_code without its feature.
        • 
    
      • 1proxy unreachableThe [egress] proxy port refused or timed out: is tor running?
        • 
    
      • 1not via Tor--tor: the exit is not a Tor exit, or the check failed.
        • 
    
      • 1NOT live--live: heartbeat missing, stopped or stale, or a required feed down or stale.
        • 
    
      • 1FAIL row--engines: a smoke turn missed a tool, got an error, or lost the token.
        • 
    
      • skiplocal on macOSA local agent on a loopback base_url is never contacted.
        • 
    
      • skipscopes denyThe agent's own scopes deny list_directory or read_file.
        • 
  
      

      


      
  
      
    Enforced in code and config
    
      Guarantees
      
  
      
  
        
    
      • Doctor fails loudly. Any failed check, in any block, returns an error: exit 1 with every failure listed.
        • 
    
      • The smoke turn is sealed. --engines runs only list_directory and read_file in a temp folder with a random token; Claude Code built-ins are off.
        • 
    
      • No way out but Tor. Under tor, tengu and Postgres sit on an internal network with no gateway and no published ports.
        • 
    
      • Bridges only. Arti's [bridges] enabled = true: it never dials a guard or relay directly.
        • 
    
      • Healthy means Tor. The proxy is healthy only after "IsTor":true; tengu does not start before.
        • 
    
      • Config is read-only. The sandbox config is mounted :ro; secrets come from .env.
        • 
    
      • Prune keeps what matters. Never <TENGU_HOME>/state beyond state/flows, the vault, the config or the managed skills; --hard empties a workspace but keeps the folder.
        •
