Who trips a halt, who clears it

A halt denies entries. Reduce-only exits still pass while allow_reduce_degraded = true.

  • daydaily_lossDay-start equity − equity over $10. Clears at the next 00:00 UTC, or by resume.
  • totaltotal_lossInitial cash − equity over $25. Only tengu risk resume clears it.
  • opoperatortengu risk halt at a terminal. Only resume clears it.
  • filefile~/.tengu/state/xmarket/KILL exists. Resume is refused until the file is gone.

Who may trade

Agents on the desk

No [orchestrator]: no planner. tengu chat talks to the Architect; tengu run feeds call the exec tools directly.

xm_architect

Opus 5.5 on the Claude CLI, default, routable. Reads hl_ctx, hl_book, risk_status, paper_positions. No order tool.

xm_executor

Sonnet 5.5 on the Claude CLI, private. Holds paper_order, paper_close, xm_exits. Feeds run its tools; its model is never called by tengu run.

xm_weekend

The one private agent of xmarket-weekend. Holds xm_weekend_fade and xm_exits. Own state dir, ledger and lease.

Market reads

hl_ctx and hl_book

Hyperliquid POST /info behind the egress gate and [rate_limits.hyperliquid]. How a reply becomes a row:

  • 200JSONDecoded into mkt_ctx/1, mkt_instrument/1 or hl_book/1.
  • null200 nullUnknown coin or user: the row is absent.
  • n/a500 nullUnknown dex or coin: not applicable, not an outage.
  • 429rate_limitedThe bucket drains; Retry-After is kept.
  • 5xxtransientAn error row: recorded, never stored.
  • 403auth_required"blocked (geo/WAF/Tor exit?)".
Enforced in code

Guarantees

  • No gate, no order. Without [risk] every exec tool refuses risk_config_missing; mode = "live" fails the config load.
  • Only private agents trade. A load rule, checked again at call time: exec_agent_not_private.
  • Check and act are one step. Gate, fill and write run in one BEGIN IMMEDIATE: two processes never race one account.
  • Missing data fails closed. An absent or failed input is missing:<field>, never 0.
  • A retry never doubles an order. The same client_order_id returns the stored row; a different request under it is client_order_id_conflict.
  • One owner per account. Another sandbox writing it is refused account_owner_mismatch.
  • Exits are never rate-limited. With allow_reduce_degraded they pass halts and stale data.
  • Halts stay with the human. tengu risk halt | resume refuse without a terminal or inside an agent process.
Try it

Look at the desk, halt it, resume it

From the repo root. paper_order needs fresh rows: read hl_ctx first.

$ tengu risk status --sandbox xmarket
# per account: halt, day-start equity, cash, positions, owed funding, last verdicts, KILL file
$ tengu tool call --sandbox xmarket --agent xm_executor --tool hl_ctx --args '{"coins":["xyz:TSLA"]}'
$ tengu tool call --sandbox xmarket --agent xm_executor --tool paper_order \
    --args '{"instrument":"hyperliquid:xyz:TSLA","side":"buy","notional_usd":20,"kind":"market","max_slippage_bps":30,"client_order_id":"try-1"}'
# no opportunity row backs it: denied missing:edge_after_costs_bps
$ touch ~/.tengu/state/xmarket/KILL
# entries now deny kill_switch; the next gate call records a "file" halt
$ rm ~/.tengu/state/xmarket/KILL && tengu risk resume --sandbox xmarket
# type the account name (xmarket) to confirm
