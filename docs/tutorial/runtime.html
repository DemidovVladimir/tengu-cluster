tengu run

One long-running process per sandbox. It holds a lease so no twin can start, builds every decision loop once, fires feeds on their clocks, beats a heartbeat and drains cleanly on SIGTERM.

  • lease 30 s, renewed every 10 s
  • ≤ 4 decisions in flight
  • ≤ 64 events waiting per loop
  • drain ≤ 20 s

job names come from a closed list in config/feeds.rs (only soe_cycle), never a command from config. A job run settles like one call: Done = an item, Failed = a failed call of its class, so the at-tick slot retries for 15 min. Kinds poll, stream, ws and rows are refused at config load: not built yet. tool, tick and job run.

Elsewhere. sandboxes/xlab-w2 runs three at-tick tool feeds in New York time: history_refresh (daily 05:00, Mon 12:05), then the daily and weekend strategy rankings (daily 06:00, Mon 13:00). A ranking that comes back INCOMPLETE, or a contract not sealed yet, fails the call.

Backoff by error class

Every HTTP client maps a failure to one class; feeds then ask next_delay with the FEED policy: 1 s floor, 60 s cap, full jitter, quota park 1 h.

Budgets. [rate_limits.<name>] is one token bucket per process (per_minute, burst, exec_reserve; xmarket: hyperliquid 600 / min). Reads leave the reserve for orders. A wait past the caller's limit is rate_limited, and nothing is sent. No section: unlimited.

Enforced in code

Guarantees

  • One runner per sandbox, one owner per ledger. Both leases are taken in one go or not at all; a held one refuses the start. An [soe] sandbox also leases its [sources] state dir, where runtime.db then lives.
  • A crash frees itself. A dead runner's lease expires after 30 s; a new one takes over then.
  • Losing the lease stops the run and its writers. Another holder, a lapse another holder used, or failed renewals past expiry, end it as failed — lost for good. A writer under the leases (Ownership: the SOE cycle of tengu run or tengu soe cycle) renews them before each irreversible write and drops a running stage at the loss, so nothing is written after it.
  • A loop never runs two events at once, and no more than max_decisions_in_flight run across loops.
  • Bursts are bounded. Past max_queued_per_loop waiting events, the next is refused and counted.
  • No replay storms. Missed feed slots are skipped; a clock stepping back does not stall a feed.
  • Readers never see half a heartbeat. It is written to a temp file, then renamed.
  • No URLs in health. Heartbeats and loop/1 / feed/1 rows replace every URL with <url>.
  • Shutdown is bounded. shutdown_grace_secs ≤ 3600; a second signal exits 130 at once.
  • Each start is its own recording. A new trace run_id per process; every loop audit line carries it and the lease holder as runtime_id. The run writes runtime.* (starting, running, stopping, stopped with the drain), feed.* per slot (a tool, tick or job run: feed.fired then its outcome), loop.* per event with the counters, each webhook request's trigger.webhook root and webhook.responded, and the plan.* / step.* of a planner endpoint or an escalation (Execution trace).
  • Studio's Play is this same start. tengu studio with control on calls the start tengu run calls (start_session): the same leases, loops, feeds, heartbeat and recording, in the Studio process. Its Stop is the SIGINT path ("studio stop"); while Studio runs it, tengu run is refused by the lease. A hardened sandbox ([risk], [soe], a signer) is never Played: its job feed runs under tengu run only (Studio).
