Scopes and hardening

Before a tool touches a file, host, env var, binary or wallet, it checks its scope. A configured scope grants only what it lists. A [risk] section or a Solana signer hardens the whole sandbox.

  • 5 fields per scope
  • empty field = deny
  • no entry = permissive fallback
  • check within 30 lines of execute

Where a scope is decided

ToolScope · src/domain/scope.rs

Five fields, one check each

Every field is an allow-list. ToolScope::default() denies everything.

fs_rootscheck_fs_read · check_fs_writeThe resolved path (symlinks, ..) must sit under a root.no wildcard
net_hostscheck_net_hostExact host, *.suffix (subdomains only, not the apex) or *."*" = any host
env_readscheck_env_readExact var name. Gates $VAR in http_request, SOLANA_RPC_URL, HL_API_URL."*" = any var
shell_binscheck_shell_binBasename of the command's first word. run_command and shell skills."*" = any binary
walletscheck_walletExact label. Privy tools; Solana writes use the full pubkey.no wildcard

    Six outcomes
    
      How a scope check can end
      
  
      
  
        
    
      • runallowedEvery check passed; the tool runs with its resolved path.
        • 
    
      • noscope denied… not in allowed net_hosts [...], or no fs_roots configured (default-deny).
        • 
    
      • outescapes workspaceThe resolved path is not under the workspace: Path escapes workspace.
        • 
    
      • nameprotectedWriting '…' is not allowed, or Writing to skill directories is not allowed.
        • 
    
      • linkcannot resolveA dangling symlink: writing through it would create its target.
        • 
    
      • loadload refusedA hardened rule broke: Config validation failed (n issues); nothing starts.

    Enforced in code
    
      Guarantees
      
  
      
  
        
    
      • Empty means no. Each check_* refuses when its list has no match; a scope with every field empty denies everything.
        • 
    
      • No field-merge. An agent's entry for a tool replaces the default for that tool whole.
        • 
    
      • Every tool checks. tests/scope_lint.rs fails when an execute in tools/ or mcp_client/ has no scope.check_ (or // scope: pure-compute) within 30 lines.
        • 
    
      • Both ends checked. persistent_store store checks read access on the source file as well as write access on the workspace; manage_skill and apply_improver_proposal check write access on the skill dir they change, so the managed tier ~/.tengu/skills needs its own grant.
        • 
    
      • Paths are resolved first. File tools follow symlinks and apply .. before comparing, so new/../../x cannot land outside; a dangling symlink is refused.
        • 
    
      • Agent state is off-limits to writers. .tengu/, .claude/, .git/, skills/, CLAUDE.md, CLAUDE.local.md, AGENTS.md, .mcp.json: any depth, any case. Hardened: also MEMORY.md, USER.md, IDENTITY.md, PROFILE.md, CONTEXT.md.
        • 
    
      • A deny stays a deny. The run-agent workspace grant skips deny-all scopes.
        • 
    
      • Hardened sandboxes refuse to load with a claude_code agent not on profile "none", any [[mcp_servers]], any shell_bins, or a root or workspace that reaches the signer key, <TENGU_HOME>/state, the kill-switch file or the config file.
        • 
    
      • Hardened fallback has no shell. Tools without a scope get no shell_bins, and no shell skill loads.
        • 
  
      
  
      Not a sandbox. shell_bins gates only the first command word: what runs after ;, | or &&, inside $( ), or in node -e is not checked. Write-path protection does not cover run_command or Claude Code built-ins (profiles other than "none").
