Sealed keys

No provider key sits on this machine. Keys are secrets of a Cloudflare Worker that you set yourself; tengu signs a session with an SSH-agent key and names a route, and the Worker adds the key and forwards.

  • session 24 h (1–168 per key)
  • SESSION_KEY ≥ 32 chars
  • signature clock ±60 s
  • reply masked ≤ 2 MiB
  • 守 guard Secure Enclave, Worker checks
  • 手 hands the upstream API
  • data wrangler.toml vars, Worker secrets

How the Worker puts the key in

Each route in ROUTES names its upstream, its Worker secret and exactly one spot for the key. TENGU_SECRET anywhere else is 403, so a session can use a key but never copy it out.

header"header", {secret} once in the value; any name but host, cookie, content-length, hop-by-hop, cf-*, tengu-*. The caller sends no TENGU_SECRET. OpenRouter, embeddings, Jev.Authorization: Bearer {secret}
path"path" templates: the caller starts the path with TENGU_SECRET, exactly once, as one template. Telegram, EVM RPC. A key with URL characters needs a header route.bot{secret}/ · botTENGU_SECRET/getMe
query"query": the caller sends that parameter as TENGU_SECRET, once, and nowhere else. Helius.?api-key=TENGU_SECRET
allowOptional path prefixes a route accepts (after a path key part); any other path is 403. The shipped openrouter route allows four.v1/keys → 403
Tengu-RouteFor clients that build absolute paths (teloxide): base URL <proxy>/, route in a header. Set by header_mode.Tengu-Route: telegram
route-scoped sessiontengu asks for the routes [keys.env] uses; the session gets those the key's CLIENTS routes allow (empty = none). Each call needs both. /whoami shows the grant."routes": ["openrouter"]
Worker answers

What can come back

  • 200forwardedThe upstream's own status and body, the key masked out. A 3xx comes back as is.
  • 400malformedAn unknown route, a session request with no route or an unknown one, a bad session request.
  • 401no sessionMissing, forged or expired; SESSION_KEY rotated; the key not (or no longer) in CLIENTS; the clock more than 60 s off.
  • 403refusedNo asked route allowed for this key; a route not in the session or gone from CLIENTS; TENGU_SECRET off its spot; a path outside allow or the upstream.
  • 500misconfiguredA route's Worker secret or SESSION_KEY missing or short; ROUTES / CLIENTS do not parse; a CLIENTS route not in ROUTES.
  • 502upstream unreachableThe message never carries the upstream URL, which may hold the key.
Enforced in code

Guarantees

  • No provider key here. Keys are Worker secrets; tengu only ever holds a session token.
  • The key goes only to its route's upstream. The target comes from ROUTES; the caller's path is checked, then the parsed URL must keep the scheme, host, port and base path.
  • The key goes only to its spot. One header, the path start or one query parameter; TENGU_SECRET anywhere else is 403. A shipped-config test parses wrangler.toml.
  • Sessions are route-scoped. The signed request names its routes; the token carries the grant; each call needs the route in the session and still in CLIENTS.
  • No session without the agent key. A fresh signature by a key in CLIENTS, within ±60 s, bound to this Worker's origin.
  • Revocation on the next request. CLIENTS is read on every request, not only at /session.
  • The session goes only to the proxy. auth_header_for and header_mode return nothing for any other origin.
  • Fail closed. If no session can be had, every [keys.env] var and the session vars are unset, so a stray local key cannot bypass the proxy. tengu telegram routed through the proxy refuses to start. The Privy wallet tools on route privy need PRIVY_APP_SECRET in strip (a load error otherwise), so without a session they fail rather than use a local secret.
  • Local copies stripped. [keys] strip names are removed at load, success or not, and again in every child. @session only for OPENROUTER_API_KEY next to an OPENROUTER_BASE_URL route.
  • Never on disk. The session lives in process env; its name ends in _TOKEN. The redaction registry is extended after the export, so old .env / vault values stay masked.
  • Replies are masked. Every header value; text, JSON and XML bodies up to 2 MiB, on bytes. A bigger body streams on unmasked past 2 MiB; event streams and binary pass through.
  • No redirect follow. The Worker fetches with redirect: manual.
  • Quiet logs. One JSON line per request: client label, route, upstream host, status, masked count, ms.

Not a sandbox. While tengu runs, an agent with a shell on the same machine can use the session or the agent socket too, and a session can use a route's key (any Telegram Bot API method, as the bot). What it cannot do is read a provider key: there is none here. Sessions are not refreshed: restart a long run before session_hours ends.

Try it

Put a key in Cloudflare

Run wrangler in cloudflare/seal-worker. The fingerprint, URL, label, dates and numbers below are examples. Dashboard walkthrough: Cloudflare secrets setup.

$ tengu keys setup
1. In cloudflare/seal-worker/wrangler.toml, CLIENTS (then `npx wrangler deploy`):
  "SHA256:EXAMPLEexampleEXAMPLEexampleEXAMPLEexample0": { "label": "tengu-attended", "session_hours": 24, "routes": ["openrouter"] }
$ npx wrangler deploy
$ npx wrangler secret put SESSION_KEY
$ npx wrangler secret put OPENROUTER_API_KEY
