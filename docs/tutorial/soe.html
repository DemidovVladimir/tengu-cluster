機 Opportunities · Software Opportunity Engine

Software opportunities

A weekly, evidence-backed ranking of software opportunities, where HOLD is a valid answer. tengu soe runs it offline on a private, signed profile: three scenarios, the hard gates, the ranking, the week and a dated eval set. Nothing here reads the network or acts.

  • money in 2 minor digits, never a float
  • 22 gate codes, 3 verdicts
  • 8 rank keys, 16 dated eval cases
  • 5 tengu soe commands, no network
  • 守 guard refusals, gates
  • data profile, records, the week
One week, offline

From a signed profile to a week

Every command reads files only. The profile decides the caps, the target and the rank order; the code holds none of them.

No config, secrets, network or LLM

The tengu soe command

Every command but init loads the signed profile first and stops on any refusal. Ids and hashes print in full; --format json prints the same data as JSON.

Dated, synthetic, replayable

The eval set

Each case is one dated decision: the record views, the candidates and what the gates and the ranking must answer. Every case is synthetic and names the profile its expectations hold for. tengu soe eval runs them.

ClassCasesExample
GOOD3a fact-backed revenue share ranks above a larger demand-backed one
BAD312000.00 a month collected with 160 owner hours is rejected
BOUNDARY2at the cap passes, one cent above rejects
HOLD4nothing passes: a valid HOLD week with the next information
STALE1an expired listing supports nothing
CONTRADICTORY1a known contradiction holds; a later one changes nothing yet
LOOKAHEAD2a later version or a later record is ignored
  • Expected vs answered. Verdicts, gates, ranking, next information and versions are compared; each difference is listed.
  • No look-ahead. Dropping every record not knowable at the decision must change nothing.
  • A HOLD week is valid. When nothing ranks, the week is built and validated as a WeeklyPortfolio.
  • Wrong profile, no run. A case run under another profile is refused (profile_mismatch).
Typed, versioned, strict

The operator's numbers stay private

Loading the operator profile

The profile lives at <TENGU_HOME>/state/soe/operator.toml. tengu soe init writes it once, unsigned, with the four money values left REQUIRED for the operator to set. Each check refuses with a code. The code never falls back to a built-in value.

Enforced in code

Guarantees

  • No float is money. A TOML or JSON float is refused; 0.10 + 0.20 is exactly 0.30.
  • Nothing is rounded on the way in. A third fraction digit is refused, not rounded.
  • Rounding never flatters. Inflows (revenue, contribution) round down; outflows (cost, exposure, capital) round up, negatives included.
  • No silent conversion. A rate converts only its own base currency; money in two currencies never adds or compares.
  • An unknown currency stays unknown. A source amount outside the closed set becomes UNKNOWN with the reason.
  • Unknown is not zero. No scenario reads a value from an unknown estimate.
  • Versions are explicit. A record tagged with a schema version other than 1 is refused.
  • No built-in operator parameter. No profile field has a default; a missing one fails the parse. There is no salary field.
  • No unknown keys. Every record table refuses a key it does not define, at every depth.
  • No look-ahead. An economic assumption dated after the opportunity's as_of is refused (future_leakage).
  • One quadrant rule. An opportunity episode's decision × outcome quadrant is the lineage rule (quadrant_of).
  • Unknown never passes a gate. An unknown input holds the candidate and names the field (UNKNOWN_INPUT:<field>).
  • Boundaries are exact. At the cap or the target a candidate passes; one cent past it fails.
  • Owner time is priced. The time-adjusted contribution subtracts owner hours × the shadow hourly rate.
  • No look-ahead in the gates. A record knowable only after the decision time — or later the same day — changes nothing then, not even the explanation.
  • One post is not demand. A single customer-demand event holds; news and social posts support nothing.
  • Only what passes ranks. A held or rejected candidate never gets a rank, and the order comes only from the signed profile.
  • A void test decides nothing. An experiment that may have expired by the decision holds the candidate and is no bounded path; a deadline that may have passed is unknown on the days key, never 0.
  • Copies count once. Records sharing an event key are one confirmation.
  • One row per opportunity. A weekly rerun takes each id at its latest version known at the decision; a later version is ignored.
  • A public brief cites public links only. A repo:, state:, vault: or run: locator is refused (private_locator).
  • Unsigned never decides. check, portfolio, sensitivity and eval refuse an unsigned profile, an init template included.
  • The profile is never overwritten. init creates the file only when none exists, whole or not at all (a synced temp file hard-linked into place), mode 0600, and never inside a git work tree.
  • Same inputs, same week. A portfolio rerun prints the same bytes, whatever the file order.
  • Nothing is allocated yet. Until the O3 allocation, every ranked candidate holds; no command contacts, spends or publishes.
Try it

Run it on the synthetic fixtures

The example week has five opportunities from three eval cases, all decided at 2026-09-21T18:00:00Z. The synthetic profile is a test fixture, so each command needs --allow-synthetic.

$ F=tests/fixtures/soe; soe() { tengu soe "$@" --profile $F/profile.synthetic.toml --allow-synthetic; }
$ soe eval $F/cases
16 case(s): 16 ok, 0 FAIL · classes without a case: none
$ soe portfolio $F/week/opportunities --cited $F/week/cited.toml --as-of 2026-09-21T18:00:00Z
# the first three of the eight key columns, in the profile's order:
rank  id                     version  action  EVIDENCE_CONFIDENCE  TIME_ADJUSTED_BASE  PAYBACK_BASE
1     final-rule-automation  1        HOLD    HIGH                 5818.67 EUR         4 months
2     reseller-at-cap        1        HOLD    HIGH                 3760.00 EUR         2 months
3     erp-integration        1        HOLD    MEDIUM               6162.40 EUR         2 months
  why: `reseller-at-cap` before `erp-integration`: EVIDENCE_CONFIDENCE HIGH vs MEDIUM
# held: draft-rule-automation (NO_TESTABLE_EVIDENCE, CONTRADICTED_EVIDENCE) · rejected: reseller-over-cap (CASH_EXPOSURE_ABOVE_CAP)
$ soe check $F/week/opportunities/erp-integration.toml --cited $F/week/cited.toml
# verdict, gates, the three scenarios, rank keys, capability fit, next information
$ soe sensitivity $F/week/opportunities/final-rule-automation.toml --cited $F/week/cited.toml

$ tengu soe init
