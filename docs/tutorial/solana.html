Solana LP tools

Eleven typed read tools watch Meteora DLMM pools, Jupiter perps and a wallet. Five write tools build real transactions: they simulate by default, with no key. Sending needs a signer grant, a per-wallet lease and fresh checks.

  • 11 read · 5 write tools
  • mode = simulate by default
  • wallet lease 150 s
  • tx ≤ 1232 bytes, ≤ 1.4M CU
  • 手 hands tools, the send pipeline
  • 守 guard gates
  • data stores
  • 決 Jev decision loops

Scope per tool

Each tool needs [default_scopes.<tool>]: fs_roots = the workspace (its cache), its net_hosts, and env_reads = ["SOLANA_RPC_URL"].

RPC URL stays secret

Without that env_reads entry the public RPC is used silently. Only the host is ever rendered; errors never echo the URL.

Explicit positions

positions on lp_snapshot or dlmm_positions bypasses discovery: never served from cache, stored with ttl 0. Decide tools refuse such a row.

    Five write tools

    Each returns one write/1 row with ttl 0. Reads inside a write tool are always live.

    dlmm_open_position

    • centred on the active bin, ≤ 70 bins
    • ≤ 2 new bin arrays (0.0714 SOL rent each)
    • SOL/USDC: refused past max_divergence_bps from the oracle
    • refused when a position exists, unless allow_existing

    dlmm_close_position

    • remove liquidity, claim fees and rewards, close
    • > 70 bins: one chunk per ≤ 70 bins, every chunk sent
    • wSOL kept open while a keeper request is pending

    jupiter_swap

    • Jupiter Ultra: order, simulate as is, sign our slot
    • send: SOL↔USDC only; worst fill within oracle_gate_bps
    • wallet must pay the fee (no gasless)

    jup_perps_order

    • a keeper request: increase, decrease or close
    • refused while one is open, without an oracle price, or above max_notional_usd

    solana_close_token_accounts

    • closes EMPTY token accounts, rent back
    • never wSOL, USDC or keep_mints
    • 8 accounts per transaction, batches independent
    • oksimulatedSimulation succeeded; nothing sent.
    • okconfirmedEvery transaction confirmed.
    • oknoopNothing to do, e.g. no empty account.
    • partunconfirmedSent, outcome unknown. Do not retry: the next send resolves it first.
    • partpartialSome transactions confirmed, then one did not.
    • errrefused · sim_failedA gate, check or simulation said no. Never sent.
    • errfailedRejected at preflight, or landed with an on-chain error (fees paid).
    • errexpiredBlockhash expired unseen: did not land, safe to retry.

    Enforced in code

    Guarantees

    • No mode is simulate. Simulate never loads the key and never sends.
    • Send needs the full wallet in this agent's own scope. check_wallet has no wildcard; a grant in [default_scopes] fails the load.
    • Only private agents sign. A grant on an agent with a description, the default agent or a webhook agent fails the load.
    • A signer hardens the sandbox. No [[mcp_servers]], no shell scopes, claude_code only with built-ins off, the key outside every fs root.
    • The key file is strict. Mode 0600, ≤ 1 KiB, its public half must match its secret half; errors never echo its content.
    • One sender per wallet across every process of the install, through one SQL lease.
    • An unknown send blocks the next until it lands or its blockhash expires.
    • Never sent blind. A failed simulation, missing compute units or a transaction over 1232 bytes is not sent.
    • No decision on pre-write data. A snapshot older than the wallet's fence is stale_input.
    • Write store down means simulate only. send is refused without the lease store.
