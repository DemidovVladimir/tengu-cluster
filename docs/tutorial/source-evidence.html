Source evidence

A fact read from an approved source (SEC EDGAR, EU TED) becomes one source record with its full provenance. The as-of view answers "what did the sources say at t?" without ever reading what came later, and keeps source text fenced off as data.

The picture

From an approved source to the model, at any t

The operator fills an append-only store; a pure view reads it as of any instant; agents get that view through one read-only tool. Pure code in src/domain/source/, fetch and store in src/adapters/outbound/sources/, the tool in src/adapters/outbound/tools/sources/.

One record

The fact and its provenance

Every field the opportunity PRD asks of a factual observation (§5.2) is on the record. Confidence and contradictions need many records, so the as-of view computes them; no record stores them.

Two clocks

When a record becomes visible

The registry row's revision tells the view whether a source can change an item after publishing it.

RecordCaptured: what we had read by tKnowable: what could be known at t
first read of an immutable item (SEC accession, TED notice), or a reparse of its bytesmax(published, read, parsed)published
new bytes under the same id (an edit), any in_place item (a page, a repository)max(published, read, parsed)max(published, read)
a withdrawal (the item is gone or moved)max(published, read, parsed)max(published, read), never back-dated

Captured mode ignores everything after t. Knowable mode ignores everything published after t and every edit read after t, but a reparse after t changes it on purpose: it re-reads bytes that already existed.

Inside the cut at tRule
one per ida record id read twice counts once, from its earliest read
current versionper item (source + native id) the newest read wins; on the same bytes, the higher parser version. Older versions are listed as superseded by revision.
correctionsa record naming another in supersedes replaces it only inside the same event and only when both are visible at t; anything else is an issue
class rulesPRD §5.1 on every current record (below); a miss flags the record, never drops it
copiesa syndicated copy counts as its origin: ten wire copies of one filing are one source
freshnessper source and query: the last complete fetch, its age, the covered span and its gaps, failed fetches, parse failures, purges — each at or before t
States at t

Where each current record stands

  • factin forceA typed fact whose validity window holds t.
  • pendpendingVisible, but in force only from valid_from_ms: a rule not yet effective.
  • expexpiredPast valid_until_ms, such as a tender after its deadline.
  • gonewithdrawnThe newest read found the item gone (404) or moved (301). Its last typed version is named.
  • errunparsedThe newest read did not parse. The errors and the last typed version are shown.

The store

sources.db: append-only

One SQLite file per [sources] state, at <TENGU_HOME>/state/<state>/sources.db, mode 0600 (its WAL and WAL index too: the file is created 0600 before SQLite opens it), never market.db. One commit writes snapshots, records, coverage and the cursor together, or nothing.

TableHoldsWrites
snapshotsevery raw body by sha256: kind response or terms, url, status, content type, fetch time, size; the bytes when the row has store_raw = trueinsert or ignore; a raw purge drops the bytes and keeps the hash
records · record_entitieseach record's JSON, keyed by record_id, indexed by item, event and read timeinsert or ignore only; deleted only by record retention
coverageone row per fetch of a query: span, complete, error classappended
cursorswhere a query resumes (SEC: the newest accession of a CIK; TED: the newest publication day read whole)the one mutable row, moved only inside a committed batch
purgestombstones: what a retention purge removed, when and whyappended in the purge's own transaction
switchesthe runtime kill switch: source, off or on, when, whyappended; the last appended row per source wins (append order, never the clock)

A commit is refused when

record
it fails validate (hash, ids, clocks, trust, parse status)
snapshot
a record names a sha256 that is neither in the batch nor stored, or a body does not hash to its sha256
coverage
a span runs backwards, or a complete fetch carries an error class
effect
nothing of the batch is written; the cursor stays

A read at t

seeds
records of the source, entity or event with min(published, read) ≤ t: nothing else can be visible at t
then
every version of each seed's item and every record of its event, until nothing new comes in
why
the knowable clock needs an item's first read; a correction or a report may lack the entity
cut
the as-of view decides what is visible
First source

SEC EDGAR, one CIK at a time

The sec_edgar row reuses the SEC client of Market history: egress gate, scope, budget, retries and the sec_edgar audit line. Every reply is kept as a snapshot.

  • okIndex readThe filing's time is the index page's Accepted (New York to UTC); the record rests on the submissions body and the index body.
  • keptAlready storedA filing with a stored ok record keeps its time with no index read. The same content is the same record, so a re-run adds nothing.
  • partIndex without a timeA 404 or a page without Accepted: the record is partial, its time is the later of the JSON clock and the end of the filing date in New York, never before the acceptance. Coverage is incomplete.
  • stopNo answerA denial, budget refusal, 401 / 403 / 429, 5xx or timeout after the retries: what was read is committed, coverage is incomplete, the cursor stays, the next CIK runs.

Before any request the row must be enabled, carry its license and terms hash and not be switched off at runtime (sources::fetch_gate). Records are committed 25 at a time; the last batch adds the coverage row cik:<cik10> and, only when complete, the cursor.

Second source

EU TED, one publication day at a time

The ted_search row posts the row's query to api.ted.europa.eu/v3/notices/search, anonymously, with {from} = {to} = one day (YYYYMMDD), and pages until every match is read. Field names and shapes were pinned from live replies (2026-10-08). A whole day of the soe query was 318 notices on 2 pages, none partial.

RequestValue
fieldsan allow-list of 21 fields: ids, dates, notice type, procedure, lots, buyer organisation and country, places, CPV, deadlines, estimated values. No contact field (person, email, phone, address) is ever asked for or read.
page · limit250 per page; the server pages no further than 15 000 matches, so a bigger day is cut there and marked incomplete
scopeALL: every notice, not only active ones
coverage · cursor keyquery:<sha256 of the query template>
  • okA noticeOne record per publication number. TED gives a date only, so published is the end of that date in its own offset, never before the notice was public. The event is the procedure; the buyer id becomes ted:buyer:<country>:<id>; the value stays text as written.
  • linkA change noticeIt supersedes the record it corrects: the publication it names, else the newest earlier notice of the procedure with the same type and lot. The as-of view then shows only the change.
  • partA field that does not readThe notice is partial (or unparsed without a notice type), never dropped. A notice with no publication number cannot be a record: it is a row error and the day stays incomplete.
  • stopNo answerAfter the retries: what was read is committed, the day's coverage is incomplete, later days are not read. A re-run without --from resumes the day after the cursor; days read whole are skipped.
Data rights

Terms, retention and personal data

What a source allows, how long its bytes stay and what is never read are rules in code, not habits.

ConcernRule
terms before any fetchan enabled row needs license, terms_url, terms_sha256, terms_reviewed_at and both retention periods (load error); the fetch gate refuses a row without license and terms hash; every record carries both
the terms page itselftengu sources terms stores the page only when its sha256 is the row's terms_sha256; terms pages are never purged
raw retentionraw_retention_days (0 = forever): tengu sources purge drops older raw bodies and keeps each hash and size, so records still cite them
record retentionrecord_retention_days (0 = forever) deletes older records, so a later replay of an earlier t misses them. Every purge that removed something leaves a tombstone, shown in the packet from its time on.
kill switchtengu sources disable refuses every fetch and import of the source from the next call; enable lifts only that switch
contact dataTED requests ask for no contact field (person, email, phone, address) and the decoder reads only its allow-list; buyers are organisations
credentialsSEC's User-Agent is a request header only: never in a snapshot, record, report or audit line. TED is anonymous.
reachsources.db (with its -wal and -shm) is mode 0600 in a state dir outside every fs_roots entry and workspace; agents read it only through source_evidence

Proposed in sandboxes/soe, for the operator to confirm: SEC raw bodies and records kept forever; TED raw bodies 90 days, records forever.

Enforced in code

Guarantees

  • No lookahead. Split-world checks over three worlds: delete, move to t + 1 ms or flood everything after t, add fetches, reparses or purges after t; the packet at t stays byte-identical (knowable mode: all but the reparse).
  • Exactly at t is in. Every record is visible from its own instant on and not 1 ms before.
  • Corrections append. A correction adds a record; the one it corrects stays byte-identical and is listed as superseded.
  • Loss is visible. A withdrawn item, an unparsed read, a coverage gap, a failed fetch and a purge each show in the packet.
  • Source text stays data. Every free text is inside one fence; nested fence tags and copies of the note are removed until none is left.
  • An inference is never a fact. Inference has no record field, no fact kind and no packet row; it sits in its own list and counts toward nothing.
  • Unknown keys are refused. Records, facts, amounts, places, packets and every [sources] row.
  • Money is text as written. NativeAmount keeps 150000.00 with an ISO 4217 code; nothing is converted here.
  • Ids stay whole. Accessions, CIKs with their leading zeros, procedure ids and every hash round-trip unchanged.
  • The store only appends. No statement replaces a row or updates a record; a re-read of the same content adds nothing, a changed one adds a version.
  • Store reads change no packet. For the three test worlds, a packet built from a store read at t equals the packet of every record, at every sampled t, in both clocks.
  • Loss leaves a mark. A raw purge keeps each snapshot's hash and size; terms pages are never purged; every purge that removed something leaves a tombstone.
  • The User-Agent is never stored. It is a request header only: not in a snapshot, record, report or audit line.
  • Contact data is never read. TED requests ask for no contact field, and the decoder reads only its allow-list: injected emails and phones never reach a record.
  • A kill switch acts at once. tengu sources disable refuses every fetch and import of the source from the next call; the TOML stays the ceiling.
  • Agents read, never fetch. source_evidence has no fetch argument (an unknown key is refused) and opens sources.db only when it exists.
  • The same answer on every engine. In-process and through the bridge: the same text and the same store rows (bridge conformance); a 16k local model gets each read whole (offline leg). The live engine-matrix legs have not run yet.
  • The eval set replays. Each of the 12 cases gives its packet byte for byte from the fixture alone, unchanged by anything after t; removing copies beside their origin changes no confidence.
