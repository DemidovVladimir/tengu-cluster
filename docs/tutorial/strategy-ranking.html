Strategy ranking

A ranking orders a sandbox's strategies weakest to strongest on the same data, under a contract sealed in the lineage registry first. No LLM computes it. Both xlab-w2 contracts are drafts: until the operator seals one, every run is refused.

  • 2 draft contracts, both unsealed
  • 15 daily · 8 weekend strategies
  • 9 cohort fields a run must share
  • one run per contract: lease 15 min
  • 手 hands backtests, the tool
  • 守 guard seal, lease, ranker
  • data registry, run dirs, files

What a contract fixes, and when it may run

One TOML file under lineage/rankings/. Ascending means rank 1 is the weakest; a leading - negates a rating key. The publisher runs only a sealed, unchanged contract.

1 · draftrankings/<id>.tomlcommitted with preregistered = true
2 · verifyranking_unsealeda Warn: verify still passes; a shape error is invalid_field
3 · operatorseal ranking:<id>digest + time appended to locks.toml
4 · load[strategy_ranking]known contract, this sandbox, strategies in the library
5 · runpublisherreloads, compares the digest, ranks; an edit is contract_changed

      The clock

      When xlab-w2 refreshes and ranks

      Three at-tick feeds of tengu run --sandbox xlab-w2, New York time. Each ranking runs an hour after its refresh; a missed refresh leaves names STALE and the date INCOMPLETE.

      Text, not paths. The tool's text is one summary line, the compact ranking (ids and run locators whole), how to read a row's run (backtest run_id) and the files relative to the state dir. It never shows the state dir's path: that is outside every agent's fs roots. Fifteen strategies fit in about 2.7 KB, 3.6 KB if each is its own cohort.

      What it leaves

      Files, in the order they are written

      Under the sandbox's [xmarket] state dir, one folder per contract. Every write is a temp file then a rename: a reader never sees half a file.

      <state dir>/strategy-rankings/rank.xlab-w2.daily.v1/
  2026-10-09/manifest.json   # example date · RUNNING at start and after each strategy
  2026-10-09/ranking.json    # 1 · strategy_ranking/1; never rewritten once published
  2026-10-09/ranking.md      # 2
  latest.md                  # 3 · COMPLETE, and no newer date already there
  latest.json                # 4 · the commit point retention reads
  2026-10-09/manifest.json   # 5 · COMPLETE | INCOMPLETE, content_sha256, latest_replaced

      Resume. A RUNNING or FAILED manifest of the same contract sha256 resumes: a DONE strategy whose report.json still hashes the same is reused, the rest run again. INCOMPLETE is final: a rerun of that date is a no-op; only deleting its date dir reruns it.

      Outcomes

      What verify, load, the ranker and the publisher say

      • okCOMPLETEEvery listed strategy has a run, ranked or listed as ineligible. Under on_missing = "EXCLUDE", failed strategies are listed and the rest is ranked. latest moves to it.
      • warnINCOMPLETEA listed strategy failed, went stale or is missing under on_missing = "INCOMPLETE", or no strategy produced a run. Dated files written, latest kept, CLI exit 1, tool error.
      • warnRUNNING · FAILEDA manifest that stopped mid-run, or a publish that failed. The next run resumes it.
      • errorcontract_unsealed · contract_changedThe publisher refuses before writing anything.
      • errorranking_busy · ranking_lease_lostAnother run holds the contract's lease, or took it mid-run (a step outlived the 15-min TTL): this run then writes nothing more.
      • errornot_a_ranking_day · cutoff_not_reached · before_fromThe date is not one of days, its cutoff is still ahead, or it is not after from.
      • warnranking_unsealedNo [[sealed]] row: a draft. Both repo contracts are here.
      • errorinvalid_fieldA shape rule: empty or repeated strategies, cohort fields or rating keys, an unknown zone, a bad cutoff, from not a UTC day, an arm other than research or capped.
      • errorseal_mismatchA sealed contract whose values changed since.
      • errorload error[strategy_ranking] names an unknown contract, one of another sandbox, or a strategy outside the library.
      Enforced in code

      Guarantees

      • Strict records. Every table of a contract denies unknown fields; a rating key outside the list fails the parse.
      • Development only. A contract with an evidence class other than DEVELOPMENT is an Error.
      • A seal is never redone. seal refuses a contract already sealed or not preregistered = true.
      • Sealed or nothing. The publisher reloads the registry on every run and writes nothing for an unsealed or changed contract.
      • Costs count. costs_sha256 moves when a resolved cost moves; spec_sha256 does not.
      • Missing is never zero. A rated figure that is absent, NaN or infinite makes the run ineligible; it is never ranked as 0.
      • One run per strategy and cohort. The newest run id is judged; an older run never stands in for an ineligible newer one.
      • Cohorts never mix. Runs rank together only when every cohort field is equal; each cohort gets its own table.
      • Same data, same hash. content_sha256 leaves out run ids, report hashes and the generation time, so a rerun on the same data hashes the same.
      • One run per contract. The lease ranking:<contract id> refuses an overlapping run, from the CLI or anywhere else on the state dir.
      • Published is final. A published date reruns as a no-op and its files are never rewritten. A later forward grade lifts the evidence tier only in later dates: the standing is read as of each date's cutoff.
      • Latest moves last. Both dated files are written before latest.md, then latest.json. An older date never replaces a newer one.
      • No holdout read. A ranking run has no split, so it never writes holdout-reads.jsonl.
      • Cited runs stay. In a sandbox bound to no generation too, retention keeps the [strategy_ranking] registry's cited runs and every run a latest.json names.
      • Same answer on every engine. The tool's conformance case runs it in-process and through the MCP bridge on the same data; an engine-matrix set (xlab_rank) calls it from each engine. Its offline local leg runs in CI; the live legs have not run yet.
      • Tested on the binary. tests/strategy_ranking.rs: a rerun is byte-identical, a restart reruns only the unfinished strategy to the same content_sha256, an INCOMPLETE date keeps latest, an unsealed or edited contract writes nothing.
