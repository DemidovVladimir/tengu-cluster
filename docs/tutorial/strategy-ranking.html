Strategy ranking

A ranking orders a sandbox's strategies weakest to strongest on the same data, under rules sealed in the lineage registry first. Built: the contract, its checks, the run identity, the ranker, the publisher (tengu ranking), the strategy_ranking tool and xlab-w2's feeds. Next: the operator seals a contract; until then every run is refused.

  • 2 draft contracts, both unsealed
  • 15 daily · 8 weekend strategies
  • 9 cohort fields a run must share
  • cutoff 00:00 / Mon 12:00 New York
  • 3 xlab-w2 feeds: refresh, daily, weekend
  • data records and run dirs
  • 守 guard seal, load checks
  • warn unsealed draft

The weekend contract rank.xlab-w2.weekend.v1 ranks the eight weekend-window strategies on Mondays only (days = ["Mon"]), cutoff 12:00 New York, after the weekend's exits close.

The ranker (pure)

From runs to rows

For one ranking date, each listed strategy brings a finished run, a failure or a stale-data flag. Checks run in this order; the first that applies keeps a run out, and the ranking lists it with its reason.

ReasonListWhen
not_in_contractdroppedthe strategy is not in strategies
failed:<stage> · stale · missingfailedno run: a stage failed, data too old for [freshness], or no input at all
holdout_presentineligiblea split run: the holdout was read
arm_missingineligiblethe report has no arm of the contract's name
cohort_unknown:<field>ineligiblea cohort field the report does not record (a report from before 2026-10-08)
cohort_mismatch:<field>ineligiblefrom_ms ≠ the contract's from, or to_ms / data_through_ms ≠ the cutoff
superseded_rundroppeda newer run of the strategy in the same cohort is judged instead
excluded_statusineligiblea variant in exclude_status
insufficient_trades · insufficient_periods · funding_incompleteineligiblebelow min_trades or min_periods, above max_funding_incomplete
metric_missing:<key> · non_finite:<key>ineligiblea rated figure is absent (never read as 0), NaN or infinite

Standing. evidence_tier is the highest result class of PASS experiments of the variants carrying the run's spec_sha256, else NONE; a PENDING forward lifts nothing. verdict is their weakest status: REJECTED 0, UNREGISTERED / INCONCLUSIVE / SUPERSEDED 1, REGISTERED / ACTIVE 2, SURVIVING 3.

# example row: tier NONE · UNREGISTERED · CI low −3.00 bps · mean +20.00 bps · best-2 share 0.30 · max DD 120 bps
rating = [0, 1, -300, 2000, -30, -12000]   # round(x / 0.01); a leading "-" negates
# rows sort ascending by this tuple, then by strategy id: rank 1 = the weakest of its cohort
The publisher

One ranking date, start to finish

tengu ranking run runs one date of one contract. No LLM and no network: it reads the market-data store and writes run dirs and ranking files in the sandbox's state dir.

StepRule
ContractListed in [strategy_ranking]. The registry is reloaded from disk; the newest [[sealed]] row must match the file, else contract_unsealed or contract_changed and nothing is written.
DateThe given date, else the newest local date whose cutoff has passed. It must be one of days. The cutoff is that date's local time in the contract's zone, correct across DST.
Published?A COMPLETE or INCOMPLETE date comes back as it is. Nothing runs.
Leaseranking:<contract id> for 15 minutes, renewed before each strategy. Another holder: ranking_busy.
FreshnessEvery instrument's newest bar must close by the cutoff minus max_lag_bars bars, else the strategy is STALE and does not run.
BacktestOne strategy at a time, decisions from from to the cutoff, data through the cutoff, no split.
Rankreport.json read back and hashed; the standing comes from the reloaded registry; then select and rank.
PublishThe dated ranking.json and ranking.md; on COMPLETE, latest.md then latest.json; the manifest's final status last.
 
<state dir>/strategy-rankings/rank.xlab-w2.daily.v1/
  2026-10-09/manifest.json   # example date · RUNNING → COMPLETE | INCOMPLETE; FAILED resumes
  2026-10-09/ranking.json    # never rewritten once published
  2026-10-09/ranking.md
  latest.md                  # the newest COMPLETE date, written first
  latest.json                # written last: the commit point retention reads

Resume. The manifest is rewritten after each strategy. A RUNNING or FAILED date resumes: a DONE strategy whose report.json still hashes the same is reused, the rest run again.

Text, not paths. The tool's text is one summary line, the compact ranking (ids and run locators whole), how to read a row's run (backtest run_id) and the files relative to the state dir. It never shows the state dir's path: it is outside every agent's fs roots. Fifteen strategies fit in about 2.7 KB, 3.6 KB if each is its own cohort.

Outcomes

What verify, load, the ranker and the publisher say

  • okCOMPLETEEvery listed strategy has a run, ranked or listed as ineligible. Under on_missing = "EXCLUDE", failed strategies are listed and the rest is ranked. latest moves to it.
  • warnINCOMPLETEA listed strategy failed, went stale or is missing under on_missing = "INCOMPLETE", or no strategy produced a run. The dated files are written, latest is kept, the CLI exits 1 and the tool returns an error. A later run of that date is a no-op: only deleting its date dir reruns it.
  • warnRUNNING · FAILEDA manifest that stopped mid-run, or a publish that failed. The next run resumes it.
  • errorcontract_unsealed · contract_changedThe publisher refuses before writing anything.
  • errorranking_busyAnother run holds the contract's lease.
  • errornot_a_ranking_day · cutoff_not_reached · before_fromThe date is not one of days, its cutoff is still ahead, or it is not after from.
  • warnranking_unsealedNo [[sealed]] row: a draft. Both repo contracts are here.
  • errorinvalid_fieldA shape rule: empty or repeated strategies, cohort fields or rating keys, an unknown zone, a bad cutoff, from not a UTC day, an arm other than research or capped.
  • errorseal_mismatchA sealed contract whose values changed since.
  • errorload error[strategy_ranking] names an unknown contract, one of another sandbox, or a strategy outside the library.
Enforced in code

Guarantees

  • Strict records. Every table of a contract denies unknown fields; a rating key outside the list fails the parse.
  • Development only. A contract with an evidence class other than DEVELOPMENT is an Error.
  • A seal is never redone. seal refuses a contract already sealed or not preregistered = true.
  • Costs count. costs_sha256 moves when a resolved cost moves; spec_sha256 does not.
  • Cited runs stay. In a sandbox bound to no generation too, retention keeps the [strategy_ranking] registry's cited runs.
  • Missing is never zero. A rated figure that is absent, NaN or infinite makes the run ineligible; it is never ranked as 0.
  • One run per strategy and cohort. The newest run id is judged; an older run never stands in for an ineligible newer one.
  • Cohorts never mix. Runs rank together only when every cohort field is equal; each cohort gets its own table.
  • Same data, same hash. content_sha256 leaves out run ids, report hashes and the generation time, so a rerun on the same data hashes the same.
  • Sealed or nothing. The publisher reloads the registry on every run and writes nothing for an unsealed or changed contract.
  • One run per contract. The lease ranking:<contract id> refuses an overlapping run, from the CLI or anywhere else on the state dir.
  • Published is final. A published date reruns as a no-op and its files are never rewritten. A later forward grade lifts the evidence tier only in later dates.
  • Latest moves last. Both dated files are written before latest.md, then latest.json. An older date never replaces a newer one.
  • No holdout read. A ranking run has no split, so it never writes holdout-reads.jsonl.
  • Same answer on every engine. The tool's conformance case runs it in-process and through the MCP bridge on the same data; an engine-matrix set (xlab_rank) calls it from each engine.
  • Tested on the binary. tests/strategy_ranking.rs: a rerun is byte-identical, a restart reruns only the unfinished strategy to the same content_sha256, an INCOMPLETE date keeps latest, an unsealed or edited contract writes nothing.
