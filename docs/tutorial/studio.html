Studio graph and trace

Two read models for Studio. The workflow graph is a sandbox drawn from its validated config and tool catalog. The trace is one redacted, ordered event file per run: every runtime, feed, loop, Jev, action and tool step. tengu studio serves both, read-only, to a browser on this machine.

  • schema v1 for both
  • payload ≤ 4096 bytes
  • graph in 8 columns
  • 8 event families
  • follow: 250 ms poll · 256 buffered
  • server: loopback · GET only
  • 心 heart Architect / map
  • 手 hands tools, catalog
  • 守 guard narrowing, redaction
  • data files and JSON

Node vocabulary

Eight columns, left to right

Every node id keeps its names whole, for example action:demo/write_marker or trigger:map/<64 hex>. The vocabulary comes from the config structs and the catalog. No list is kept by hand in a browser.

Ten statuses

What an event can say

Each status is written where the rule already ran, from the value it computed. Its colour is decided once, in Rust (Status::tone): green, amber, red, or plain. The page is sent the name and only picks the CSS token.

  • greenokDone as asked: executed, or terminally completed.
  • redfailedAn error: a tool call, a decisions call, a feed run.
  • redrefusedA deterministic gate said no: risk, legality, caps, a full queue.
  • amberescalatedBelow act_at: the event stops.
  • amberpending · runningQueued, retrying later, or in progress.
  • amberstale · missingAn observation too old, or absent.
  • amberdroppedA slot or an event not run: late, busy, a full queue, the stop. The next slot tries again.
  • plainskippedLogged, not run: a dry-run step, or a run the stop came before. Drawn with a dashed outline.
  • greynot legalNever a status: an action outside the step's legal set, or one a map dropped. Grey wins over the node's latest colour.

Read-only, loopback only

The Studio server

tengu studio --sandbox <s> (build with --features studio) serves the page in web/studio/ and a JSON / SSE API over what Rust already computed. The page draws; it decides nothing. It prints one URL on stdout, with a fresh token after #t=.

Route (GET only)Serves
/ · /assets/<file>the page, compiled into the binary (include_str!); nothing loads from the network
/api/v1/metasandbox, config_hash, schema versions, read_only: true, control_enabled: false, evidence paths
/api/v1/graph[?map=<sha256>]the graph above; with map, a map tengu decide --map kept, re-hashed and re-applied to this config
/api/v1/healththe heartbeat and the tengu doctor --live checks (one function, runtime::read_live)
/api/v1/runsevery recorded run, the heartbeat holder, the live run, each run's state (live, closed, open) and whether its config hash is the current one
/api/v1/runs/<run_id>/events?after=&limit=a page of events in seq order (limit 1–1000), more, next_after; each event with its view: tone, what it belongs to, the edges it lights
/api/v1/runs/<run_id>/board?upto=<seq>the run folded over its graph up to seq: every node's colour and why, lit edges, grey legal sets, runtime state, model, loop counters
/api/v1/nodes/<node_id>the validated config behind a node (never the TOML text), its edges and the files that hold its facts

  • keyToken32 random bytes per process. Every /api/ call sends it (X-Studio-Token, or ?token= for EventSource); compared in constant time, else 401.
  • hostHost / Origina Host other than 127.0.0.1:<port> / localhost:<port> is 421 (DNS rebinding); a foreign Origin or a cross-site fetch is 403; no CORS header.

Enforced in code

Guarantees

  • The graph never widens. A map goes through ExecutionMap::apply; a mapped graph has no node or edge the base graph lacks, except the map trigger.
  • The graph is deterministic. It is normalized: the same config gives the same bytes (golden files for control-loop-lab and lping).
  • Redaction before the write. Registered secrets become [REDACTED] and URLs become <url> in every payload string and object key before the line is written.
  • Bounded, never cut. An oversize payload loses whole fields, largest first, and says which (_dropped, _bytes). Ids and strings are never shortened. jev.* pin the legal set: legal and legal_actions go only after every other field, the names last, so a grey node survives a huge answer.
  • One event, one line, in order. seq is taken under the same lock as the write; a failed write reuses its seq, so there is no gap.
  • Runs never mix. Every process start is a new run_id and a new file.
  • No path from input. A run id must be a lowercase UUID and a sandbox name a plain name before any file is opened.
  • Fail-soft. If the trace dir cannot be written, the run goes on without a trace and logs a warning.
  • The server cannot change anything. Only GET / HEAD routes exist (anything else is 405); no control route is built yet. The page decides nothing: tones, lit edges, grey nodes, run states and the health verdict all arrive computed. Tests run the real router on a 127.0.0.1:0 listener.
  • No rule twice. An event is written where the rule ran, from its result: the loop's StepOutcome, the queue's refusal, the feed's class and delay, the world read. Shared tests live in one place (ObsStatus::usable, reduce::http_ok, DecisionLoopConfig::logs_only), so the trace and the graph never judge differently from the loop.
