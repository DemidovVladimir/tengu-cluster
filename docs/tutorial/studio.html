動 Runtime · Studio read model

Studio graph and trace

Two read models for Studio. The workflow graph is a sandbox drawn from its validated config and tool catalog. The trace is one redacted, ordered event file per run: every runtime, feed, loop, Jev, action and tool step. tengu studio serves both to a browser on this machine, and — only where the sandbox allows it — plays and stops that sandbox's runtime.

  • schema v1 for both
  • payload ≤ 4096 bytes
  • graph in 8 columns
  • 9 event families
  • follow: 250 ms poll · 256 buffered
  • server: loopback · POST = control only, body ≤ 1 MiB
  • 心 heart Architect / map
  • 手 hands tools, catalog
  • 守 guard narrowing, redaction
  • data files and JSON

Node vocabulary

Eight columns, left to right

Every node id keeps its names whole, for example action:demo/write_marker or trigger:map/<64 hex>. The vocabulary comes from the config structs and the catalog. No list is kept by hand in a browser.

Ten statuses

What an event can say

Each status is written where the rule already ran, from the value it computed. Its colour is decided once, in Rust (Status::tone): green, amber, red, or plain. The page is sent the name and only picks the CSS token.

  • greenokDone as asked: executed, or terminally completed.
  • redfailedAn error: a tool call, a decisions call, a feed run.
  • redrefusedA deterministic gate said no: risk, legality, caps, a full queue.
  • amberescalatedBelow act_at: the event stops.
  • amberpending · runningQueued, retrying later, or in progress.
  • amberstale · missingAn observation too old, or absent.
  • amberdroppedA slot or an event not run: late, busy, a full queue, the stop. The next slot tries again.
  • plainskippedLogged, not run: a dry-run step, or a run the stop came before. Drawn with a dashed outline.
  • greynot legalNever a status: an action outside the step's legal set, or one a map dropped. Grey wins over the node's latest colour.

The Studio server

tengu studio --sandbox <s> (in the default build: feature studio) serves the page in web/studio/ and a JSON / SSE API over what Rust already computed. The page draws; it decides nothing. It prints one URL on stdout, with a fresh token after #t=.

One runtime, never a copy

Play, Stop, send an event

With control on, Play starts the sandbox's runtime inside the Studio process through the start tengu run uses (tengu run): the same leases, loops, feeds, heartbeat and recording. Stop is the path SIGINT takes. The page shows the buttons only when GET /api/v1/control says control is on, and greys each one with the reason Rust gives.

  • starting · stoppingstarting, stoppingStudio is taking the lease, or draining (≤ shutdown_grace_secs): no button.

A scenario is a file sandboxes/<s>/scenarios/<name>.json — what tengu decide --event takes; a *.map.json is a map, never an event. The page sends a name, never an event body. Each request and its verdict (ok, refused, failed) lands in Studio's own recording, kind studio.

Enforced in code

Guarantees

  • The graph never widens. A map goes through ExecutionMap::apply; a mapped graph has no node or edge the base graph lacks, except the map trigger.
  • The graph is deterministic. It is normalized: the same config gives the same bytes (golden files for control-loop-lab and lping).
  • Redaction before the write. Registered secrets become [REDACTED] and URLs become <url> in every payload string and object key before the line is written.
  • Bounded, never cut. An oversize payload loses whole fields, largest first, and says which (_dropped, _bytes). Ids and strings are never shortened. jev.* pin the legal set: legal and legal_actions go only after every other field, the names last, so a grey node survives a huge answer.
  • One event, one line, in order. seq is taken under the same lock as the write; a failed write reuses its seq, so there is no gap.
  • Runs never mix. Every process start is a new run_id and a new file.
  • No path from input. A run id must be a lowercase UUID and a sandbox name a plain name before any file is opened.
  • Fail-soft. If the trace dir cannot be written, the run goes on without a trace and logs a warning.
  • Only the control routes change anything. Every other route is GET / HEAD (anything else is 405). Any request but GET / HEAD — on any path, however it is spelled — passes the guard only with the token header, its own Origin and Sec-Fetch-Site: same-origin; a Host that is not this server is 421 first. The page decides nothing: tones, lit edges, grey nodes, run states, the health verdict and which button may act all arrive computed. Tests run the real router on a 127.0.0.1:0 listener.
  • One runtime per sandbox. Play is tengu run's own start, so the lease refuses a second runner either way: a CLI tengu run while Studio runs one, a Play while the CLI runs one (Studio then attaches read-only). Stop never touches a runtime Studio did not start.
  • No orphan. The runtime lives in the Studio process. SIGINT / SIGTERM drain it first (no new Play, the Stop path, then studio.stopped); a killed Studio takes it along and its lease frees after 30 s.
  • A click never pretends. Every Play, Stop and event is a studio.control request and its verdict in Studio's recording; a failed start is failed with the error, a held lease refused with the holder.
  • No rule twice. An event is written where the rule ran, from its result: the loop's StepOutcome, the queue's refusal, the feed's class and delay, the world read. Shared tests live in one place (ObsStatus::usable, reduce::http_ok, DecisionLoopConfig::logs_only), so the trace and the graph never judge differently from the loop.

The editor: the sandbox builder

tengu studio --sandbox <s> --allow-edit also serves a drag-and-drop builder at /builder (tengu sandbox new opens it on a new sandbox). Without the flag every builder route is 404. The design rules (docs/studio-editor-design-2026-10-08.md) hold, with one change: the builder rewrites the sandboxes it made, never a hand-written one. Full page: Sandbox builder.

RuleHow
Paletteserved from Rust (GET /api/v1/builder): 10 card kinds with their fields, the catalog tools with their own schemas, skills, engines, secret stores. No list in the page; no shell or code node.
Connections12 wires (CONNECTIONS), each mapped to the TOML key it writes; Rust colours each one live, warn or error.
ValidateConfig::load on a temp copy at sandboxes/<s>/config.toml; the page only shows the errors.
SaveFinalise, after a TOML preview and a diff: only a sandbox with builder.json (made by tengu sandbox new), never one whose runtime is running; the old file is kept as config.toml.prev.
Frozen and hardeneda W1-bound or hardened sandbox is view-only; a new design is a new sandbox or generation.
Narrowingdecision loops and feeds are not on the canvas: a builder sandbox keeps any it has as hand-written sections, and a loop is narrowed only by an execution map (ExecutionMap::apply).
