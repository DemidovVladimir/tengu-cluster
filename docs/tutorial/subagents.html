Subagent steps

Every plan step is a fresh tengu run-agent child. It reloads the same sandbox, takes one [agents.<name>] block, works with its own tools until compress_and_store, prints one JSON line and exits.

  • ≤ 70 tool rounds per step
  • 600 s per step, then killed
  • 3 attempts, waits 1 s, 3 s
  • ≤ 2 replans
  • 心 heart LLM
  • 手 hands tools
  • 脳 brain memory
  • 守 guard checks
  • data config, JSON

    Six endings
    
How a step ends

  

  
    
    
  • okcompress_and_store calledThe canonical path. Its summary is the step summary.
    • 
    
  • oktext, no compress_and_storeStill ok, with a warn line. The text becomes the summary (stored with postgres_memory).
    • 
    
  • failedno text, no callStatus failed; the parent retries.
    • 
    
  • exitrun-agent exited with non-zero statusBefore or during the loop: guard, bad JSON, unknown agent, widening compose, engine error.
    • 
    
  • timerun-agent timed out after 600sThe child is killed; the parent retries.
    • 
    
  • capmax turns reachedThe loop just ends: ok if the model wrote any text, else failed.
    • 
  






  

    Enforced in code
    
Guarantees

  

  
    
    
  • Routable agents only. A block without a description never runs as a step: the runner refuses it, and so does the child.
    • 
    
  • No accidental children. tengu run-agent exits with an error unless TENGU_AGENT_IPC=1.
    • 
    
  • Bounded in time. After step_timeout_secs the parent stops waiting and the child process is killed.
    • 
    
  • A deny stays a deny. The workspace root is added to every inherited scope except one with every field empty.
    • 
    
  • Hardened compose only narrows. In a [risk] or signer sandbox an extra tool or skill fails the step before the engine is built.
    • 
    
  • Redacted results. Every tool result and tool error passes the secret redactor before the model sees it.
    • 
    
  • Same network rules. The child installs the parent's resolved egress policy; an invalid one aborts it.
    • 
    
  • One log. The parent reads the child's stderr into its own log (target tengu::run_agent); a failed exit carries its last 40 lines.
    • 
    
  • No orphans. A replan, a cancel or a panic aborts every step still in flight; its child is killed.
    • 
  






  

    Try it
    
Run one step by hand

    
From the repo root. run-agent is internal, but the guard is the only thing stopping you. Needs OPENROUTER_API_KEY.

  

  


$ echo '{"goal":"What is the SOL price?","agent_name":"crypto_researcher","model":"","session_id":"try-1","step_id":"s1","sandbox_config":"lping"}' > step.json
$ tengu run-agent < step.json
Error: `tengu run-agent` is a subprocess mode not meant for direct invocation. Set TENGU_AGENT_IPC=1 …
$ TENGU_AGENT_IPC=1 tengu run-agent < step.json
# logs on stderr; max_turns is 20 here (field missing)
{"status":"ok","output":"…","summary":"…","tools":[{"name":"sol_price","ok":true},{"name":"compress_and_store","ok":true}],…}
$ cargo test --test run_agent_ipc
