Chat turn and tool loop

One message, one or many engine rounds. The model asks for tools, Tengu runs each inside its scope, feeds the result back, and repeats until the model answers or the round cap hits.

Budgets, knobs, and what /context shows

The prompt is sized once per turn. The flow budget counts only user and assistant text, never tool results.

# prompt_budget.rs — window = limits.context_window (engine's own for claude_code)
output_cap   = max_output_tokens_per_turn               # when set
             | clamp(window / 8, 256, 16 384)          # else
reserved     = max(output_cap + max(output_cap / 4, 64),
                   clamp(window / 50, 64, 2 048))     # never above window
input_budget = min(window − reserved, flow_tokens_left) − tokens(system_prompt)
history      = input_budget − tokens(memories)          # newest first, ≤ 20 messages
tokens(text) = max(bytes / 4, 1)

Flow compaction keeps half the history. Past the threshold it folds older turns into one summary and keeps the newest keep_turns user turns: half the history limit by default (10 of 20), and always below it, so there are turns old enough to fold.

Eight endings

How a turn ends

  • okanswerA round with no tool calls. Its text is the reply and joins the flow.
  • capround capAfter max_tool_rounds, one more call with no tools offered forces an answer.
  • moreauto-continueOutput ends in [OUTPUT_TRUNCATED]: the loop asks the model to continue, if rounds remain.
  • stopcancelledTelegram /stop. Checked before each round, before each tool, and every 2 s of stream.
  • errstream idleNo event for 120 s: "Engine stream timed out".
  • errengine errorAn error event before any text fails the turn.
  • fullflow limitFlow tokens reach max_tokens_per_flow: "Flow token limit reached. Use /reset". A notice from 80 %.
  • fullno roomNothing fits the input budget: "Context budget exhausted. Use /reset to continue."
Enforced in code

Guarantees

  • A tool runs with its own scope. Configured entry first; a tool with none gets the fallback rooted in the workspace (no shell in a hardened sandbox). See Scopes.
  • Unknown names never run. The executor answers with the agent's real tool list, so the model can retry.
  • No result enters whole above the cap. max_tool_result_chars on every engine; local engines ≤ 1/8 of the window, footer included.
  • Older rounds shrink to line 1. Chat and run-agent apply the same rule, on every engine.
  • Secrets never reach the model. Every surface wraps its executor in SanitizedToolExecutor: text, typed rows and errors redacted.
  • Call ids never repeat. A fresh uuid nonce per loop, plus round and index.
  • The round cap always ends in an answer call. The last call offers no tools.
Try it

Run one turn headless

The hidden tengu tool turn runs the chat loop once and prints the activity; tool call runs one tool, no model. Needs OPENROUTER_API_KEY and the Tor proxy (make tor) unless the config sets network = "open".

$ tengu tool turn --agent main --goal "List the files in your workspace"
# one JSON line, wrapped here; text and numbers are example values
{"metrics":[{"completion_tokens":41,"prompt_tokens":2310}],
 "output":"The workspace is empty.","status":"ok",
 "tools":[{"name":"list_directory","ok":true}]}
$ tengu tool call --agent main --tool list_directory --args '{"path":"."}'
{"is_error":false,"observation":null,"text":"(empty directory)"}
