Execution trace

Every run writes one ordered file of events: what fired, what Jev picked, which tool ran, how it ended. Each event names its cause, so a run reads as a tree. Secrets and URLs are scrubbed before each write.

  • schema v1
  • payload ≤ 4096 bytes
  • follow: 250 ms poll · 256 buffered
  • a subagent hands back ≤ 512 events
  • 心 heart planner
  • 決 Jev typed choice
  • 手 hands actions, tools
  • 守 guard the sink: seq, scrub, bound
  • data observations, files

What a run is

One process, one recording

A run = one file <TENGU_HOME>/logs/trace/<sandbox>/<run_id>.jsonl (sandbox default for a -c config). A restart never appends to an old run.

tengu run

kind run

One file per start. runtime_id = the lease holder. Feeds, loops, webhook requests, escalations. Ends runtime.stopped.

tengu decide

kind decide

One file per call, no runtime_id. Root trigger.decide or trigger.map; ends trigger.completed or trigger.failed.

tengu webhooks

kind webhooks

One file per process, runtime_id = its lease holder. Each request is a trigger.webhook root. Ends run.closed.

tengu chat · tengu telegram

kind chat · telegram

Only with [orchestrator]: one file per process, its plans and steps. Ends run.closed.

tengu eval

kind eval

Only with [orchestrator]: one file per orchestrated row. Ends run.closed.

tengu studio

kind studio

With control on: its own file of studio.* requests and verdicts. Play starts a runtime in the process, which writes its own run file.

Who and where

  • event_id = <run_id>:<seq>, the same live and in replay
  • seq 1, 2, … in file order; ts_ms the sink's clock unless the event brings its own
  • config_hash = sha256 of the parsed config; runtime_id = the lease holder <host>:<pid>:<uuid>, or null

Links

  • parent_event_id: the event that caused this one
  • session_id: <feed>:<slot ms>, decide-<loop>-<uuid>, webhook-<endpoint>-<uuid>, a chat session
  • correlation_id: the event's own, else the session, else the runtime, else the run
  • call_id: the tool call, {loop}:{session}:{t} or feed:<f>:<slot>:<i>

What happened

  • kind = <family>.<what>; node_id = a Studio graph node
  • status, duration_ms of the thing reported

Content

  • payload: a scrubbed summary, ≤ 4096 bytes
  • artifact: where the full record lives (file + key)

How events nest

Each event points at its cause, so a run reads as a tree. Siblings appear in file order. Pick a source.

  • run.opened runtime:<s> kind, pid
  • runtime.starting holder, leases
  • runtime.running loops, feeds
  • feed.fired feed:tick a tick feed
    • loop.queued loop:demo counters
      • loop.started waited_ms
        • observation.read world:demo/tick ok · stale · missing · failed
        • jev.completed jev:demo answers, legal set
          • action.selected action:demo/<a> args, call id
            • tool.started tool:<agent>/<tool>
              • tool.completed · tool.failed
            • action.completed · action.refused
          • action.escalated gate:demo/act_at · action.rejected
        • loop.completed · loop.failed
    • feed.tick_sent · feed.dropped · feed.skipped
  • feed.fired feed:probe a tool feed
    • tool.started tool:lab/read_file
      • tool.failed · tool.completed
    • feed.failed · feed.completed · feed.retrying
  • runtime.stopping reason, grace
    • runtime.stopped drain, lease_released
  • trigger.webhook trigger:webhook/<e> endpoint, body size; never the body or a header
    • loop.queued loop:<l> a loop endpoint
      • loop.started
        • observation.read · jev.* · action.* · tool.*, as under tengu run
        • loop.completed · loop.failed
    • plan.created planner an agent endpoint: see Plan and steps
    • webhook.responded 2xx ok · 401 / 429 / 503 refused · 500 failed

Recorded by tengu webhooks, tengu run and Studio Play. The answer comes before the work ends: both endpoint kinds answer 202 once the event is queued or the turn is spawned, so webhook.responded often sits between loop.queued and loop.started.

  • root: a webhook's trigger.webhook, an escalation's cause, or none (a chat or telegram message, an eval row)
    • plan.created planner steps, agents; never the goal
      • step.started agent:<a>
        • tool.started tool:<a>/<t> from the run-agent child
          • tool.completed · tool.failed
        • metrics.recorded subagent tokens, no node
        • step.completed · step.retrying · step.failed
      • plan.completed ok · failed · dropped (cancelled)

A replan: plan.replanned hangs under the last step.failed, the next plan.created under it. A step's tool calls run in its run-agent child; the child hands them back over IPC and the parent writes them under step.started.

Three states

What a recorded run is now

  • liveliveThe run of the runtime that holds the lease now, not closed.
  • closedclosedIts last event ends it: runtime.stopped, trigger.completed / trigger.failed (or a failed root), run.closed, studio.stopped.
  • openopenNo closing event, not the lease holder's: a decide still going, or a process that died before its last line.
Enforced in code

Safety

  • Scrubbed before the write. In every payload string and object key: registered secrets become [REDACTED], then URLs become <url>. A run-agent child scrubs its events too, before they cross the IPC.
  • Bounded, never cut. A payload over 4096 bytes loses whole fields and says which (_dropped, _bytes). A string, id or number is never shortened.
  • Summaries, not contents. A tool event keeps its args and the result's first line and size; a webhook event the body size, never the body or a header; a plan event counts, sizes and an error's first line, never the goal, a message or the answer.
  • One event, one line, in order. The next seq is taken under the lock the write holds; one write_all per line. A failed write keeps its seq for the next event: no gap.
  • One writer per file. A run-agent child keeps at most 512 tool events and hands them back over IPC; the parent writes them under the step.
  • Runs never mix. Every process start is a new run_id and a new file.
  • No path from input. A run id must be a lowercase UUID, a sandbox name letters, digits, . _ -, before any file opens.
  • Replay order is seq, never the clock. Readers sort by seq and keep one copy of each event_id; a partial last line is skipped.
  • Fail-soft. No writable trace dir: the run goes on with no trace and a warning. A failed write warns; the run goes on.
