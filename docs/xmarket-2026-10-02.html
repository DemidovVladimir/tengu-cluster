How the pieces connect

One tengu run process per sandbox. Feeds call tools directly (no LLM, no Jev in M0); read tools write typed rows into the workspace store; exec tools go through run_exec, whose [risk] gate, paper fill and ledger write share one SQLite transaction. Solid arrows: calls and writes. Dashed: reads, probes, later work.

Where it lives

The [risk] gate, the paper fill engine, the ledger, halts and exits

Paper first, $100: every order tool runs a deterministic gate inside the tool — check + fill + ledger write in one SQLite transaction — that neither Jev nor an LLM can change. It fails closed: a missing input is a deny missing:<field>, never 0.
