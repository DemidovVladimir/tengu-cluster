Tengu-Cluster · Operator Guide

Multi-agent harness in Rust. RAG-routed planner, subprocess subagents, Qdrant-backed memory.

A user message arrives at a channel (TUI / Telegram). The harness builds an Orchestrator, holding a RagPlanner (the LLM that decides) and a SubprocessRunner (which executes plan steps as child processes). The planner queries tengu_registry — a Qdrant collection of agents, skills and tools — for the top-K matches, then asks an LLM to emit a direct response or a plan referencing one of those matches. Each plan step spawns tengu run-agent as a subprocess, which loads the agent's TOML, builds a tool executor, and runs an LLM-with-tools loop until the model calls compress_and_store. Step output flows back; on failure the executor calls RagPlanner::replan with cross-plan recall from tengu_outputs.

Doctrine · LLM = heart, RAG = brain, tools = hands. The planner has exactly one job: emit plan JSON. Subagents do the work.

Quick launch

One-shot Qdrant + native build (recommended for local dev)
docker compose --profile qdrant up -d qdrant
cargo build --release --features "qdrant claude_code"
TENGU_REGISTRY_FORCE_REINDEX=1 ./target/release/tengu registry reindex-all
TUI
RUST_LOG=tengu=info ./target/release/tengu chat --sandbox aura
Telegram
RUST_LOG=tengu=info ./target/release/tengu telegram --sandbox aura
Verify the registry has data
./target/release/tengu registry list --limit 50
./target/release/tengu registry search "your query here" --top-k 5
